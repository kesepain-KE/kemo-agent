# 原理：智能体感知和拓展

## 源码分布

| 模块 | 路径 | 职责 |
|------|------|------|
| PromptSourceRegistry | `run/prompt_sources.py` | select_perception / select_expand 核心选择逻辑 |
| 知识索引 | `run/knowledge.py` | select_knowledge_index 确定性索引注入 |
| 全局感知注册 | `global_sense/register.py` | 注册感知根目录 |
| 全局拓展注册 | `global_expand/register.py` | 注册拓展根目录及模块 |
| Web 接口 | `web/service.py` | 感知/拓展页面 API |

## 标准化演进

### 旧方案（2026-07-18 前）

- **感知**：register.py 注册根目录 → 扫描目录下所有 .md 文件 → 全量注入 prompt
- **拓展**：register.py 调用 `add_expand(scope, module, inject_file)` → 注入指定文件内容
- 无元数据校验，无健康检查，无数据/操控分离

### 新方案（2026-07-18+）

- **感知标准化（SenseMeta）**：每个子目录是独立感知模块，通过 `sense.json` 声明元数据
  - 字段：name、data_md、recent_update、health、start_update
  - 校验严格：字段完整性、文件存在性、目录逃逸、时间格式
  - 错误隔离：单个模块损坏不影响其他模块
  - 注入条件：`health == "正常"`
- **拓展标准化（ExpandMeta）**：每个子目录是独立拓展模块，通过 `expand.json` 声明元数据
  - 字段：name、explain、open_input、input_data、input_health、start_update、open_control、start_expand、start_control
  - 数据采集层 + 操控能力层两层分离
  - 注入条件：`open_input && input_health == "正常"`（数据采集），`open_control`（操控）

## 注入 Prompt 顺序

```text
build_prompt_bundle()
  ├── knowledge_index  ← select_knowledge_index()     → run/knowledge.py
  ├── expand_data      ← select_expand()               → run/prompt_sources.py
  ├── perception       ← select_perception()            → run/prompt_sources.py
  └── skills           ← select_skills()                → run/prompt_sources.py
```

### 层级优先级

| 维度 | 优先级顺序 |
|------|-----------|
| knowledge_index | user → shared → global |
| expand_data | global → shared → user |
| perception | global（仅全局层，无共享/用户层） |
| skills | shared → user |

## 注入格式

```

### 拓展数据

```
