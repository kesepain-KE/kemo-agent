# 用户模板说明

本目录是创建用户时复制的最小参考模板。正常创建请使用 `user_create.py` 或 Web 用户管理；
不要从其他真实用户目录复制，以免带入历史、记忆、凭据或运行产物。

## user_config.json — 用户配置

| 字段 | 说明 | 必须修改 |
|------|------|----------|
| `web_ui.language` | 网页界面语言，默认 `zh-CN`；支持九种语言，仅影响界面、不影响智能体回复 | 按需 |
| `web_ui.background` | 用户网页背景显示设置，默认关闭；遮罩 `0.65`，背景模糊 `0`，UI 不透明度 `0.94`、UI 毛玻璃 `0`，仅影响网页外观 | 按需 |
| `provider.type` | `"kemo"` 或 `"chat"`；模板默认 `"kemo"` | 按需 |
| `provider.base_url` | Provider API 或 Kemo 网关地址；Chat 会按规则补全 `/v1` | ✅ |
| `provider.api_key` | API 密钥（优先于 `api_key_env`） | 按需 |
| `provider.api_key_env` | 环境变量名；留空时按 Provider 类型使用 `KEMO_API_KEY` 或 `OPENAI_API_KEY` | 按需 |
| `provider.model` | 默认聊天模型名 | ✅ |
| `provider.reasoning_effort` | 推理档位；由 Provider 能力归一化 | 按需 |
| `provider.stream` | 是否启用流式输出 | 可选 |
| `provider.input_modalities` | 主模型确认支持的输入模态；Chat 只允许 `text/image`，Kemo 可增加 `audio/video/file` | 按需 |
| `agent_models.default` | 默认子代理模型；留空时回退 `provider.model` | 按需 |
| `agent_models.cheap` | 低成本子代理模型；留空时回退 `provider.model` | 按需 |
| `agent_models.reasoning` | 推理型子代理模型；留空时回退 `provider.model` | 按需 |
| `multimodal_models.*` | 各多模态能力对应的专用模型名，含独立的 `video_understanding` | 按需 |
| `multimodal_routing.vision` | 只允许 `auto`、`main` 或 `dedicated`；默认 `auto` | 按需 |
| `task_plan.auto_accept` | 是否自动批准任务计划 | 按需 |
| `skills.shared_whitelist` | 允许使用的共享技能列表 | 按需 |
| `expand.shared_whitelist` | 允许使用的共享拓展列表 | 按需 |
| `expand.global_whitelist` | 允许使用的全局拓展列表 | 按需 |
| `expand.prompt_injection` | 是否允许全部拓展数据进入系统提示词；关闭不影响主动调用拓展 | 按需 |
| `expand.realtime_injection` | 是否在同一轮对话内持续重读最新拓展快照；默认关闭以提高 Prompt Cache 命中率 | 按需 |
| `perception.global_whitelist` | 允许使用的全局感知列表 | 按需 |
| `perception.prompt_injection` | 是否允许全部感知数据进入系统提示词；关闭不停止后台采集 | 按需 |
| `perception.realtime_injection` | 是否在同一轮对话内持续重读最新感知快照；默认关闭以提高 Prompt Cache 命中率 | 按需 |
| `knowledge.use_shared` | 是否使用共享知识库 | 按需 |
| `knowledge.use_global` | 是否使用全局知识库 | 按需 |
| `plugins.whitelist` | 允许使用的插件白名单 | 按需 |

`provider.timeout` 不写入模板 JSON。运行时未配置时使用当前默认值 `120.0` 秒，避免模板字段和
Provider 默认逻辑维护两份事实。用户可以在自己的配置中显式覆盖，但应以
`global_knowledge/configuration-reference.md` 和当前配置加载器为准。

`user_config.json` 中的 Provider、模型、模态、知识、技能、拓展、感知和插件段都是用户覆盖段；
它们不会从全局配置中静默继承同名的用户专属字段。完整字段合同见
`global_knowledge/configuration-reference.md`。

## user_soul.md — 用户人格

注入系统提示词的人格定义。格式为 Markdown，包含工作方式、沟通风格、执行习惯。

## 子目录骨架

必需目录由 `run/config/user_skeleton.py` 的 `REQUIRED_USER_DIRS` 统一定义。需要保留的空目录使用
`.gitkeep` 跟踪；`runtime/` 是框架运行期目录，`tools/` 是约定式目录（框架不读写，仅供用户或智能体
放置自产脚本）。模板中的这两个目录都只能保留 `.gitkeep`。

`improve/` 在模板中只保留目录标记，不预置 SQLite 二进制、Markdown 记忆碎片或旧式 `data.json`；
真实用户创建完成后会初始化 `improve/memory.sqlite3`，四档记忆都存放在该数据库的表中。

`history/` 与 `task_plan/` 在模板中必须保持为空，只保留目录标记；不要预置数据库二进制文件或运行数据。创建用户的后处理会按当前 schema 初始化 `history/history.sqlite3` 与 `task_plan/task_plans.sqlite3`。

运行期还可能按需生成：

- `runtime/background_jobs/`：受管理 Shell 后台作业记录和日志；
- `history/thumbnails/`：附件缩略图缓存；
- `web_preferences.json`：Web 外观偏好；
- 用户根目录的 `completion_sound.*` 与 `failure_sound.*`：Windows 网页端上传的运行音效。

这些路径不属于模板的静态目录清单，创建器和更新器不会复制或预置其中的数据。

## memory_temporary_important.md

由 `memory_temporary_important` 子代理自动维护，不需要手动修改。

## background.* — 用户网页背景

模板根目录的 `background.webp` 是项目原创程序绘制的轻量静态背景，不含第三方素材，
新用户创建时随模板复制，默认不启用；已有用户补齐与升级不会添加或覆盖背景文件。
在“配置 → 外观与主题 → 网页背景”上传后，文件按真实内容保存为根目录的
`background.jpg/png/webp/mp4/webm`；也接受手工放入的 `background.jpeg`。
图片仅支持静态 JPG/PNG/WebP，最大 100 MB、3200 万像素；视频 MP4/WebM 最大 400 MB。
网页背景卡片可同时调节前景 UI 透明度和毛玻璃；视频启用后静音循环，不依赖系统动态效果偏好。
关闭只停用，清除才删除；背景不进入文件列表、知识库或模型请求。
显示参数仅存于 `user_config.json → web_ui.background`，不接受任意文件路径或 URL。
模板验收会验证默认 WebP，用户目录修复只补目录，不补背景文件。

## completion_sound.* / failure_sound.* — 可选运行音效

模板不会预置音频文件，也不会创建单独的音效子目录。用户在 Windows
桌面网页端上传运行音效后，文件才会按固定名称写入用户根目录：
`users/<name>/completion_sound.mp3`、`completion_sound.wav`、
`completion_sound.ogg` 或 `completion_sound.webm`（同一时间最多保留一个）。
成功运行使用 `completion_sound.*`；最终失败运行使用独立的
`users/<name>/failure_sound.mp3`、`failure_sound.wav`、`failure_sound.ogg` 或
`failure_sound.webm`（同一时间最多保留一个）。
这些文件不属于 `download/`、`file_upload/` 或文件列表；未设置时路径不存在。
Windows 网页端优先由浏览器播放，浏览器不支持时可使用受保护的终端降级；
Android/iOS 不显示该设置，也不会播放。

## 统一验收

```powershell
python -m tests.template_tests.user --target users/<name>
```

验收会检查配置合并、人格 Prompt、SQLite 记忆库、知识目录和多用户隔离，但不会回显密钥，
也不会请求真实 Provider。模板验收必须使用 `--template-mode`，并会检查 `runtime/`、`tools/`
只保留目录标记以及已移除配置字段不会被真实来源策略接受。`task_cron` 与 `task_plan` 只检查
初始化目录，不在本批测试其业务逻辑。稳定标准见 `tests/template_tests/user/STANDARD.md`。
