# `module/` —— 模块内部实现区（含组件面板）

> 框架只读取本目录声明的 `panel.json`、对应值文件和状态文件；除此之外的内部实现、资源和工程文件
> 不会被自动注册、注入或执行。上一层 `sense.json` 仍严格保持五字段，不要把面板字段写进清单。

## 这个目录里有什么

| 文件 | 谁写 | 谁读 | 作用 |
|---|---|---|---|
| `panel.json` | 模块作者手写 | **框架（只读 JSON 渲染控件）** | 组件面板的**声明**：放几个容器、每个容器显示什么、能改什么 |
| `panel.values.json` | 框架（用户点保存时写） | 模块自己 | 用户在面板上改出来的**值**（明文 JSON，允许含密钥） |
| `status.json` | 模块自己（采集时写） | **框架（只读渲染）** | 状态容器的**数据源**，只给用户看 |
| 其他任何文件 | 模块自己 | 模块自己 | 实现、资源、完整工程……随你放 |

## 组件面板怎么工作

```text
       用户点一下                             模块自己的代码
  ┌──────────────────┐                  ┌───────────────────┐
  │  config 容器     │ ──写──────────▶  │ panel.values.json │
  │ （改采集参数）   │                  └─────────┬─────────┘
  └──────────────────┘                            │ 模块读它做真事
                                                  ▼
  ┌──────────────────┐                  ┌───────────────────┐
  │  status 容器     │ ◀──读──────────  │   status.json     │
  │ （看采集状态）   │                  └─────────▲─────────┘
  └──────────────────┘                            │ 采集时写
                                                  │
  ┌──────────────────┐  框架内置动作              │
  │  action 容器     │ ──触发一次采集──────────▶ data_update.py
  │ （立即采集）     │                      update()
  └──────────────────┘
```

三条关键性质：

1. **状态与配置都不进 Prompt。** 进 Prompt 的永远只有模块根目录的 `sense.md`。
2. **面板不需要模块提供后端。** 框架只读写 JSON 文件，不执行模块代码、不要求模块起服务。
3. **数据来源自由。** 状态文件里写什么、数据从哪来（网络、本地、框架内）由模块自己决定。

## 与拓展面板的区别（**先看这条**）

感知是**单向数据流、没有操控通道**，所以面板能力比拓展窄：

| | 拓展 `expand` | 感知 `sense` |
|---|---|---|
| 状态容器 | ✅ | ✅ |
| 配置容器 | ✅ | ✅ |
| 动作容器 | 框架动作 + **模块命令** + `send`（输入并发送） | **只有框架内置动作** |
| 数据出口（进 Prompt） | `input_data.md` | `sense.md` |
| 作用域 | 全局 / 共享 / 用户 | **只有全局** |

一句话：感知面板是「**看 + 改 + 手动刷新**」，不是「遥控」。

## `panel.json` 字段速查

顶层：

| 键 | 说明 |
|---|---|
| `schema_version` | 固定 `1` |
| `title` | 面板标题（可省略） |
| `containers` | 容器数组，每个元素是一块独立的小卡片 |

三类容器：

| `kind` | 必填键 | 可选键 | 说明 |
|---|---|---|---|
| `status` | `source`（模块内文件路径） | `fields` | 只读展示 |
| `config` | `values`（模块内文件路径） | `fields`、`presets` | 读写配置 |
| `action` | `controls` | — | 仅框架内置动作（如"立即采集"） |

`fields[]` 每项：`key`（对应文件里的键）、`label`（显示名）、`type`，以及按类型可选的
`default` / `options` / `min` / `max` / `placeholder` / `masked` / `required`。

`controls[]` 每项（感知侧只用到这一种）：

- `{ "type": "button", "label": "…", "command": "<框架内置动作>" }`

> `command` 是**框架内置动作的标识**，不是模块自己的命令 —— 感知没有 `expand_call` 通道。
> 具体取值随框架实现定案，此处 `refresh` 表示"触发一次采集"。

## 控件类型

| 类型 | 用途 | 落盘形态 |
|---|---|---|
| `string` | 单行文本（目标、地址） | 字符串；`masked: true` 只影响显示 |
| `number` | 数值，可配 `min` / `max` | 数字 |
| `boolean` | 开关 | `true` / `false` |
| `enum` | 下拉选择，配 `options` | 选中的 `value` |
| `text` | 多行文本（备注、长说明） | 字符串 |
| `badge` / `markdown` / `keyvalue` | 仅用于 `status` 容器的展示 | — |

## 硬边界

- **不要**把 `panel.json` 写进 `sense.json` —— 清单恰好五字段，多一个字段整个模块判 invalid。
- **不要**把密钥写进 `sense.md` —— 那份文件会进 system prompt，可能被所有启用用户看到。密钥写在 `panel.values.json` 里是允许的。
- 面板**不做**任意 HTML/JS：只能使用上表中的原语，由框架渲染。
- 路径必须留在模块目录内，不能用 `..` 或符号链接指向外部。

## 当前框架行为

- Web 感知详情区已经常驻显示用户配置面板；每次请求重新读取面板、值文件和状态文件，修改后无需
  重启 Web，重新选择模块或刷新页面即可热加载。
- `sense_creater action=create` 会把本目录四个文件原子复制到新模块，并把面板标题替换成真实模块名。
- 感知 action 仍只允许框架内置的零参数 `refresh`，不会获得任意模块操控通道。
- 默认 `data_update.py` 会读取 `panel.values.json`、刷新 `sense.md`，并把脱敏执行状态原子写入
  `module/status.json`；配置值不会仅因存在而自动进入 Prompt。
- `validate` 会在面板存在时使用框架真实解析器复验；没有面板的旧感知模块仍保持兼容。
