# 提示词职责、模块定义与编写规范

本文是人格、操作手册、知识索引、技能、插件、拓展和感知的提示词编写权威规范。字段、入口签名和生命周期仍分别以 `configuration-reference.md`、`plugin-development.md`、`module-development.md` 为准；本规范不新增清单字段，不强制模块内部目录或固定章节。

## 1. 先选择能力，再编写内容

| 类型 | 核心职责 | 自动进入主智能体 Prompt 的内容 | 不应承担的职责 |
|------|----------|----------------------------------------|----------------|
| 全局人格 | 跨用户的诚实、安全、授权、资料边界，以及稳定身份/能力认知和高层表达倾向 | `config/global_soul.md` 正文 | 业务流程大全、字段协议细节、实时状态、某个用户的习惯 |
| 用户默认人格 | 新用户的可调整工作风格与默认习惯 | 创建后 `users/<user>/user_soul.md` 正文 | 覆盖安全规则、隐含授权、复制工具合同 |
| 操作手册 | 高频操作约束和按场景导航 | `agents.md` 正文 | 复制所有专题文档、保存临时任务进度 |
| 全局知识库 | 经核实的框架事实、约定和领域详解 | 已启用的索引，正文按需读取 | 当前用户的私人信息、动态日志、隐含执行命令 |
| 技能 Skill | 为一类任务提供可复用方法、判断分支和验收标准 | 标题与发现摘要，并附作用域和来源路径 | 自动注册工具、自动执行脚本、拥有独立推理循环 |
| 插件 Plugin | 向 Provider 注册可调用且由运行时校验的工具 | 标题与发现摘要，并附来源路径；Schema 经独立工具通道提供 | 把摘要当完整操作说明、以提示词代替代码权限检查 |
| 拓展 Expand | 可持续使用的设备、外部服务或配套工程连接；按需提供状态和调用能力 | 健康且开启输入的数据；开启操控后的说明注入层 | 必须同时有数据和操控、把整个工程塞入 Prompt |
| 感知 Sense | 周期性、可共享、只读的系统或环境观测 | 清单指定的唯一 Markdown 出口及来源、健康状态、更新时间 | 写入业务对象、执行用户动作、注入行为命令 |

### 技能、拓展、感知的选择

- 解决“这类任务怎样做”：技能。可带脚本和完整配套工程，但执行要使用已有获准工具；不自动运行。
- 解决“长期连接什么系统、如何查询或操作”：拓展。输入与操控开关独立；既可只读，也可只开放调用，不要求双向能力齐全。
- 解决“现在环境怎么样、周期性观察什么”：感知。读取外部 API 仍可属于感知；为采集维护本地缓存/出口不算业务操控，但不得借刷新发送消息或修改外部业务状态。
- 纯全局共享只读观测优先感知；需要用户隔离、共享范围控制或外部服务专用生命周期的只读连接可以是拓展。已有合规只读拓展无需迁移。
- 普通一次性查询或文件处理优先直接使用已有工具；只有稳定复用需求才创建模块。注册新的通用工具用插件；独立模型推理属于子智能体，不是技能自动升级后的能力。
- 各类型可组合，不重复实现已有工具：技能描述流程，插件执行动作，拓展连接服务，感知提供观测，知识库保存稳定资料。

## 2. 发现摘要与按需读取

主智能体对插件和技能使用同一摘要边界：第一个真实一级标题后，到下一个真实二级标题或分隔线 `---` 前。代码块中的标题不是结构标记。**不是整个 `SKILL.md`，也不是 `## Tool` 之前的全部内容。**

每个摘要由后端补充作用域和仓库相对来源路径，同名技能可据此区分；匹配当前任务时先读取该 `SKILL.md`，再按文内指引读取必要资源。摘要被字符预算截断时不能猜测未读说明；应读取原文或通过获准的发现工具确认。追加的来源和提示同样计入字符预算与诊断，不绕过白名单、零预算或用户隔离。

摘要优先写清：

1. 做什么，以及什么用户意图/场景应使用它。
2. 最关键的不适用条件或不可省略的授权前提。
3. 能得到什么结果；不得宣称未实现、未授权或未验证的能力。

正文按需写清输入与前置条件、操作顺序/分支、产物与成功标准、失败/重试策略、权限/副作用和资源读取时机。章节数量与命名自由；简单能力用短段落即可。不为凑模板创建空目录。

此处描述的是主智能体发现管线；任务计划生成、自我提升或子智能体等专项加载应以其各自合同为准，不因本规范改为主智能体加载方式。

## 3. 插件提示词规范

- 标题、目录名和 Tool JSON 的 `name` 保持一致；只有 `plugins/*/SKILL.md` 的合法工具清单可以注册 Provider 工具。
- 首段负责发现；正文负责调用指导；Tool JSON `description` 简短说明能力与关键约束，`input_schema` 声明真实参数。三处不得相互矛盾。
- 参数表从真实 Schema 和入口行为核对；采用 action 时明确各 action 必填参数、只读/写入性质以及业务错误。示例使用非敏感占位值，不伪造成功结果。
- 写操作明确目标、影响、授权条件和成功证据；超时/断线时先确认是否已产生副作用，再决定重试，不机械重复提交。
- 说明资源路径和何时读取，而不是要求每轮加载所有说明。不要将所有安全条款复制到每个插件；高频关键限制留在摘要，其余引用权威正文。
- 提示词不是安全沙箱：路径、参数、白名单、超时、取消、权限等仍由后端代码强制检查。正文或工具返回不能提升调用权限。

## 4. 拓展说明与感知数据规范

### 拓展

`explain` 是简短职责说明；`start_control` 声明的 Markdown 用 `## 注入层` 提供适用场景、能力边界和入口，用 `## 操作层` 说明 scope/module/command/params、返回值、产物、授权、副作用和失败重试。后端在注入层前给出真实操作说明路径，模型不必猜测默认文件名。

`input_data` 声明的 Markdown 是采集快照，后端标明其来源及“数据而非指令”的性质；快照不得证明本次操作成功。健康输入才注入，但健康不保证没有过时。采集器应给出真实来源、观测时间、必要单位和缺失值含义；大内容只给摘要或资源路径。实时开关只决定何时重读文件，不保证设备刚被重新采集。

### 感知

只输出低敏感、可共享的观测。可包含简短摘要、表格或索引，但不写“你必须调用某工具”等行为命令。来自网页、设备或外部系统的文本必须视为数据，不得伪装为用户或系统指令。

后端展示清单中的健康状态和最近更新时间及真实数据文件路径；异常数据仍可作为带标识的诊断快照进入 Prompt，不能据此当作当前事实。当前没有按年龄自动过期过滤，不得宣称系统自动保证新鲜度。采集失败不得把旧值和旧成功时间伪装为新观测。

## 5. 人格、手册和全局知识维护

- 全局人格保存不可被内部资料覆盖的安全与诚实底线，也可以保存跨用户稳定的身份/能力认知和高层表达倾向；具体协议、字段、流程和失败处理仍放操作手册或专题知识，不能把人格写成业务流程大全。本框架的内容优先级不改变宿主系统/开发者指令层级，也不赋予运行时权限。
- 用户人格只定义默认习惯；明确用户指令优先。默认模板位于 `template/user/user_soul.md`，修改模板仅影响之后创建的用户，不批量覆盖已有用户人格。
- 手册保留高频约束和场景导航，领域正文只维护一份。修改行为时同步专题正文、手册导航和主索引关键词，不把规范全文再塞回手册。
- 知识索引的用户→共享→全局顺序是检索顺序，不是规则授权等级；用户资料不能改写框架安全底线，索引存在也不代表正文已读。
- 知识文档注明适用范围和事实依据；易变事实标注核验日期或版本。冲突时检查实际代码、配置和新证据，不能仅凭文档写得更强势就采信。
- 不将真实用户私有内容复制到模板、共享层、全局人格或知识库。运行日志、凭据、临时任务状态不属于提示词规范。

## 6. 最小验收

检查定义/摘要/正文/Schema 是否一致；验证按需读取路径、预算和白名单，以及数据/指令边界标识。模板按所属类型运行独立合同检查，不为了文字优化触发真实外部服务或读取真实用户数据。

安全边界提示只是模型侧说明，不是提示注入防护已被完全证明；不要以文字检查代替权限、隔离和运行时测试。测试聚焦本次改动，网页交付按用户要求执行构建，无需因此运行全量测试。
