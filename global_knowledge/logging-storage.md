# 结构化运行日志存储

## 存储分工

运行日志分为三类：

| 类型 | 事实来源 | 说明 |
|------|----------|------|
| Cron 执行记录 | `runtime/logs.sqlite3` | 结构化查询；旧的 `cron/task_cron_system/log/*.jsonl` 保留为兼容审计文件 |
| 外部消息路由记录 | `runtime/logs.sqlite3` | 结构化保存入站、出站、附件和失败状态；旧的模块 `log/*.md` 保留为人类可读格式 |
| 进程/重启诊断 | 文本日志，例如 `tmp/restart.log` | 非结构化调试输出，不进入事件表 |

Cron 任务定义仍然存放在各自的 JSON 文件中。日志数据库不是聊天历史数据库，也不保存附件二进制内容。

## SQLite 规则

数据库使用 Python 标准库 `sqlite3`，位于项目运行目录的 `runtime/logs.sqlite3`，不纳入 Git。启用 WAL、跨平台忙等待和结构化索引，支持 RuntimeHost、Cron、消息路由和 Web 同时访问。

主要表为 `cron_execution_logs` 与 `message_route_logs`。网页查询使用分页上限和时间索引，不再为了展示最近记录读取全部日志文件。

数据库写入失败属于诊断链路故障，不得阻断智能体、定时任务或外部消息路由；旧 JSONL/Markdown 文件仍作为回退和导出格式。

## 迁移与保留

首次读取时，旧 JSONL/Markdown 会按文件指纹幂等导入 SQLite；重复导入不会制造重复事件。新记录采用双写，旧文件写入成功后更新导入指纹，进程在中途退出时下次仍可补导入。

默认保留 90 天，可通过环境变量 `KEMO_LOG_RETENTION_DAYS` 修改；设置为 `0` 表示不自动清理。清理只删除结构化事件，不删除聊天历史、任务定义或附件。当前版本不自动删除兼容 JSONL/Markdown，避免升级时破坏人工审计记录；其保留周期由部署者单独管理。

消息正文和外部平台标识属于敏感运行数据。运行目录必须保持 Git 忽略，部署时应限制数据库文件的本地访问权限，不得把 Token、Cookie 或平台密钥写入日志。
