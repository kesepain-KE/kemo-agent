# 感知模块模板说明

感知只提供只读数据采集。将本目录复制为 `global_sense/<name>/`；模块必须是 `global_sense/` 的直接子目录，不存在用户层或共享层感知。

本模板只建立框架能够发现的最小合同，不是完整目录范式。复制后可以保留、删除或重写模板实现，并在模块目录内自由添加任意文件、任意层级目录或完整工程。框架不会自动注册、注入或执行清单未声明的内部文件，也不会要求简单模块为了匹配样例而拆分，或要求大型实现全部挤进 `data_update.py`。

## 自动运行机制

RuntimeHost 按 `task_cron_system.sense_update_rate` 扫描合法模块，并在独立 Python 子进程中调用 `data_update.py` 的零参数 `update()`；没有 `update()` 时才回退到零参数 `main()`。

刷新频率属于框架级统一调度，不属于单个感知模块。不要向 `sense.json` 增加 `update_interval`、`interval_seconds` 等模块级字段；需要调整时修改全局配置 `task_cron_system.sense_update_rate`。Web 感知 API 会从同一全局配置返回 `update_interval_seconds`，并保留 `update_interval` 显示文本，因此页面显示与真实系统任务使用同一频率来源。

- 子进程使用隔离模式并受 `task_cron_system.module_update_timeout` 限制。
- Windows 后台采集由框架以隐藏窗口方式启动；Linux 使用普通无交互子进程。
- 模块不要自行启动终端、守护进程、无限循环或常驻线程，也不要设置 `CREATE_NEW_CONSOLE`。
- 用户在终端手动执行 `python data_update.py` 属于前台调试，不受后台隐藏策略影响。

## 文件合同

### `sense.json`

| 字段 | 说明 |
|------|------|
| `name` | 模块唯一标识，建议与目录名一致 |
| `data_md` | 数据输出文件名，通常为 `sense.md` |
| `recent_update` | 最近一次成功采集时间，格式为 `YYYY-MM-DD HH:MM:SS` |
| `health` | `正常` 或 `异常`；首次成功前建议为 `异常` |
| `start_update` | 零参数同步采集入口，通常为 `data_update.py` |

清单仍严格保持以上五个字段。模块自己的接口轮询、设备采样或缓存刷新可以作为内部实现细节，但不能冒充框架调用此模块的系统调度频率。

### 清单声明的更新入口

模板中的 `data_update.py` 只是一个可替换示例。可以修改其中任意部分、换成更小实现，或让它仅负责调用模块内部其他程序；框架只要求最终暴露同步、零参数、可在超时内结束的 `update()`（或兼容 `main()`）。成功可以返回 `None` 或 `{ "ok": true }`；失败应抛出异常、返回 `False`、`{ "ok": false }` 或失败状态。

输出应原子写入，认证信息只从环境变量读取。框架会再次校准 `sense.json` 健康状态，因此模块不得伪造成功时间。

### `sense.md`

该文件可能进入所有启用用户的 System Prompt。只保存必要、低敏感且有界的数据，不写密钥、Cookie、完整环境变量或无界日志。

### `_last_run.json`

可选的最近运行记录，不参与模块发现。模板会保存 `ok`、时间、错误和输出大小，便于排查采集失败。

感知模块不需要模块级 `register.py`；根级发现和 Prompt 注入由框架统一完成。额外内部文件不需要登记，除非它本身就是清单选择的数据出口或更新入口。

## 统一验收

```powershell
python -m tests.template_tests.sense --target global_sense/<name>
```

动态验收在临时副本内执行更新入口并检查健康状态、Markdown 出口和 Prompt 注入；
不可信或暂时无法连接设备的实现可先使用 `--static-only`。稳定标准见
`tests/template_tests/sense/STANDARD.md`。
