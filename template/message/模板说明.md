# 外部消息模块模板说明

本目录用于展示外部消息路由的最小合同和一种 Telegram 长轮询适配方式，不是固定工程结构，也不是适用于所有平台的完整成品。创建 `message/out/<name>/` 后，可以完全替换示例源码，或把它们改成调用模块内完整项目的薄适配入口。

## 框架实际关心的内容

- `message.json`：严格清单，声明平台身份、绑定用户、能力、三个适配入口以及缓冲/附件/日志路径。
- input 入口：实现 `start(config, buffer_path, files_path, state_path)` 与幂等 `stop()`；后台接收模式还应提供 `is_alive()`，可选提供 `restart()` 和 `last_error()`。
- output 入口：实现 `send(payload) -> bool`，只有真实发送成功才返回 `True`。
- detect 入口：实现轻量 `check(config, state) -> dict`。
- 消息缓冲、附件目录和日志目录：名称与层级由 `message.json` 决定，不要求使用模板中的平铺布局。
- `state.json`：核心约定的运行状态文件。

## 模块目录内部完全自由

除上述合同外，可以自由增加任意文件、Python 包、SDK 封装、数据库、协议代码、资源、测试、构建文件或完整开源项目。框架只加载清单声明的三个入口，不会扫描并自动执行其他内部文件，也不会因为模板未列出某个文件就拒绝模块。

简单平台可以直接在入口中实现；复杂平台应保留自身工程结构，由入口转交处理。不要为了匹配模板把所有网络、解析、缓存和业务代码塞进 `input.py`、`output.py` 或 `detect.py`。模板中的 `files/`、`log/` 和文件名只是当前清单的选择，不是保留结构。

## Telegram 示例注意事项

当前 Python 文件是 Telegram 定向参考代码，展示附件登记、长期轮询、停止和重启语义。使用前必须根据目标目录和实际 SDK 调整内部导入、凭据读取与平台 API；接入其他平台时允许删除并重写全部示例实现。

示例内部共享函数位于 `util.py`，额外 SDK 声明在模块自己的 `requirements.txt`；安装
模块依赖不会改变 kemo-agent 的核心依赖集合。空的 `message.md` 是队列初始状态，不要
写说明文字；一旦非空就必须是完整、可消费的 YAML front matter 消息序列。

凭据不得写入 `message.json` 或提交到版本库，应从环境变量或明确忽略的本机配置读取。被声明入口导入的内部代码与入口具有同等权限，只能使用可信项目。

## 队列和附件

输入模块先原子保存附件到清单声明的 `files_dir`，再向缓冲文件追加 YAML front matter 消息。附件路径必须是模块内非空相对路径，并包含原始文件名、准确 MIME 和真实字节数。平台模块不要自行把图片编码为 Base64 或 Markdown 图片；核心会统一登记资产并按模型能力路由。

输入模块只追加消息，不直接执行主智能体，也不自行实现 `/new`、`/clear`、`/compress` 等核心命令。自动重启不得清空平台积压消息，所有网络调用必须有超时，并能在 RuntimeHost 停止时退出。

`allowed_tools=null` 表示沿用用户工具权限；显式白名单会进一步收窄外部入口能力。若文本主模型需要借专用模型处理媒体，白名单必须包含 `multimodal`。

## 统一验收

```powershell
python -m tests.template_tests.message --target message/out/<platform>
```

通用验收不会启动平台、发送消息或调用在线检测，只验证导入、生命周期签名、状态、
缓冲协议和 Transport 发现。真实 Token/网络联调由模块自己的集成测试完成。稳定标准见
`tests/template_tests/message/STANDARD.md`。
