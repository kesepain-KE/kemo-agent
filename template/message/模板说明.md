# 外部消息模块模板说明

将 `my_bot/` 目录复制到 `message/out/<name>/` 后，按以下规则修改。

## message.json — 模块配置

| 字段 | 说明 | 必须修改 |
|------|------|----------|
| `machine_id` | 全局唯一机器标识，用于消息路由 | ✅ |
| `platform` | 平台类型，当前支持 `telegram` | 不改 |
| `display_name` | 显示名称 | ✅ |
| `bound_user` | 绑定的内部用户名 | ✅ |
| `modules.input` | 收消息模块，指向 `input.py` | 不改 |
| `modules.output` | 发消息模块，指向 `output.py` | 不改 |
| `modules.detect` | 健康检测模块，指向 `detect.py` | 不改 |
| `capabilities` | 能力声明：receive_text / send_text / receive_file / send_file | 按需 |
| `message_buffer` | 消息缓冲文件，指向 `message.md` | 不改 |
| `files_dir` | 附件存储目录，指向 `files/` | 不改 |
| `log_dir` | 日志目录，指向 `log/` | 不改 |

## bot_config.json — 凭据

`token` 字段填入 Telegram Bot Token（从 @BotFather 获取）。此文件不提交到 Git。

## input.py / output.py / detect.py / util.py

这四个文件是完整的运行代码，直接复制可用。只需修改：
- `input.py`：from 导入路径中的 `telegram` 改为实际目录名
- `output.py`：同上
- `detect.py`：同上
- `util.py`：同上

`input.py` 已包含长期运行生命周期接口：

- `is_alive()`：供核心判断接收循环是否仍在工作。
- `last_error()`：把后台线程顶层异常交给核心监督器。
- `restart()`：确认旧线程退出后复用最近一次启动参数。
- `stop()`：15 秒内无法退出会明确失败，避免重复启动第二个消费者。

核心会独立监督输入模块并按指数退避自动重启，不会阻塞 `message.md` 队列轮询。复制模板到新平台时必须保留这四个函数的语义；即使更换 SDK，也不能在自动重启时清空平台积压消息。

## state.json

运行时状态，由核心监督器和 detect.py 共同维护。`input_status`、`input_restart_count`、`input_last_restart_at`、`input_error` 用于展示输入长存活状态，保留初始值即可。

## message.md

消息缓冲队列，由 input.py 自动追加 YAML front matter 格式消息。初始为空。输入模块只负责追加队列，不直接更新 `state.json` 的标准消息字段；核心领取消息后统一更新计数和最后消息时间。
