# 默认长任务运行合同

主智能体从一条用户输入到最终正文始终使用同一个 Run、CardStream 整合和引导邮箱。
不设置工具调用总次数或模型请求轮数上限，不需要会话长任务开关。
不会因工具次数产生新 Run ID、synthetic 用户消息或续跑提示；不维护独立长任务状态机。

## 请求、工具与最终正文

每个 Provider 响应可以包含多次工具调用，各次调用仍进入真实执行记录并计入统计。
工具结果追加 RAW，后续主请求通过一致快照读取最新 VIEW；历史超过有效输入容量80%时压缩，
失败保留原VIEW和完整RAW。单次响应产生临时正文并不代表整合完成。
一次压缩可按完整卡片分多次只读摘要请求，片段共用总时限及额外重试额度；
临时摘要不发布到 VIEW，全部成功且完整请求预算通过后才原子提交，不改变主 Run 或引导邮箱。
运行时确认必要工具、Shell作业、子任务结果及待处理引导全部收妥后，才正常提交最终正文。

用户附件、引导附件和 attach_media 原生块只进入下一次获得完整有效响应的请求。
同一请求的网络重试复用原媒体，成功后移除临时投影；历史保留文字和安全资产引用。
需要再次查看媒体时显式 attach_media 重新装载。引导正文只经历史卡片投影，不重复叠加临时文本。

## 保留的结束边界

工具本身的超时、连续相同调用保护、成功副作用防重、连续失败隔离、Provider有限重试、
输入容量限制和用户取消继续生效。子代理按自己的agent-config.json保留独立时间/工具段预算及显式resume规则，
不再读取已退出的全局tools.max_iterations。
任务计划创建/等待批准仍收束当前整合；计划的执行、暂停、失败与取消遵守其权威状态。

等待子任务和取消收尾共用一次绝对deadline；到期以partial保存已有正文和未完成项。
仍存活执行继续占槽位并保护同一会话，实际退出后才解除；partial不会自动另起Run，迟到结果不重启回复。
这些状态不冒称成功，也不把请求数或工具数当作任务完成依据。

## Web与App

Web输入坞移除长任务开关和专属状态气泡，配置页移除主对话最大工具调用数字段。
旧会话长任务GET/PUT/cancel API、long_task_update事件及其前后端类型均已退出。
取消统一使用带user/source/session_id的 POST /api/runs/{run_id}/cancel，支持可选cancel_subagents；
关闭网页标签、折叠处理过程或关闭App订阅都不自动等同于运行取消。
App桥接保留同一Run的事件游标恢复，不按续跑事件创建Run别名。

最终正文出现后，网页将思考、工具、临时正文、统计、计划与引导归入默认折叠的“处理过程”，
最终正文单独展示。用户展开后仍可按原事件顺序查看证据。

## 验证入口

默认调用不限次数与取消：tests/cards/test_unlimited_run.py。
单Run的网页事件与终态：tests/core/test_long_task.py。
同一Run完成已批准计划：tests/web/test_plan_long_task.py。
媒体首次交付、重试、inline输入及子代理：tests/core/test_transient_inputs.py。
上下文统计一致性：tests/web/test_prompt_accounting.py。
