# 修复 chat API 流式输出缓冲问题 — 编程方案

**目标项目**：`E:\code\kemo-agent`
**修改文件**：`run/engine.py`（仅 `_iter_request_events_impl` 函数）
**影响范围**：流式 Provider 的事件产出时机；非流式路径不动
**交付对象**：编程智能体

---

## 一、问题

当 `stream=True` 时，Chat API 的 SSE 流式输出实际上不是真流式——文字不会逐 token 出现在前端，而是等待整个 LLM 响应完成后一次性弹出。

根因在 `run/engine.py` 第 1048 行：

```python
buffered_provider_events = list(
    _provider_events(provider, protocol_request)
)
```

`_provider_events()` 本身是生成器，逐条产出 `RunEvent`。但 `list()` 把它一次性全部拉取到内存，等 Provider 完整响应后才进入后续的逐条 yield 循环。浏览器在此期间收不到任何 SSE 事件，表现为长时间空白等待后文字突然全部出现。

---

## 二、完整现状流程

以下为 `_iter_request_events_impl` 中与本次改动相关的完整链路（从 LLM 请求到 SSE 推送）：

```
┌─────────────────────────────────────────────────────────────────┐
│  _iter_request_events_impl()                                    │
│                                                                 │
│  1. 解析请求参数 (user, prompt, session_id ...)                  │
│  2. 加载配置、Provider、工具注册表、记忆、Prompt Bundle           │
│  3. 上下文选择 (select_context) → 裁剪历史、生成摘要              │
│  4. 构建 ChatRequest → chat_request_to_kemo → KemoRequest        │
│                                                                 │
│  5. ┌──────────────────────────────────────────────────────┐    │
│     │  while True:  (重试循环，处理 context_length_exceeded) │    │
│     │                                                      │    │
│     │  try:                                                │    │
│     │    ★ buffered = list(_provider_events(...))  ← 问题   │    │
│     │    for event in buffered:                            │    │
│     │      if error → _raise_if_context_length_exceeded    │    │
│     │    break  # 安检通过，跳出重试                         │    │
│     │                                                      │    │
│     │  except ContextLengthExceeded:                       │    │
│     │    压缩上下文 → 重试 (最多 2 次)                       │    │
│     └──────────────────────────────────────────────────────┘    │
│                                                                 │
│  6. ┌──────────────────────────────────────────────────────┐    │
│     │  for event in buffered:   ← 第二遍遍历同一个 list      │    │
│     │    if text_delta     → yield 给 SSE                  │    │
│     │    if reasoning      → yield 给 SSE                  │    │
│     │    if tool_call_start → 收集 + yield                 │    │
│     │    if usage          → yield 给 SSE                  │    │
│     │    if error          → yield + return                │    │
│     │    if done           → 记录 iteration_done            │    │
│     └──────────────────────────────────────────────────────┘    │
│                                                                 │
│  7. 工具循环：有 tool_calls → 执行工具 → 回到步骤 4              │
│  8. 无 tool_calls → 提交历史、加权记忆 → yield done             │
└─────────────────────────────────────────────────────────────────┘
```

**关键点**：步骤 5 的 `list()` 阻塞了整条链路。Provider 可能花费 10 秒生成回复，但事件全部积压在 `buffered` 里，直到步骤 6 才逐条推给 SSE。

---

## 三、方案

**核心思路**：去掉 `list()`，直接迭代 `_provider_events()` 生成器。事件分两类处理——

| 事件类型 | 处理方式 |
|---------|---------|
| `text_delta` | **立即 yield 给 SSE** + 收集文本 |
| `reasoning_delta` | **立即 yield** + 收集推理 |
| `tool_call_start` | **立即 yield** + 收集调用 |
| `usage` | **立即 yield** + 更新用量 |
| `error` | 安检 → **立即 yield** → return |
| `done` | 仅收集，不 yield（后面统一发） |

error 事件无论在什么位置出现，都先做 `_raise_if_context_length_exceeded` 安检，确保上下文超限错误能被正确捕获并触发压缩重试（此时尚未提交任何历史，重试安全）。

### 新增辅助函数

在 `_iter_request_events_impl` 同文件内新增 `_stream_provider_events` 函数：

```python
from dataclasses import dataclass, field

@dataclass
class _StreamedBatch:
    """流式产出 Provider 事件的第一遍结果。"""
    
    text: str = ""
    reasoning: str = ""
    calls: list[ToolCall] = field(default_factory=list)
    done: RunEvent | None = None
    usage: Usage | None = None
    error: RunEvent | None = None


def _stream_provider_events(
    provider: Any,
    protocol_request: KemoRequest,
) -> Iterator[tuple[RunEvent, _StreamedBatch]]:
    """
    直接迭代 _provider_events()，每条事件立刻产出 (event, batch)。
    
    - text_delta / reasoning_delta / tool_call_start / usage：立即 yield，同时累积到 batch
    - error：安检 context_length_exceeded → yield → 终止
    - done：仅累积到 batch，不 yield
    
    调用方拿到每条 (event, batch) 后，对非 error/non-done 事件应直接推 SSE。
    done 事件由调用方在循环结束后统一处理。
    """
    batch = _StreamedBatch()
    for run_event in _provider_events(provider, protocol_request):
        if run_event.type == "text_delta":
            batch.text += run_event.content
            yield run_event, batch
        elif run_event.type == "reasoning_delta":
            batch.reasoning += run_event.content
            yield run_event, batch
        elif run_event.type == "tool_call_start":
            batch.calls.append(
                ToolCall(
                    id=run_event.tool_call_id,
                    name=run_event.tool_name,
                    arguments=run_event.arguments or {},
                )
            )
            yield run_event, batch
        elif run_event.type == "usage":
            if not batch.usage:
                batch.usage = _usage_from_dict(run_event.usage)
            yield run_event, batch
        elif run_event.type == "error":
            _raise_if_context_length_exceeded(run_event.error)
            batch.error = run_event
            yield run_event, batch
            return
        elif run_event.type == "done":
            batch.done = run_event
            # done 不 yield，由调用方循环结束后处理
    # 隐式返回：生成器耗尽 = 流正常结束
```

### 修改 `_iter_request_events_impl` 中的循环

**现有代码**（第 1047–1161 行）：

```python
try:
    buffered_provider_events = list(
        _provider_events(provider, protocol_request)
    )
    for buffered_event in buffered_provider_events:
        if buffered_event.type == "error":
            _raise_if_context_length_exceeded(buffered_event.error)
    break
except BaseException as exc:
    # ... 压缩重试逻辑 ...

# 第二遍
for event in buffered_provider_events:
    if event.type == "text_delta":
        iteration_text.append(event.content)
        all_text.append(event.content)
        yield event
    elif event.type == "reasoning_delta":
        # ...
    # ...
```

**替换为**：

```python
try:
    # ── 流式产出：第一遍直接推送 SSE，同时累积数据 ──
    batch = _StreamedBatch()
    for event, batch in _stream_provider_events(provider, protocol_request):
        # text_delta / reasoning_delta / tool_call_start / usage 已在上层 yield
        # 这里只需要把非 error 事件继续透传给外层 SSE
        if event.type == "error":
            # error 已安检，透传后终止
            yield event
            return
        if event.type != "done":
            yield event  # 推 SSE

    # ── done 事件处理 ──
    if batch.done is None:
        yield error_event(
            EngineError("Provider 事件流缺少 done 终态"), phase="provider"
        )
        return

    # ── 从 batch 提取数据（替代原来的第二遍遍历 buffered） ──
    iteration_text = [batch.text] if batch.text else []
    iteration_reasoning = [batch.reasoning] if batch.reasoning else []
    calls = batch.calls
    iteration_done = batch.done
    iteration_usage = batch.usage or _usage_from_dict(batch.done.usage)

    # 文本累积到全局（用于最终提交）
    if batch.text:
        all_text.append(batch.text)
    if batch.reasoning:
        all_reasoning.append(batch.reasoning)

    break  # 安检通过，跳出重试循环

except BaseException as exc:
    # ... 压缩重试逻辑完全不变 ...
```

**注意**：`iteration_text` 和 `iteration_reasoning` 原来是 `list[str]`，在后续代码中通过 `"".join(iteration_text)` 使用。batch 里已经是完整拼接的字符串，后续的 join 使用方式需微调，或者直接将 batch.text 包成单元素列表保持兼容。建议保持 `["..."]` 格式以最小化改动面。

### 后续不变代码

重试循环之后的以下代码**完全不动**：

- `iteration_usage` 合并 → `_merge_usage(usage_total, iteration_usage)`
- `calls` → 工具执行循环
- `all_text` / `all_reasoning` → 最终提交到历史窗口
- 非流式路径（`stream=False`）：`_provider_events` 对非流式本身就返回完整 `KemoResponse`，生成器只有一轮产出，`list()` 与否无关——**但改为直接迭代后非流式路径也能正确工作**，因为 `_events_for_protocol_response` 一次性 yield 所有事件。

## 五、风险与边界

| 场景 | 影响评估 |
|------|---------|
| Provider 在流中间返回 error（非 context_length_exceeded） | error 事件立即推送 SSE 并 return；客户端看到部分文本 + 错误，行为合理 |
| Provider 首个事件就是 context_length_exceeded | error 安检触发 `_raise_if_context_length_exceeded` → 进入压缩重试，**此时尚未 yield 任何文本给客户端** |
| Provider 流末 RESPONSE_FAILED 带 context_length_exceeded | 极罕见；若出现，文本已推送无法撤回，但压缩重试会生成新文本继续推送 |
| 非流式 Provider | `_events_for_protocol_response()` 一次性 yield 所有事件，行为不变 |
| chat API 和 kemo API | 到 `_provider_events()` 层已统一为 RunEvent，不受影响 |

---

## 六、应达到的效果

1. **前端**：SSE 流中 `text_delta` 事件逐 token 到达，文字渐进式出现，不再长时间空白等待
2. **工具调用**：`tool_call_start` 事件也在 Provider 产出时立即推送到前端
3. **错误处理**：`context_length_exceeded` 首个事件即被拦截，不影响客户端；非 context 类错误立即通知客户端
4. **兼容性**：非流式路径行为不变；chat/kemo 两种 API 形式行为不变；历史提交、记忆加权、工具循环逻辑不变
