# 记忆生命周期

`users/<user>/improve/` 按时间档位保存记忆碎片：

```text
seven_days → one_month → half_year → permanent
```

## 权重规则

- 不进行每日权重衰减，不每天遍历全库减权。
- 只有记忆被最终选中并实际注入模型上下文，或被任务实际使用时才加权；仅检索命中不加权。
- 同一条记忆在同一用户本地自然日最多加权一次。
- 权重无上限，只用于比较记忆在当前档位内的实际活跃程度。
- 进入新档位后权重归零，重新从该档位累计。

## 档位审核

| 当前档位 | 持续时间 | 升级阈值 | 下一档位 |
|---|---:|---:|---|
| `seven_days` | 7 天 | 3 | `one_month` |
| `one_month` | 30 天 | 10 | `half_year` |
| `half_year` | 180 天 | 60 | `permanent` |
| `permanent` | 无到期 | 无 | 无 |

到达 `review_at` 后：

- 权重达到阈值：升级，权重归零，重新计算进入时间和审核时间。
- 权重未达到阈值：直接删除。
- `permanent` 是最高档，不自动到期；仍允许用户明确纠正或删除。

## 数据与执行边界

- 所有档位的 `data.json` 使用统一条目契约和原子替换写入。
- 成功提交的对话才能产生记忆候选；失败、取消或未提交轮次不得写入。
- 用户明确要求记住的有效内容可直接进入永久档。
- 密码、API Key、Token、Cookie、私钥、验证码等敏感凭据禁止入库。
- `memory_temporary_important.md` 是从记忆派生的热画像，不参与档位升级。
