# kemo-agent 项目介绍

## 项目定位

kemo-agent 是面向个人智能基础设施的本地优先、多用户 Agent Runtime。它不是只保存当前窗口
上下文的聊天壳，而是把对话历史、长期记忆、知识、工具、子代理、任务计划、定时调度、感知、
拓展和多入口交互组织成持续存在的用户工作空间。

当前稳定版本为 `1.2.4`。`1.0.0` 完成主生态闭环，`1.0.1` 对完整框架进行了系统性稳定性
复核；`1.0.2` 修复潮汐记忆热画像输出上限、已有碎片搜索命中、每日加权和批量搜索性能；
`1.0.3` 建立可配置的请求级动态快照机制：拓展和感知分别由用户选择“单轮固定快照”或
“请求级实时注入”。两个开关默认关闭以提高 Prompt Cache 命中率；采集任务始终独立调度；
`1.0.4` 增强 Provider 工具参数异常恢复、生成媒体嵌套路径找回和 Web 跨渠道只读历史，外部消息、
CLI 与 Web 继续共享同一用户记忆，同时修正技能编辑器和超长引导内容的前端布局。
`1.0.5` 为拓展和感知增加独立的用户级总注入闸门，两类数据均可选择不注入、按轮固定或
请求级实时注入；上下文窗口会只读展示当前有效策略。运行状态与 Prompt 分段诊断统一识别
`disabled`，生成媒体的嵌套路径找回使用有界 LRU、短期失败缓存和受限扫描，避免异常请求重复扫盘。
`1.1.0` 完成主生态的移动端闭环：新增 `kemo_app` 全局拓展，为 Android 客户端提供独立的 HTTP/SSE/WebSocket 桥接服务（两级认证、流式对话与运行中引导、任务与定时、文件传输上限 80 MiB、在线设备统计），kemo-agent 生态正式延伸至手机端。该拓展的公开源码默认为未初始化、未激活，只有部署者在本地生成配置、设置设备 Token 与用户密码并显式启动后才会监听端口。
`1.1.1` 修正移动端会话来源合同：Android App 全链路固定使用 `source=app`，与 `source=web` 的活动租约、历史读写、关闭、压缩、删除和记忆处理互相隔离；网页历史把 APP 会话标注为“APP版”并保持只读。核心更新器开始分发 `kemo_app` 公开源码，同时保留部署端本地凭据、激活状态、采集摘要和运行文件。
`1.1.2` 加固任务计划、记忆、长工具等待、APP 桥接和 Web 交互：计划创建成功后只收束当前 `source + session_id` 的 Run，其他对话不受影响；临时重要记忆 Prompt 预算提升至 20000 字符；新增最长两小时、条件满足即返回的 `wait_for_condition`；已显式激活的 `kemo_app` 可由后台采集器限流恢复；Web 暗色主题、工具调用展开区和长计划起跑溢出同步修复。
`1.2.0` 是会话级长任务版本。用户在单个对话空间显式开启后，只有 Run 因 `max_tool_iterations` 收束时才会自动跨 Run 继续；每个 Run 仍独立提交历史并进入既有上下文选择与压缩链路，客户端通过非终态 `long_task_update` 更新当前 Run ID 和累计统计。状态按 `(user, source, session_id)` 隔离并保存在现有会话记录中，不进入全局或用户配置。关闭开关不会中断当前 Run，取消则终止整个逻辑长任务；上下文保护、Provider 错误、计划批准边界和普通取消均不会触发续跑。自动、手动与 Provider 超限压缩新增 `context_compression` 可见事件；摘要就绪后，裁剪轮次仍按既有队列在本轮提交后完成记忆分析，零新增候选也是合法结果。
`1.2.1` 聚焦长期运行可靠性。历史正文、轮次分区、会话索引和运行状态在统一 SQLite 事务内提交，并通过跨进程锁保护兼容写路径；系统 Cron 使用单领导租约，正常高频状态先进入内存检查点并按周期落盘，成功日志聚合、错误立即记录。Provider 工具调用在同一响应内先整批校验，主智能体与子代理仅在无不可重放媒体副作用时安全纠错。Web 将拓展、技能和插件统一纳入能力引用抽屉。Android `kemo_app` 桥接协议推进到 `1.1.4`，在 1.1.3 后台 Run 快照基础上增加跨进程生命周期锁、Windows 启动交接保护、PID/实例安全对账、精确端口诊断与临时退避自愈。
`1.2.2` 是稳定性和维护更新。`run/` 按职责拆成领域包，并删除旧的平铺导入路径；启动器恢复正确项目根目录，并在默认端口不可用时使用备用端口；本机 `kemo_app` 桥接跟随启动器发布的实际 Web 地址。任务计划支持修改、重试、重置、修订查看和安全回滚，Web 修改与重试按计划所属 `session_id` 隔离，任务摘要、执行记录和修订列表在返回浏览器前再次脱敏。网页成功结束音效与失败音效按用户独立保存，只在 Windows 桌面网页端显示；成功只在显式完成的最终 Run 播放，失败只在明确失败的最终 Run 播放，取消、暂停、受限停止和长任务中间 Run 不播放；发送附件后立即清除引用；运行中引导上传使用 `purpose=input`。根 `update.py` 改为薄兼容入口，实际更新能力按版本清单、远程源码、板块调度、备份、锁、回滚、构建和迁移拆入 `update/`；更新器保护 Cron/拓展运行态、拒绝组件降级并脱敏更新日志。本次同时补充项目路径、包结构、备用端口、模板和更新器安全合同测试。旧 `run.*` 平铺导入路径不再支持，外部插件需要迁移。`kemo_app` 桥接端口跟随修复记为 `1.1.5`。

`1.2.3` 继续做稳定性收口：Kemo 网关在发布流式工具完成事件前先校验完整参数，并对并行调用采用批次原子语义；后台 Shell Worker 强制执行截止时间，日志异常不会堵塞子进程，取消时复核 PID 身份并隐藏宿主机绝对路径；对话取消、Provider 异常和参数重试路径使用幂等归档，避免正文与思考链在同一轮重复累加；Provider 诊断增加敏感字段别名、递归/节点预算和前缀 JSON 脱敏；主智能体与子代理对输出解析错误执行最多 5 次有界重试，上下文压缩记忆提取在重试中复用，持久化 Provider 标识脱敏并限长。该版本只更新现有合同和测试，不新增用户配置字段。

`1.2.4` 在此基础上增加外部智能体绑定合同。已授权拓展可以通过 `agent_bridge.json` 声明外部代理的名称、Schema、命令和超时，由 `subagent_dispatch` 统一列出并同步调用；实际远程连接和凭据仍由拓展隔离进程负责。网页端重试状态在下一次尝试产生实际进度时立即收束，子智能体模型档位说明也明确对应后台功能。当前外部绑定不支持后台提交，避免在没有统一持久任务状态的情况下留下无法恢复的远程任务。

项目的核心目标是：

- 让对话在不同时间和入口之间保持连续；
- 让数据、授权和运行状态由部署者掌管；
- 让复杂任务可规划、可暂停、可继续、可回溯；
- 让能力通过明确合同扩展，而不是把所有逻辑堆入对话主循环。

## 核心能力

### 潮汐式生命周期记忆

Kemo Tidal Engram 记忆系统把记忆分为七天、一个月、半年和永久四档。用户历史中的可回溯
证据通过完整短语优先、带覆盖率门槛的多关键词搜索定位已有碎片；确认语义一致后复用稳定
文件名，使临时记忆每日最多加权一次。达到阈值后晋升，未达到阈值的过期内容淡出。

`memory_temporary_important.md` 是从临时三层单向提炼的可重建热视图，不是第五个记忆层，
也不能反向作为源记忆加权证据。热视图只强化高价值事实，不替换或阻止七天、月、半年三层
权威碎片按各自上限正常注入。其 Prompt 注入预算已提升至 20000 字符；语义独立的 20000
字符输出上限只用于阻止模型失控重复。

### 长对话与上下文压缩

完整历史保存于 archive 窗口，Provider 使用可裁剪 runtime 窗口。达到轮次或 Token 条件时，
框架通过 `context_manage` 生成摘要并事务化裁剪 runtime；完整归档不会因压缩而被删除。

Web 只加载最近消息，需要时用游标继续读取更早正文，避免历史增多后每次启动全量扫盘。

### 会话级长任务

长任务模式把“单个 Run 的工具调用上限”保留为稳定保护边界，同时允许用户授权当前对话在命中该边界后
开启下一 Run。中间 Run 不向客户端发送终态 `done`，而是发送 `long_task_update`；最终 Run 才结束整个
逻辑任务。Web 输入框上方展示原始请求、累计耗时、Run/续跑次数、工具调用、Provider 请求和 Token
用量，并提供会话级取消。内部续跑控制消息带 synthetic metadata，历史界面只显示续跑边界，记忆和
摘要仍使用原始用户请求，避免控制提示污染长期数据。

### 三层知识库

知识分为：

- `global_knowledge/`：框架级公共知识；
- `shared_knowledge/`：跨用户共享资料；
- `users/<user>/knowledge/`：用户私有资料。

系统 Prompt 只自动注入各层索引，正文按需读取。Kemo Graph 是可选的侧载超级文档站，只有
用户明确要求时才查询、同步或整理，不接管本地知识和记忆。

### 工具与技能

`plugins/` 是唯一能注册 Provider function call 的目录。每个插件使用 `SKILL.md` 描述操作规则
和 Tool Schema，并由本地 Python 入口执行。

长时间后台任务应由专门工具先启动，再使用 `wait_for_condition` 等待可靠的 PID、路径或端口
条件；最长等待 7200 秒，条件满足立即返回。等待超时只代表条件尚未满足，不等同于后台任务
失败。插件可声明最多 30 秒的外层看门狗清理宽限，但不得借此增加实际业务期限。

技能只提供可复用指令，不注册工具。共享技能位于 `shared_skills/`，用户技能位于
`users/<user>/user_skills/`。Web 支持安全上传技能 ZIP 并递归发现 `SKILL.md`。

### 子代理

内置子代理包括：

- `context_manage`：上下文摘要和压缩；
- `history_summary`：后台历史标题/摘要；
- `memory_temporary_important`：临时重要热视图维护；
- `self_improve`：记忆候选提取和晋升决策；
- `task_plan`：任务计划生成；
- `time_plan`：定时任务参数规划。

用户可以在 `users/<user>/agents/` 创建自己的子代理。每个子代理拥有独立 Prompt、模型档位、
工具白名单、知识权限、超时和取消信号，不继承主智能体全部权限。

### 任务计划与定时任务

任务计划创建后，创建它的当前主智能体 Run 会在同一会话边界强制收束；同一 Provider 响应中
排在创建工具之后的调用不会执行。计划存储仍按用户集中管理，但 Prompt 注入、主智能体管理
工具和 Web/App 起跑都会校验 `source + session_id`，因此 A 对话不会把计划或暂停状态传播给 B 对话。

任务计划支持创建、审批、逐步执行、暂停、继续、失败和取消。计划、步骤与依赖存入用户级
SQLite。

定时任务使用北京时间，支持一次性和周期性规则。RuntimeHost 负责 Cron 扫描、系统维护、
历史摘要、任务计划调度和消息路由。

### 感知、拓展和外部消息

- 感知：从已授权数据源单向采集状态并注入 Prompt；
- 拓展：提供状态摘要和显式操控入口；
- 外部消息：把 Telegram 等平台适配为统一消息传输合同；
- Kemo 网关状态拓展：只读查看已配置网关运行状态；
- Kemo Graph 拓展：连接用户注册的内置或绝对路径 Library。

这些模块采用“最小框架合同 + 内部自由工作区”。模块可以很小，也可以包含完整工程，但必须
遵守清单、入口、权限、超时和输出协议。

### 多模态

首次输入和运行中引导都可携带图片、音频、视频和普通文件。Kemo 协议根据模型能力和 Asset
API 处理已支持模态；Chat 兼容协议保留图片直传链路，其余资产通过专用多模态或文件工具处理。

### 多入口

同一用户可以通过：

- Web；
- `cli.py`；
- 外部消息平台；
- Cron/任务计划；
- 框架内部维护任务

访问同一历史、记忆和已授权资源。入口不同，不代表创建新的用户身份。

## 本地数据与隐私边界

kemo-agent 本地管理对话、记忆、知识、任务和用户文件。不同用户使用独立工作空间，主配置和
模块白名单决定可使用的资源。

本地优先不等于模型请求永不离开机器。发送给外部 Provider 的 Prompt、历史片段、附件和工具
结果取决于用户选择的服务、模型能力和授权范围。部署者应同时审查 kemo-agent 配置和上游服务
隐私政策。

凭据通过 `.env`、用户配置或运行环境提供，不应写入知识库、记忆、日志、回复或 Git。

## 环境要求

基础环境：

- Python 3.10 或更高版本；
- Git；
- Node.js 与 npm（构建 React 前端时需要）。

如果机器暂时没有 Node.js，Python 后端仍可安装，但无法重新构建更新后的 Web 前端。

## 获取与首次部署

```bash
git clone https://github.com/kesepain-KE/kemo-agent.git
cd kemo-agent
python setup.py
```

`setup.py` 引导依赖安装、环境配置、前端构建和用户创建。非交互默认部署：

```bash
python setup.py --yes
```

可选参数包括：

- `--skip-deps`：跳过 Python 依赖安装；
- `--skip-web`：跳过前端构建。

跳过步骤后，部署者需要自行完成相应依赖或构建。

## 用户创建

setup 可在首次部署中引导创建用户，也可以独立运行：

```bash
python user_create.py
```

用户目录包含配置、人格、历史、记忆、知识、技能、拓展、子代理、上传和下载空间。完整结构见
`user-directory-skeleton.md`。

## 启动 Web

```bash
python start_web.py
```

默认监听端口为 1357：

```text
http://127.0.0.1:1357
```

如果默认端口被占用，启动器会在有限范围内尝试后续端口。也可以显式指定：

```bash
python start_web.py --host 0.0.0.0 --port 1357
```

开放局域网或公网监听前必须配置认证、TLS 反向代理、防火墙和可信代理边界。

### Web 认证

Web 认证支持：

- `WEB_ACCESS_TOKEN`；
- `WEB_USERNAME` + `WEB_PASSWORD`；
- `WEB_SESSION_SECRET`；
- 登录失败限流和可信反向代理配置。

用户名和密码必须同时配置或同时留空。详细字段、优先级和安全规则见 `env-reference.md`。

## 命令行入口

```bash
python cli.py
```

CLI 复用核心对话引擎和用户数据，不是另一套独立历史系统。需要后台 Cron、消息路由和维护任务
时，应通过 RuntimeHost 入口运行，而不是假定一次性 CLI 进程会永久驻留。

## 更新与重启

更新：

```bash
python update.py
```

根目录 `update.py` 是兼容入口，实际逻辑集中在 `update/` 包。更新器支持按 core、agents、
plugins、web 四个板块同步，使用单实例锁、远程源码一致性校验和失败恢复，并保护用户数据、
配置、Cron 运行状态、运行时数据库和模块派生存储。全量更新会同时检查根版本和四个组件版本，
不允许隐式降级；输出到终端或 CI 的仓库 URL、配置差异和错误信息会先脱敏。详细规则见
`version-and-update-modules.md`。

`restart.py` 是 Web 受控重启辅助入口，一般由 Web API 调用，不建议把它当作常规手工启动命令。
重启后新进程会重新读取 `.env` 和磁盘配置。

| 路径 | 内容 |
|------|------|

| `shared_skills/` | 共享技能 |

| `users/<name>/` | 用户私有工作空间 |
| `template/` | 模块和用户创建骨架 |

## 相关项目

- `kemo-adapter-api`：Kemo 模型网关与 Provider 适配项目；
- `kemo-graph`：可选知识图谱和大型文档 Library 服务；
- `kemo-agent-doc`：面向用户的独立文档站；
- `votx-agent`：独立维护的 Agent 项目，与 kemo-agent 不存在继承关系。

这些项目可以协作使用，但 kemo-agent 的本地历史、记忆、知识和主对话能力不应因可选项目未启动
而整体失效。
