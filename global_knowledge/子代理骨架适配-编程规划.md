# 子代理骨架适配 — 编程规划

> 目标：将框架运行时代码适配到新的子代理 JSON 配置骨架。
>
> 输出给编程 agent。不修改代码，只输出结构化规划。

---

## 一、问题

子代理的 JSON 骨架已于 2026-07-19 更新为新格式（`agent.json` 精简为 4 字段、`agent-config.json` 替换为 6 字段新结构、新增 `trigger.md`），但以下框架运行时代码仍引用旧格式，导致加载子代理时会直接报错：

| 文件 | 问题 |
|------|------|
| `agents/_runtime/schema.py` | `_load_manifest()` 要求 agent.json 必须含 `enabled`、`instruction`、`model_profile`、`timeout`、`execution`、`write_policy`、`input_schema`、`output_schema` 共 8 个必填字段，新 agent.json 只有 4 个（`name`、`version`、`description`、`trigger`）。`_load_capabilities()` 仍读旧 agent-config.json 的 `exposure`、`prompt_sources`、`knowledge.scopes`、`context` 等字段，新格式为 `internal_mode`、`allowed_callers`、`tools`、`global_knowledge`、`shared_knowledge`、`inherit_main_history`。`AgentCapabilities` 仍保留 12 个旧字段。 |
| `agents/_runtime/resources.py` | `build_agent_prompt_bundle()` 通过 `capabilities.shared_skills`、`capabilities.user_skills`、`capabilities.global_expand` 等旧字段构建子代理 prompt，新结构中已不存在这些字段。`build_agent_tool_registry()` 使用 `capabilities.plugin_tools`（保留）和 `capabilities.knowledge_body_access`（旧字段需迁移）。 |
| `agents/_runtime/user_packages.py` | `create_user_agent_package()` 创建用户子代理包时仍写入旧格式 agent.json（12 字段）和旧格式 agent-config.json（`exposure`/`prompt_sources`/`knowledge`/`context` 结构）。 |
| `run/agent_runner.py` | `_run_model()` 和 `run()` 使用 `definition.model_profile`、`definition.execution`、`definition.write_policy`、`definition.timeout`、`definition.input_schema`、`definition.output_schema` 等旧 AgentDefinition 字段。`AgentRunResult.metadata` 写入 `model_profile`、`execution`、`write_policy`。 |
| `tests/test_subagent_hotplug.py` | `write_agent()` 硬编码旧格式 agent.json（12 字段）和 agent-config.json（旧 5 节点结构）。 |
| `tests/test_subagent_runtime.py` | 直接引用 `definition.instruction_file`（`AGENT.md`），以及通过旧 registry 测试。 |
| `tests/test_task_plan.py` | 硬编码旧格式 agent.json（含 `instruction`、`任务计划.txt` 等旧引用）。 |
| `tests/test_memory_lifecycle.py` | 直接读取 `agents/self_improve/agent.json` 旧格式内容。 |

---

## 二、方案

### 总体策略

**最小破坏原则**：内部 `AgentDefinition` 和 `AgentCapabilities` 保持字段不变（或做最小加法），只修改 JSON 解析层做新旧格式映射。这样 `resources.py`、`agent_runner.py` 等下游消费者无需大改。

### 字段映射表

#### agent.json 新→旧映射

| 新字段（仅 4 个） | 旧 AgentDefinition 字段 | 处理方式 |
|---|---|---|
| `name` | `name` | 直接映射 |
| `version` | `version` | 直接映射 |
| `description` | `description` | 直接映射 |
| `trigger` | — | 新增字段，指向 `trigger.md`，解析时读取注册信息注入 system prompt |
| （不再存在） | `enabled` | 默认 `true` |
| （不再存在） | `instruction_file` | 固定为 `AGENT.md` |
| （不再存在） | `instruction` | 读取同目录 `AGENT.md` |
| （不再存在） | `executor` | 默认 `executor.py:execute`（内置代理）/ `builtin:llm`（用户代理） |
| （不再存在） | `model_profile` | 默认 `default` |
| （不再存在） | `timeout` | 从 `config/global_config.json` → `agent_runtime.default_timeout` 读取（600s） |
| （不再存在） | `execution` | 默认 `sync`；内置代理按旧值硬编码映射 |
| （不再存在） | `write_policy` | 默认 `derived_cache` |
| （不再存在） | `input_schema` | 在 `trigger.md` 的操作信息区域定义，运行时由调用方传入的 JSON 做宽松校验 |
| （不再存在） | `output_schema` | 在 `trigger.md` 的操作信息区域定义，运行时解析 LLM 输出后做宽松校验 |

#### agent-config.json 新→旧映射

| 新字段 | 旧 AgentCapabilities 字段 | 处理方式 |
|---|---|---|
| `internal_mode: true` | `exposure` = `"internal"` | 直接映射 |
| `internal_mode: false` | `exposure` = `"tool"` | 直接映射 |
| `allowed_callers` | `allowed_callers` | 直接映射 |
| `tools.plugins.allow` | `plugin_tools` | 直接映射 |
| `tools.shared_skills.allow` | `shared_skills` | 直接映射 |
| `tools.max_iterations` | `max_tool_iterations` | 直接映射，默认 20 |
| `global_knowledge: true` | `knowledge_scopes` 增加 `"global"` | 映射 |
| `global_knowledge: false` | 不增加（除非 shared 也 true） | — |
| `shared_knowledge: true` | `knowledge_scopes` 增加 `"shared"` | 映射 |
| `shared_knowledge: false` | 不增加 | — |
| （不再存在） | `user_skills` | 固定为空（子代理不注入用户技能） |
| （不再存在） | `global_expand` | 固定为空 |
| （不再存在） | `shared_expand` | 固定为空 |
| （不再存在） | `user_expand` | 固定为空 |
| （不再存在） | `knowledge_index_enabled` | `global_knowledge \|\| shared_knowledge` 时自动为 `true` |
| （不再存在） | `knowledge_body_access` | 固定 `"none"` |
| （不再存在） | `knowledge_max_index_chars` | 固定 `8000` |
| `inherit_main_history` | `inherit_main_history` | 直接映射 |
| （不再存在） | `inherit_current_request` | 等同 `inherit_main_history`（新设计中合并为一个开关） |

### 内置代理的硬编码默认值

由于 agent.json 不再携带 `execution`、`write_policy`、`model_profile`，这些值需要按代理名硬编码或从旧值迁移。以下列表基于更新前的旧 agent.json：

| 代理 | execution | write_policy | model_profile |
|------|-----------|-------------|---------------|
| context_manage | sync | derived_cache | cheap |
| token_condense | sync | derived_cache | cheap |
| memory_temporary_important | background_serial | user_memory | cheap |
| self_improve | background_serial | user_memory | reasoning |
| task_plan | background_serial | user_task | reasoning |
| time_plan | background_serial | user_task | default |

> 实现时建议在 `_load_manifest()` 中维护一个 `_BUILTIN_DEFAULTS` 字典按 name 查表。

## 三、详细规划

### 步骤 1：修改 `agents/_runtime/schema.py`

**文件**：`E:\code\kemo-agent\agents\_runtime\schema.py`

#### 1.1 更新 `AgentCapabilities` dataclass

- 保留现有字段不变（保证下游兼容）
- 新增 `trigger_file: str = ""` 字段
- 移除不再需要的字段由调用方自行忽略（不删字段，避免破坏性变更）

#### 1.2 重写 `_load_capabilities()`

当前函数读旧 agent-config.json 的 `exposure` / `prompt_sources` / `knowledge` / `context` 结构。

改为读新 agent-config.json 结构：

```python
def _load_capabilities(path, *, legacy=False):
    raw = _read_json_object(path, "子代理能力配置")
    # 读取新字段
    internal_mode = raw.get("internal_mode", True)
    allowed_callers = raw.get("allowed_callers", [])
    tools_raw = raw.get("tools") or {}
    plugins_allow = (tools_raw.get("plugins") or {}).get("allow", [])
    shared_skills_allow = (tools_raw.get("shared_skills") or {}).get("allow", [])
    max_iterations = tools_raw.get("max_iterations", 20)
    global_knowledge = raw.get("global_knowledge", False)
    shared_knowledge = raw.get("shared_knowledge", False)
    inherit_main_history = raw.get("inherit_main_history", False)
    
    # 映射到 AgentCapabilities
    return AgentCapabilities(
        exposure="internal" if internal_mode else "tool",
        allowed_callers=tuple(allowed_callers),
        plugin_tools=tuple(plugins_allow),
        max_tool_iterations=max_iterations,
        shared_skills=tuple(shared_skills_allow),
        user_skills=(),  # 新设计：子代理不注入用户技能
        global_expand=(),
        shared_expand=(),
        user_expand=(),
        knowledge_scopes=self._build_knowledge_scopes(global_knowledge, shared_knowledge),
        knowledge_index_enabled=global_knowledge or shared_knowledge,
        knowledge_body_access="none",
        knowledge_max_index_chars=8000 if (global_knowledge or shared_knowledge) else 0,
        inherit_main_history=inherit_main_history,
        inherit_current_request=inherit_main_history,
    )
```

#### 1.3 修改 `_load_manifest()`

当前函数将 `enabled`、`instruction`、`model_profile` 等 8 个字段作为必填。

改为从新 agent.json（仅 4 字段：`name`、`version`、`description`、`trigger`）读取，其余字段从内置默认表或全局配置补全：

```python
_BUILTIN_DEFAULTS = {
    "context_manage": {"execution": "sync", "write_policy": "derived_cache", "model_profile": "cheap"},
    "token_condense": {"execution": "sync", "write_policy": "derived_cache", "model_profile": "cheap"},
    "memory_temporary_important": {"execution": "background_serial", "write_policy": "user_memory", "model_profile": "cheap"},
    "self_improve": {"execution": "background_serial", "write_policy": "user_memory", "model_profile": "reasoning"},
    "task_plan": {"execution": "background_serial", "write_policy": "user_task", "model_profile": "reasoning"},
    "time_plan": {"execution": "background_serial", "write_policy": "user_task", "model_profile": "default"},
}

def _load_manifest(path, *, source, root):
    raw = _read_json_object(path, "子代理清单")
    name = str(raw["name"]).strip()
    if name != path.parent.name:
        raise ...
    
    # 从新 agent.json 读取
    trigger_file = str(raw.get("trigger", "trigger.md")).strip()
    trigger_path = path.parent / trigger_file
    trigger_content = trigger_path.read_text("utf-8-sig") if trigger_path.is_file() else ""
    
    # AGENT.md 仍是子代理自我运行手册
    instruction_path = path.parent / "AGENT.md"
    instruction = instruction_path.read_text("utf-8-sig").strip() if instruction_path.is_file() else ""
    
    # 内置代理 → 从默认表查；用户代理 → 硬编码
    if source == "builtin":
        defaults = _BUILTIN_DEFAULTS.get(name, {})
    else:
        defaults = {}
    
    return AgentDefinition(
        name=name,
        version=str(raw.get("version", "1.0.0")).strip(),
        description=str(raw.get("description", "")).strip(),
        enabled=True,  # 默认启用
        instruction_file="AGENT.md",
        instruction=instruction,
        executor="executor.py:execute" if source == "builtin" else "builtin:llm",
        model_profile=defaults.get("model_profile", "default"),
        timeout=_read_agent_timeout(root, defaults),  # 从 global_config.json 读取
        execution=defaults.get("execution", "sync"),
        write_policy=defaults.get("write_policy", "derived_cache"),
        input_schema={"type": "object", "additionalProperties": True},  # 宽松校验
        output_schema={"type": "object", "additionalProperties": True},  # 宽松校验
        capabilities=_load_capabilities(config_path, legacy=False),
        source=source,
        directory=path.parent,
        manifest_path=path,
        config_path=config_path,
    )
```

#### 1.4 新增辅助函数 `_read_agent_timeout()`

```python
def _read_agent_timeout(root: Path, defaults: dict) -> float:
    """从 global_config.json 读取 default_timeout，或使用默认值"""
    try:
        config_path = root / "config" / "global_config.json"
        if config_path.is_file():
            config = json.loads(config_path.read_text("utf-8-sig"))
            return float((config.get("agent_runtime") or {}).get("default_timeout", 600))
    except Exception:
        pass
    return 600.0
```

#### 1.5 trigger.md 读取

在 `_load_manifest()` 中读取 trigger.md，提取「注册信息」区域内容，存到 `AgentDefinition` 的新字段或作为单独的注入文本。具体注入逻辑在步骤 5 中单独处理。

### 步骤 2：修改 `agents/_runtime/resources.py`

**文件**：`E:\code\kemo-agent\agents\_runtime\resources.py`

`build_agent_prompt_bundle()` 当前通过 `capabilities.shared_skills`、`capabilities.user_skills` 等字段注入技能和扩展提示词。

新设计中这些字段已全部置空（子代理不再注入用户技能/扩展），因此该函数大幅简化：

- 技能注入：仅注入 `shared_skills`（如果有）
- 扩展注入：全部移除（字段已为空）
- 知识库注入：仅当 `knowledge_index_enabled` 时注入索引
- 保留 `definition.instruction`（AGENT.md 内容）作为核心 system prompt
- 从 `definition.trigger_content`（新字段）注入注册信息摘要

逻辑变更点：

```
原来: instruction + skills + knowledge_index + expand_data + execution_contract
改为: instruction + trigger_registration + skills + knowledge_index + execution_contract
```

`build_agent_tool_registry()` 基本不变，因为 `capabilities.plugin_tools` 字段名保留，`knowledge_body_access` 固定为 `"none"`。

### 步骤 5：trigger.md 注入到主智能体 system prompt

**新文件或修改**：`run/prompt.py` 或 `run/prompt_sources.py`

当前主智能体的 system prompt 构建中尚未注入子代理信息。新设计下需要：

1. 扫描 `agents/` 目录下的所有 `trigger.md`
2. 提取每个文件的「# 注册信息」区域内容
3. 作为 `[subagent_registry]` 区块注入到主智能体 system prompt

注入格式：
```
[subagent_registry]
以下子代理可供调用。触发条件和职责见各条目，详细操作信息请自行读取对应 trigger.md 文件。

### context_manage
- 触发: ...
- 职责: ...
- 模型: cheap

### task_plan
- 触发: ...
- 职责: ...
- 模型: reasoning
- 工具: knowledge_search
```

**注意**：只注入注册信息（元数据摘要），不注入操作信息。操作信息需要主智能体调用 `read_file` 自行读取 `trigger.md`。
