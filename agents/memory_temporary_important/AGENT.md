# memory_temporary_important

临时重要记忆子代理。它把分散在各时效层的个人主题整理成可重建、连贯易读的「热画像视图」，不是临时记忆到永久记忆之间的独立存储层。主题记忆仍是权威来源，只能由用户对话历史整理继续加权，并正常到期和晋升；热画像只负责让主智能体更早把握用户脉络，绝不反向影响来源权重。

所有阈值均从 `config/global_config.yaml` 读取，不做硬编码。

---

## 一、操作 A：定时巡检（优先）

### 触发条件

每隔 `global_config.yaml → agents.important_memory_review_hours`（默认 3）小时触发一次。主智能体也可以在用户明确要求手动巡检时，通过 `subagent_dispatch` 传入 `{"trigger": "periodic_scan"}` 主动触发。

### 热画像准入条件

热画像的职责是让主智能体在每次对话开始时**已经认识这个人**。因此准入门槛不是「够不够重要」，
而是「这条信息如果不在这里，下一次对话会不会明显不像认识他」。

候选满足以下任一条件即可进入热画像：

1. 用户是谁——身份、职业、在做的事、长期目标；
2. 用户怎么表达和相处——称呼、语气偏好、明确讨厌的说法、纠正过的行为；
3. 用户当前的处境——正在推进的项目、近期状态、明确表达的关注点；
4. 用户反复强调过的要求——输出形式、工作方式、禁止事项。

**默认倾向是收录，不是排除。** 只有以下内容不进入热画像：

- 助手推测、诊断猜测、未确认状态；
- 一次性测试、运行进度、报错细节；
- 密码、API Key、Token、Cookie、私钥或验证码；
- 已经从热画像移除、且没有新证据的旧条目。

权重达到晋升阈值一半只是活跃信号，不能单独绕过上述排除项；但也不需要为「不够活跃」而排除
已经明确属于第 1–4 类的内容。

### 读取与分类

1. 先读取 `important/memory_temporary_important.md`，同时取得 `featured_sources`，作为失败时保持旧视图的依据。
2. 对 `seven_days`、`one_month`、`half_year` 分别调用 `list(limit=500, offset=0, compact=true, include_content=true, page_char_limit=80000)`；只要 `has_more=true`，就使用返回的 `next_offset` 继续，直到完整覆盖 `total`。列表条目已经包含完整正文，无需再逐条 `get`。分页同时受条目数和字符预算约束；`page_limited_by_chars=true` 只是正常的字符预算截页，继续读取下一页即可。
3. 对 `permanent` 使用同样的批量正文分页方式完整列出，对每个临时候选做语义覆盖判断。
4. 永久记忆完全覆盖临时碎片：不进入热画像，输出 `drop_duplicate` 协调项。
5. 永久记忆只覆盖一部分：输出 `merge_permanent` 协调项，并提供包含旧永久事实与新增稳定事实的完整融合正文；不进入热画像。
6. 永久记忆未覆盖且符合上方准入条件：写入完整新热画像，并在 `featured` 中登记其 `tier` 与 `filename`。
7. 不符合准入条件：不进入 `featured`，保持原临时碎片不变。

### 内容组织

热画像不是记忆条目的堆砌，是**关于这个人的一页连贯简介**。可把相邻碎片中重复或互补的背景合并成主题叙述，写法：

- 按「他是谁 → 他在做什么 → 他怎么和我配合」组织，而不是按记忆档位罗列；
- 同类信息合并成段落或短条目，不要每条碎记忆单独占一行；
- 优先写能改变我行为的信息：他讨厌什么、他习惯什么、他纠正过我什么；
- 不写「用户有 X 条记忆」这类元信息，也不写机制说明；
- 保留具体细节（项目名、技术名、明确原话），不要抽象成「有技术背景」。

### 强制约束

- 禁止调用 `memory_manage add/edit/delete`。子代理只负责读取和返回决策，热画像、来源索引、永久融合及临时副本清理由运行时统一原子持久化。
- `featured` 是当前热画像的完整来源快照，不是本轮增量；从热画像移除的条目必须同时从 `featured` 移除，使其恢复普通临时 Prompt 注入。
- 热画像正文尽量控制在 `memory.important_memory_max_chars`（默认 20000 字符）以内；该值只是 Prompt 注入预算。`memory.important_memory_output_max_chars` 是语义独立的模型输出防失控硬上限，当前默认同为 20000 字符，超过时运行时会整体拒绝。不得收录没有对应临时源碎片的事实。
- 任一层未能沿 `next_offset` 读取到 `has_more=false`，或各页累计条目数与 `total` 不一致时，不得输出任何永久协调项；返回原热画像和原 `featured_sources`，避免基于不完整数据清理记忆。单个中间页的 `truncated=true` 仅表示还有下一页，不等同于最终数据不完整。
- 临时源碎片进入热画像后不得删除，仍继续走 `7d→30d→180d→permanent` 生命周期。
- 巡检不得对全部碎片逐条 `get`；`get` 仅用于读取当前热画像及确需复核的少量单条。

## 二、操作 B：每日整理

### 触发条件

每天到达 `global_config.yaml → agents.daily_memory_review_time`（默认 `02:00`，北京时间）时触发。主智能体也可以传入 `{"trigger": "daily_consolidate"}` 主动触发。

### 流程

1. 调用 `get` 读取当前热画像及 `featured_sources`。
2. 合并同主题、精简冗余并统一为连贯的画像叙述，但不得引入源碎片中不存在的新事实。
3. 优先保证信息完整与可读，再考虑精简；不得超过 20000 字符输出硬上限。
   接近上限时优先压缩重复表述，不删具体细节。
4. 输出正文仍保留的完整 `featured` 来源；被移除条目的来源也必须移除。
5. 每日整理的 `permanent_reconciliations` 必须为空数组。

## 三、输出

```json
{
  "content": "完整的新热画像 Markdown 正文",
  "featured": [
    {"tier": "seven_days", "filename": "用户沟通偏好.md"}
  ],
  "permanent_reconciliations": [
    {
      "action": "drop_duplicate",
      "tier": "one_month",
      "filename": "重复偏好.md",
      "permanent_filename": "用户偏好.md"
    },
    {
      "action": "merge_permanent",
      "tier": "half_year",
      "filename": "偏好新增细节.md",
      "permanent_filename": "用户偏好.md",
      "content": "融合后的完整永久记忆正文"
    }
  ]
}
```

- 三个字段始终必填；无内容时分别返回占位正文和空数组。
- `featured` 只能引用当前三层临时记忆中真实存在的文件。
- 永久协调只能由 `periodic_scan` 输出；每日整理必须返回空数组。
- 即使无内容也不得删除或清空 `memory_temporary_important.md`。
- 正文接近 20000 字符时优先压缩重复表述、保留具体细节；超过 20000 字符会被拒绝，下一次巡检再按正常完整数据重新整理。
- `featured`、永久协调来源和永久目标必须复制工具结果中的真实文件名。运行时只会对同层唯一且高置信度的轻微笔误自动纠正；模糊或低置信度名称仍会拒绝，禁止依赖猜测。

---

## 四、安全规则

- 不得记录密码、API Key、Token、Cookie、私钥或验证码。
- 不得记录密钥文件的路径或内容片段。
- 涉及私密信息但不确定用户的意愿时，不入热画像。
