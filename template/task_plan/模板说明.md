# 计划任务模板说明

`plan_template.json` 只展示计划结构，不是运行时存储文件。创建或编辑计划时，应把同结构对象交给 `task_plan` 子智能体和 `PlanStore`；权威数据写入 `users/<name>/task_plan/task_plans.sqlite3`，不要复制 JSON 到用户目录。

## 字段说明

| 字段 | 说明 | 必填 |
|------|------|------|
| `plan_id` | 全局唯一计划 ID，格式 `plan_xxxxxxxx` | ✅ |
| `title` | 计划名称 | ✅ |
| `description` | 计划描述 | ✅ |
| `user` | 创建此计划的用户名 | ✅ |
| `status` | `pending`（待批准）/ `approved`（已批准）/ `running`（执行中）/ `paused`（暂停）/ `completed`（完成）/ `failed`（失败）/ `cancelled`（取消） | 不改 |
| `created_at` | 创建时间，ISO 8601 格式 | ✅ |
| `steps[*].step_id` | 步骤唯一标识 | ✅ |
| `steps[*].description` | 步骤描述，智能体据此执行 | ✅ |
| `steps[*].status` | 步骤状态：`pending` / `running` / `completed` / `failed` / `skipped` | 不改 |
| `steps[*].result` | 步骤执行结果摘要 | 不改 |

## 生命周期

1. 创建时 `status: "pending"`，等待用户在 Web UI 批准
2. 批准后 `status: "approved"`，智能体按步骤顺序执行
3. 每步完成后调用 `task_plan_step_done`，失败调用 `task_plan_step_fail`
4. 全部完成后 `status: "completed"`

## 与 task_plan 子代理的关系

`task_plan` 子代理（`agents/task_plan/`）负责分析用户请求并生成结构化对象，再由 `PlanStore` 校验并事务写入。用户若要手动创建，也应通过工具或 Web API 提交对象，不能直接编辑 SQLite。
