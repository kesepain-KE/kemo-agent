# 拓展模块模板说明

将本目录复制为 `global_expand/<name>/`、`shared_expand/<name>/` 或 `users/<user>/expand/<name>/`。拓展可以同时提供状态数据注入和外部操控；只读采集优先使用感知。

本目录只是框架最小合同样例，不是工程结构标准。拓展内部可以自由添加任意文件、任意层级目录或完整开源项目，也可以把极小功能保持为单文件。框架只调用 `expand.json` 声明的入口并读取声明的数据/说明文件；其他内部内容不会自动注册、注入或执行。不要为了匹配模板拆分简单实现，也不要把大型工程强行合并进 `data_update.py` 或 `start_expand.py`。

## 自动运行机制

RuntimeHost 按 `task_cron_system.expand_update_rate` 刷新三层拓展：全局与共享层每周期各扫描一次，用户层按用户身份隔离扫描。每个合法 `start_update` 都在独立 Python 子进程中执行。

- 调度器优先调用零参数 `update()`，不存在时回退到零参数 `main()`。
- 子进程使用隔离模式并受 `task_cron_system.module_update_timeout` 限制。
- Windows 后台采集与框架发起的拓展操控均隐藏终端；模块不要设置 `CREATE_NEW_CONSOLE`、启动无限循环或常驻后台进程。
- 用户手动运行脚本属于前台调试，不受后台隐藏策略影响。

隔离子进程用于限制生命周期和回收进程树，并不收窄操作系统文件或网络权限。只使用受信任的拓展代码；需要常驻浏览器、SSH 或设备会话时，应连接由系统或用户明确管理的外部服务，本模板不创建 daemon。

## `expand.json`

| 字段 | 说明 |
|------|------|
| `name` | 模块唯一标识，建议与目录名一致 |
| `explain` | 一句话功能描述 |
| `open_input` | 是否允许 `input_data.md` 进入 Prompt |
| `input_data` | 数据文件名，通常不改 |
| `input_health` | `正常` 或 `异常`；首次成功前建议为 `异常` |
| `start_update` | 零参数同步采集入口 |
| `open_control` | 是否开放操控能力 |
| `start_expand` | 操控入口脚本 |
| `start_control` | 操作说明文档 |
| `recent_update` | 可选，最近一次成功采集时间 |

所有清单路径必须留在模块目录内，不能经过符号链接、目录联接或 `..`。这只是作用域边界，不限制目录内部的工程布局。

## `data_update.py`

模板中的辅助函数只是可替换示例，不是必须保留的架构。可以重写整个入口、使用更小实现，或让入口调用模块内其他程序；框架只要求最终更新入口提供零参数 `update()`（或兼容 `main()`）并在超时内结束。成功可以返回 `None` 或 `{ "ok": true }`；失败应抛出异常、返回 `False`、`{ "ok": false }` 或失败状态。

`input_data.md` 是进入 Prompt 的小型摘要或资源索引，不是完整数据库。大型内容应保存在模块内部由实现自行选择的位置，再由 Markdown 写出按需读取路径；框架不会自动把这些文件内容塞进 Prompt。`data/` 和 `artifacts/` 只是常见名称，不是必需目录。

文件应原子写入。新模块在首次采集前保持 `input_health=异常` 且没有 `recent_update`；成功后模板采集器会写回健康状态，框架在隔离执行结束后再次确认，失败时标为 `异常` 且保留最近成功时间。模块可以在成功结果的 `resources` 中声明模块内文件，框架只保存受限资源索引，不复制内容或自动注入。

## `start_expand.py`

操控入口统一实现 `execute(command, params)`。它可以直接完成极小操作，也可以作为完整内部工程的薄适配层。主智能体通过 `expand_call` 调用，框架使用 stdin 向隔离子进程传递结构化参数；Shell 仅用于人工调试和旧模块兼容。

返回值可以携带任意 JSON 兼容的 `data`。大型 DOM、日志、图片、音视频和二进制内容必须保存为模块内文件，并通过 `artifacts` 数组返回路径；框架校验后发布到当前用户下载空间。操控结果直接属于本轮工具调用，不经过 `input_data.md`。同一模块的自动采集、Web 手动刷新和操控会被框架串行执行，等待时间计入调用超时。禁止把未实现操作报告为成功；涉及外部副作用时，应提供明确错误、权限要求和幂等边界。

## `expand_control.md`

`## 注入层` 只描述模块职责和使用条件，实时数据放在 `input_data.md`。框架不会替换 `{{变量}}`。`## 操作层` 列出命令、参数、返回值、失败格式和副作用，供智能体按需读取。

## `_last_run.json`

可选的最近运行记录，不参与模块发现，主要用于排查采集失败。
