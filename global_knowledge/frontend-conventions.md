# 前端约定与调试

本文记录 `web/frontend/` 的样式组织约定，以及在真实返工中确认有效的调试方法。手册只保留
「UI 调试先量再改」的入口，具体手法在这里。

## 样式组织

- 2026-10-10 起，Web 展示层完整移植本地 `E:\cache\front` 样例。应用入口只加载
  `src/reference/styles/index.css`，旧 `styles/prototype.css`、`styles/app.css` 不再进入主应用。
- 样例的 tokens/base/components/layout/chat/artifacts/pages 七份 CSS 保持原始设计；
  主题变量权威定义在 `src/reference/styles/tokens.css`，生产合同适配只写入
  `src/reference/styles/production.css`，不另建第二套主色、间距或明暗主题。
- 样例页面采用其原有全局语义类；安全 Markdown、内联组件、声明式模块面板等生产组件继续使用
  CSS Module（`*.module.css`），通过 `production.css` 的变量别名桥接到样例主题。
- 页面级语义别名（如 `--memory-brand: var(--brand)`）可以定义在某个页面容器的类上，
  供该页面内部复用。

## 变量链断裂：最常见也最难察觉的失效

**症状**：样式改了但页面上看不出任何变化，元素既没有背景也没有预期颜色，文字回退成继承色。

**根因模式**：声明引用了只在某个容器类上定义的别名变量，而**那个类从未挂到 DOM 上**。
此时 `var(--xxx)` 解析为空值，**整条声明失效**（不是回退到默认值，而是整条作废）：

```css
.memoryPage { --memory-brand: var(--brand); }      /* 定义了别名 */
.lifecycleInline { background: color-mix(... var(--memory-brand) ...); }
/* 若 <ModuleFrame> 没有 className={styles.memoryPage}，上面这条 background 整条消失 */
```

**排查顺序**：

1. 搜该页面/组件的类是否真的被使用：`styles.<容器类>` 在 TSX 中出现几次（0 次即命中本问题）。
2. 搜变量的定义处与引用处数量是否匹配。
3. 用全仓扫描确认变量名是否根本不存于任何定义（近似名混淆也常见，如
   `--ink` / `--text-muted` / `--orange` / `--surface-1` / `--shadow-lg` 这类"想用但没定义"的名字）。
4. 若容器组件支持 `className` 透传（如 `ModuleFrame`），补上挂载即可一次性恢复全部引用。

**预防**：变量只在确定会被渲染的容器上定义；新增别名后立刻检查该容器是否已在用。

## 布局调试：投影被父容器裁切

**症状**：卡片四周只有一圈**方形**的阴影（不是柔和扩散），圆角处也被切直。

**根因**：卡片与外层容器**尺寸齐边**，而外层设了 `overflow: hidden`。
`box-shadow` 向外扩散的部分（偏移 + 模糊半径）落到容器边界之外，被整条切掉。

**确认方法**：用 DevTools 的元素高亮（盒模型叠加层）看 —— margin 区（橙色）四角是**直角**
而 padding 区（绿色）是圆角，就说明阴影被外层裁了。或者量 `getBoundingClientRect()`，
卡片底边与外层容器底边坐标完全重合即为齐边。

**修法**：让内容区在该模式下 `overflow: visible`（条件类，不影响其他模式），
或给卡片留出大于阴影扩散距离的间距。不要用 `margin-bottom` 硬挤 —— 那只会压缩卡片高度。

**输入坞对话菜单**：样例 `.composer` 的 `overflow: hidden` 会裁掉其内部向上展开的
`.conversation-menu`，提高菜单 z-index 不能突破父层裁切。生产适配使用
`.composer.composer-inner { overflow: visible; }`；菜单锚定整条 `.composer-bar` 而非操作按钮，
避免窄屏或停止按钮出现时弹窗左缘被挤出视口。菜单按视口限制高度并内部滚动，
不要为保留圆角重新给这层容器加裁切。验收必须实际打开菜单，检查上/中/下部命中菜单且所有操作可滚动到达，
不能只检查关闭状态或 DOM 中存在 `role=menu`。

## 滚动条

- CSS Module 里定义 `::-webkit-scrollbar` 不一定生效；还要处理 `::-webkit-scrollbar-button`
  （浏览器默认箭头按钮）与 `scrollbar-gutter`，否则会出现多余的轨道条或箭头。
- 出现"多出来一条方框"先确认是不是滚动条，再动样式。

## 改前端样式后的验证

1. **构建**：`npm run build`（含 `tsc -b` 类型检查）。
2. **产物核对**：在 `dist/assets/*.css` 里搜改后的规则名，确认编译结果与预期一致
   （有些写法在构建后会被改写或与相邻规则合并）。
3. **计算样式**：页面刷新后读 `getComputedStyle()`，确认目标属性真的生效，而不是只看源码。
4. **测试**：`npm test`（vitest）。涉及文案或 role/aria 的 DOM 变更要同步断言。
5. 浏览器可能缓存旧壳，验证前先强制刷新。服务端对 SPA `index.html` / 路由回退固定返回
   `no-store, no-cache, must-revalidate`，避免新构建继续引用旧哈希 Chunk；`dist/assets/` 的哈希产物则
   返回一年 `immutable` 缓存，其他静态文件使用 `no-cache`。改变这组规则时同步测试响应头。

## 文案与 DOM 契约

- 测试可能断言具体文案、`role`、`aria-label`。移动元素位置通常不影响按 role 查询的断言，
  但**改文案或删元素会**。改前先搜测试。
- 展示层剥离标点、缩短文案时，同步更新对应断言。
- 历史日期浮层通过 Portal 挂在 `document.body`，测试应从 `screen` 查询，不能限定到抽屉 DOM 内，否则会误报日历不存在。

## 新建对话的路由交接

保存新建或清空新建时，自动恢复旧会话应持续暂停，直到新会话 ID 已提交到 URL；
不能在创建接口返回时提前解除 `sessionTransitioning`，否则本地状态更新可能抢先于路由提交，
导致旧活跃会话恢复逻辑覆盖新会话地址。切换其他页面期间仍按最新页面位置更新参数，不强制返回聊天页。

### 新建与保存新建的延迟边界

- 新建接口已持久预留空间并写入本标签页租约。仅当回执同时确认 `created=true`、匹配的
  `user/client_id`、`active_clients>0` 和 Web/open 会话时，前端复用这个短时确认，
  立即绑定新地址和读取正文，不串行再等一次初始化 lease。确认只消费一次、最多有效 15 秒；
  后续 15 秒心跳、页面恢复与既有会话验证仍走真实 lease。旧服务缺少这些字段时继续验证，
  不能因浏览器缓存存在而跳过 closed/deleted 裁决。
- 同一用户、同一源空间的并发新建复用一个 Promise 和一个 POST；旧请求结束不能清除其他
  用户/空间的新建锁。创建成功把服务端返回的会话补入已有列表，不伪造尚未读取的完整库存。
- 未绑定空间期间不读取 overview、聊天任务与欢迎 Token 聚合；新 URL 自行读取新 overview，
  不再额外刷新旧/无绑定空间的概览。首次任务读取在计划列表为空时不重复失效已同时加载的正文；
  存在计划时仍重新核对正文，避免首屏加载期间任务刚完成却漏掉结果。后续任务轮询与运行提交仍刷新正文。
- 保存新建仍严格“关闭旧空间（持久登记后台记忆/摘要）→创建新空间”，不并行投机创建；
  同步防连点。新建成功才清理原草稿，失败保留草稿且不隐式恢复已关闭空间。
- 会话列表、正文、overview 和任务总览的同步服务调用在工作线程执行，避免较慢的磁盘读取
  或上下文计算阻塞 ASGI 事件循环，挤压新建/关闭请求。归档元数据和索引单行优化见
  `storage-and-persistence.md`；不通过降低 SQLite 持久化或省略保存来换取速度。

## 导航与最近会话恢复

- 所有业务导航携带当前 `user + session`，根路由与未知路由回跳聊天页时保留查询参数。
  首轮发送前必须通过会话接口预留并绑定空间，不能等任务终态再填写 URL；切页期间 Run 注册表、
  SSE 控制器、文本草稿和附件仍由 AppShell 与草稿 store 持有，不随聊天页面卸载而清除。
- `sessionNavigation.ts` 只缓存每用户最近空间的 ID：sessionStorage 保存本标签页身份，
  localStorage 保存前台最近访问身份。后台心跳不能抢占其他页面的最近空间。
  显式 URL 优先，其次本标签页、浏览器最近空间，最后既有后端 active-session 合同。
  缓存恢复前调用 lease 验证；404 清除对应缓存后回退，断网或 5xx 保留身份等待重试。
  不调用 reopen，也不复活 closed/deleted 记录；显式失效 URL 仍解除绑定并提示，不自动新建替代空间。
- 会话正文读取不依赖其是否在历史索引第一页；成功验证的会话可直接按 ID 分页读取正文。
  恢复刚预留的空会话同样绑定 URL 并刷新历史索引，避免缓存列表落后时一直停留无会话状态。
- 配置页重启后等待原端口健康检查成功，再整页加载 `/chat?user=...&session=...`。
  最多等待 60 秒，失败保留身份供重试；离开配置页取消等待，迟到健康响应不能改变当前页面。

## 知识库编辑与预览

- 业务文档统一使用 `src/components/DocumentMarkdown.tsx`，直接复用知识库放大预览的
  `.prose` 排版与 `MarkdownMessage` 安全渲染能力；reference 页通过 `mountMarkdown` 桥接。
  知识、记忆、技能/插件、子智能体、感知/拓展的采集与注入文档、模块面板 Markdown 状态字段、
  任务说明/执行内容/结果、人格与文件空间的 Markdown 预览都使用同一入口。
  标题、段落、列表、引用、表格、公式与可复制代码块保持一致，遵循现有黑白主题与界面字号。
  业务容器继续决定预览高度和内部滚动，编辑器保留原文及拖动行为。
  数据注入、运行上下文和任务结果预览保持只读，文档动作不会自动执行任务；
  结构化任务结果和计划快照作为 JSON 代码块渲染，日志和非 Markdown 文件仍展示原始文本。

- 知识文件使用样例的“预览 / 编辑”分段按钮；全局层仍显示分段控件，但编辑按钮禁用，
  并明确提示界面只读，保存和删除同样禁用。
- “放大预览”始终渲染当前 `draft`，包括尚未保存的编辑内容；由
  `src/reference/shared.js` 的 `Overlay.modal` 挂载到 `document.body`，避免被右侧编辑容器的高度和
  `overflow` 裁切。正文仍桥接生产安全 Markdown 组件；对话框支持关闭按钮、背景点击与
  `Escape` 关闭、键盘焦点循环及关闭后焦点恢复。
- 知识详情的预览和编辑内容区共用默认最低高度，以原预览面板的
  `100dvh - 120px` 上限扣除实际标题、工具栏、留白和底栏后确定；字号与视口变化同步重新计算。
  正文超出时在内容区内滚动；编辑框允许纵向拖动放大及回缩，但不能小于此底线。
  仅知识详情取消通用编辑面板的高度上限，确保拖动后面板随内容增长，保存栏仍在编辑框下方。

## 记忆详情

普通权重说明统一使用“不同日期出现次数”（上海自然日）；不新增碎片级轨迹或过期归档网页入口。
自动生成技能的 `memory_lifecycle` 在技能列表与详情展示 active/stale 和简要来源；
stale 显示“来源已失效 · 待复核”、不再自动注入，保留现有编辑/人工删除入口。

- 普通记忆列表卡片间保留 6px 间隔；详情预览使用与编辑框相同的边框、宽度和 260px 默认高度，
  内容在框内滚动，编辑框仍可纵向拉伸。详情不展示“权重规则”说明卡。
- 临时重要记忆分栏采用两列布局：左侧分栏，右侧单个只读详情，直接展示正文预览以及路径、
  大小、上海时区更新时间、后端 `lifecycle.status/reason/prompt_eligible` 的简要状态。
  不展示第二个空详情、编辑入口、保存或删除按钮。切换分栏后手动刷新仍保留该分栏。
- 普通四层的读取和删除携带 `tier + filename`，保存通过既有 `PUT /memory/item` 携带
  `content + tier`，新建长期记忆显式写 `permanent`。普通时间按 UTC 显示，临时重要时间按
  Asia/Shanghai 显示；恢复读取更新正文及元数据，并防止迟到响应覆盖另一条已选记忆。

## 子智能体详情与列表

- 子智能体列表复用知识库的分页控件，每页最多六条；搜索或切换来源层级回到第一页，
  详情随当前页选择同步，空筛选不保留上一条的删除操作。
- 右侧详情宽度由原 340px 扩大三分之一，即 `340px × 4 / 3`；仅作用于子智能体页面。
  描述、触发文档和配置与规则均通过生产安全 Markdown 组件渲染，不展示文件清单。
- 工具与技能页同样使用左右两列，右侧预览与子智能体详情共用宽度；插件及各类 Prompt 技能
  均每页最多六条，复用相同分页控件。搜索与分类切换回到首页，详情随当前页同步；
  技能正文仍按需读取原接口，迟到的旧选择响应不能覆盖新选择正文，编辑和保存权限保持后端合同。
- 基础插件、共享技能、智能体生成及用户自建技能全部通过
  `GET /api/users/{user}/skills/{category}/document?name=...` 读取完整 SKILL.md；
  不用目录摘要替代插件正文。预览通过安全 Markdown 渲染到气泡容器，长文在容器内滚动，
  不截断文档。详情不再展示“管理权限”说明卡；读取中或失败时禁止编辑与保存，失败提供重新读取。

## 感知详情与注入预览

- 感知及拓展模块卡片位于左半区，注入总览及模块详情共用右半区；感知通过“全局注入 / 模块详情”切换，
  不再展示注册说明折叠卡。总览渲染 `injection.content` 全文，不使用截断的 `preview`。
- 两页复用记忆、子智能体和工具与技能的 `makePager`，每页最多六个模块；拓展按当前层级独立分页，
  切换层级回首页，翻页把详情选中项同步到当前页。重新读取和保存保留页码、模块及标签，
  库存减少时钳制页码并改选当前页第一项；空层级回到注入总览并禁用模块详情。
- 模块详情保留状态摘要，并用“注入数据 / 用户操作”两个小标签切换内容。
  数据页并排展示 `collected_markdown` 与 `injected_markdown`，均通过生产安全 Markdown 渲染，
  各自有复制按钮和内部滚动。无注入时显示空态，不用采集正文替代实际注入片段。
- 用户操作页提供原白名单、刷新采集和删除确认，同时按需挂载生产 `ModulePanel`。
  刷新采集位于详情标签栏最右侧，白名单右侧只保留 36px 高的删除按钮。
  感知宿主将 h1/h2 配置及状态卡片高度固定为 13rem/26rem（原上限的两倍），
  操作卡片正文与注入预览共用 400px 高度并内部滚动；拓展用户操作宿主复用相同尺寸。
  配置保存继续走既有 panel PUT 与 refresh POST，不新增感知 action 接口。
  页面重新读取、白名单保存及刷新后保留当前模块和详情标签；更新时间优先使用接口 `recent_update`。
- 拓展通过“注入总览 / 模块详情”切换，总览只读展示全部三层实际数据注入；模块详情有“数据注入 / 操作文档 / 用户配置”。
  数据页与感知共用采集和实际数据注入并排预览，操作文档分别安全渲染完整 `control_document`、
  `control_injection_markdown` 和 `control_operation_markdown`，保留全文、复制及内部滚动。
  刷新采集位于详情标签栏右端。全局和共享层开关调用当前用户白名单接口，用户层始终可用，
  开关禁用且只在该层提供带确认的删除按钮；无效模块也不能修改白名单。
  用户操作仍调用原 panel GET/PUT/action、refresh POST 和用户层 DELETE，不新增接口。
  只读预览不提供组件填入或发送动作。“增加到用户层”跳转同一用户会话的聊天页，
  仅填入“创建一个新的用户拓展，扩展要求为：”，不自动发送。
  分类字段优先使用 `data_injected_markdown` 与 `injection.data_content`，由真实注入范围裁剪，
  不把操控能力说明放进数据预览。旧服务兼容仅识别框架固定数据前缀并逐字核对采集正文，
  不按采集数据内的同名 Markdown 标题切段，也不以未注入的采集正文补全预览。

## 正文内联组件

- 聊天正文组件只通过 `kemo-widget` 声明渲染；内置类型走 `InlineWidget` 专用组件，未知声明式名称走
  通用数据卡。开放名称兼容不代表执行任意 HTML、JSX、脚本、样式文本或远程 iframe。
- 流式渲染必须先确认 fence 闭合。不能只依赖 `streaming=false`，因为失败重试快照也会把半截正文
  收口为静态消息；未闭合组件应显示占位或未完成状态，不显示原始 JSON。
- 新组件必须使用主题变量和 CSS Module，支持暗色主题、窄屏、键盘焦点与文本/表格替代；Tooltip
  不能是读取数据的唯一途径。
- 表格排序、筛选、分页、列显隐，标签页、折叠、轮播等状态只保存在组件本地，不另建持久化表。
- 历史归档抽屉对输入会话做防御性时间倒序，避免 mock、缓存合并或旧接口返回乱序；搜索框下方的日期入口以内联
  42 格月历展开，周一为每周起点，提供上月/下月、清除和今天，并禁用上海自然日之后的未来日期。选中日期后使用

## 当前对话文件历史（2026-10-11）

- 聊天顶栏的文件历史入口只在已提交会话显示，打开时通过既有
  `GET /api/users/{user}/sessions/{session}/history?source=web` 读取该用户、该会话的完整历史；
  不读取文件空间总目录，也不根据路径猜测其他会话附件。
- “来源”来自当前会话消息附件、引导附件和当前会话运行态/待发送队列；“输出内容”来自当前会话
  `round_metrics.artifacts` 与工具 trace artifacts。按 asset/checksum/path 去重，切换用户或会话时
  query key 必须同时切换。
- 图片使用现有缩略图端点，普通文件使用类型缩略图；可下载项仍受原有 `available`、scope 和
  artifact URL 合同限制。浮层使用 portal，受视口限制，支持外点、Escape、重试和运行结束后的刷新。
