# 原理：记忆升级权重

对应源码：

- `E:\code\kemo-agent\run\memory.py`（核心引擎）
- `E:\code\kemo-agent\run\memory_pipeline.py`（提取管线）
- `E:\code\kemo-agent\run\memory_migrate.py`（v1→当前迁移）
- `E:\code\kemo-agent\run\engine.py`（调用入口）

## 架构演进：v3 文件型存储

### v1（已废弃）

- 全部条目合并 JSON 数组存入 `data.json`
- UUID 作为条目 ID
- 每条内存携带 keywords, entities, source, confidence, importance, status 等冗余字段
- `MemorySelection` 负责检索 + 截断

### v2

- 每条记忆为独立 `.md` 文件，文件名是全局唯一标识
- 临时三层的 `data.json` 降级为轻量索引
- 永久层彻底无索引，纯 `.md` 文件
- 搜索仅按文件名匹配
- 去掉 `MemorySelection`，改为 `MemoryLocation(tier, filename, path, indexed)`

### v3（当前，2026-07-23）

- 索引字段扩展为：weight, created_at, content_updated_at, updated_at(别名), last_used_at, last_weight_date, tier_entered_at, expires_at
- `updated_at` 不再记录引用时间，仅是 `content_updated_at` 的兼容别名
- `last_used_at` 独立记录引用时间
- `local_day()` 统一使用 `Asia/Shanghai` 时区
- 注入排序去除 updated_at 次要排序，仅按 weight 降序 + 文件名稳定排序
- 新增 `extraction_mode` 四模式控制提取时机
- v2 索引读取时自动补全 v3 字段并就地升级

## 存储布局

```
users/<user>/improve/
├── storage.json                        # v2 标志 {schema_version: 2}
├── seven_days/
│   ├── data.json                       # 索引（schema_version, files 对象）
│   ├── 某记忆文件.md
│   └── ...
├── one_month/  (同上)
├── half_year/   (同上)
└── permanent/
    ├── 永久记忆.md                     # 无 data.json
    └── ...
```

## 权重规则

- 不进行每日权重衰减，权重无上限。
- 临时记忆正文被修改（`upsert_candidates` 内容更新）或被 Prompt 实际引用（`mark_used`）后可加权。
- 引用只有在 Provider/工具循环和正式历史提交成功后成立；失败或取消不加权。
- 修改与引用共用 `last_weight_date`，同一记忆在同一用户本地自然日合计最多 +1。
- 实际修改更新 `content_updated_at`；引用更新 `last_used_at`，不得覆盖内容时间；`updated_at` 仅是内容更新时间的兼容别名。
- `last_weight_date` 显式按 `Asia/Shanghai` 计算，绝对时间统一保存为 UTC ISO 8601。
- 进入新档位后 weight 归零，重新计算该档位的固定到期时间。
- 永久记忆不记录权重，也不参与 `mark_used`。

## 档位审核

| 当前档位 | 固定持续时间 | 晋升阈值 | 下一档位 |
|---|---:|---:|---|
| `seven_days` | 7 天 | 3 | `one_month` |
| `one_month` | 30 天 | 10 | `half_year` |
| `half_year` | 180 天 | 60 | `permanent` |
| `permanent` | 无到期 | 无 | 无 |

到达 `expires_at` 后：
- 权重达到阈值：`_promote_location()` 原子操作 → 移动 `.md` 文件到下一层，设置新层到期时间。
- 权重未达到阈值：`_delete_location()` → 删除 `.md` 文件和索引项。

## Prompt 注入顺序

```
permanent_memory      → 全部注入，文件名自然排序
important_memory      → memory_temporary_important.md 独立文件，受字符上限控制
temporary_memory:half_year    → 按 weight 降序、文件名自然稳定排序，最多 3 条
temporary_memory:one_month    → 最多 4 条
temporary_memory:seven_days   → 最多 3 条
```

## 迁移脚本

`run/memory_migrate.py` 提供一次性 v1→当前 schema 迁移：
- 读取旧 JSON 数组 → 按文件名规范化 → 写入 `.md` + 索引
- v2 索引读取时自动补全 v3 字段并就地升级
- 全文搜索旧数据中的文件名冲突
- 支持 dry-run 预览和自动备份
- 迁移后自动完整性校验

## 提取模式（2026-07-23 新增）

`memory.extraction_mode` 控制记忆提取时机，替代旧的 `auto_extract_on_commit` 布尔值：

| 模式 | 说明 | memory_status |
|------|------|----------------|
| `compression_only`（默认） | 提交只登记游标，保存或压缩时才顺序提取 | `deferred` |
| `background` | Maintenance 领取普通轮次 | `pending` |
| `on_commit` | 提交后同步提取 | `processing` |
| `disabled` | 不提取 | `disabled` |

所有保存与压缩入口共用连续 `memory_processed_round` 游标。`context_manage` 只负责摘要，不重复持久化同一轮记忆。
