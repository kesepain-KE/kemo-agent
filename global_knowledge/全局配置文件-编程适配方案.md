## tools — 工具调用控制

```json
  "tools": {
    "enabled": true,
```
- **含义**：是否允许 AI 调用工具（function calling）
- **源码影响**：控制 ToolRunner 是否注册和执行工具
- **false 时**：AI 只能纯文本回复，无法调用任何工具

```json
    "timeout": 240,
```
- **含义**：每个工具的单次超时秒数。超时后该次调用标记失败
- **源码影响**：`tool_timeout` 配置值，传递给 ToolRunner 中每个工具的执行超时
- **与 `consecutive_tool_fail_limit` 的关系**：超时计入一次失败计数

```json
    "max_iterations": 8,
```
- **含义**：单轮对话中最大工具调用迭代次数。达到后终止本轮工具调用，返回已有结果
- **源码影响**：ToolRunner 循环上限，防止 LLM 陷入无限工具调用循环

```json
    "max_per_round": null
```
- **含义**：单轮对话最大工具调用次数。超过此数后 AI 不能直接继续调用，需用户手动点击"继续"按钮
- **`null` = 不限制**
- **源码影响**：在 ToolRunner 循环中增加计数检查，达到上限时暂停并返回前端等待用户确认的信号
- **与 `max_iterations` 的区别**：`max_iterations` 是硬上限（到数自动停），`max_per_round` 是软上限（到数等用户确认后可继续）

```json
  },
```

## history — 对话历史

```json
  "history": {
    "schema_version": 1,
```
- **含义**：历史存储结构版本号，用于向后兼容

```json
    "recent_full_rounds": 3,
```
- **含义**：最近 N 轮对话完整保留，不做任何压缩或摘要
- **源码影响**：历史压缩逻辑中，保留最近 N 轮的完整消息，只对更早的轮次做摘要/截断

```json
    "consecutive_tool_fail_limit": 5
```
- **含义**：同一工具连续失败达到此数，提示 AI 换思路，不再重复尝试该工具
- **源码影响**：ToolRunner 中维护每个工具的连续失败计数，达到阈值时将工具标记为"暂时不可用"或向 LLM 返回特殊提示
- **不重置场景**：换了一个不同工具后又切回来，计数是否重置取决于实现策略（建议同工具连续失败才累计，中间穿插其他工具则重置计数）

```json
  },
```

## memory — 记忆系统

```json
  "memory": {
    "storage_schema_version": 2,
```
- **含义**：记忆存储结构版本号

```json
    "temporary_injection_limits": {
      "half_year": 300,
      "one_month": 200,
      "seven_days": 100
    },
```
- **含义**：各临时记忆档位单次 Prompt 最多注入的条数
- **源码影响**：记忆检索/注入模块在组装 prompt 时，从各档位最多读取 N 条
- **注意**：只限制注入数量，不限制磁盘存储量

```json
    "important_memory_max_chars": 2000,
```
- **含义**：重要记忆单条最大字符数

```json
    "history_read_enabled": true,
```
- **含义**：是否允许智能体调用**查询历史对话的专用工具**
- **`true`** 时：智能体可以主动检索过往对话记录
- **`false`** 时：该工具不可用，智能体无法查看历史对话
- **源码影响**：控制一个特定工具的注册/禁用，这个工具用于按关键词或时间范围搜索用户的对话历史

```json
    "tiers": {
```
- **含义**：记忆晋升层级定义

```json
      "seven_days": {
        "days": 7,
        "upgrade_threshold": 3,
        "next": "one_month"
      },
```
- **7 天档**：有效期 7 天，权重 ≥ 3 晋升到 `one_month`，到期未达标删除

```json
      "one_month": {
        "days": 30,
        "upgrade_threshold": 10,
        "next": "half_year"
      },
```
- **30 天档**：有效期 30 天，权重 ≥ 10 晋升到 `half_year`

```json
      "half_year": {
        "days": 180,
        "upgrade_threshold": 60,
        "next": null
      }
```
- **180 天档**：有效期 180 天，权重 ≥ 60 晋升到永久记忆（`next: null` 但后台机制自动处理晋升到 permanent）
- **`next: null`** 在此配置中不声明目标层级，实际晋升由代码内部逻辑处理

```json
    }
  },
```

**晋升规则（需在代码中实现/维持）：**
- 每条记忆每自然日最多加权 1 次（修改和引用共用锁）
- 只在实际注入上下文的引用才计数
- 到期未达阈值 → 直接删除，不降级保留
- 永久层由代码内部维护，不在此配置中声明

## agents — 智能体运行时策略

```json
  "agents": {
    "conserved_rounds": 3,
```
- **含义**：触发工具调用压缩前保留的最近完整轮次数
- **源码影响**：历史压缩逻辑中，最近 N 轮的 tool_call 记录完整保留

```json
    "max_rounds": 80,
```
- **含义**：单次对话最大轮次数（用户消息 + AI 回复算一轮）
- **达到上限后**：触发上下文压缩或强制摘要

```json
    "rounds_after_compression": 20,
```
- **含义**：触发压缩后保留的轮次数
- **源码影响**：压缩后历史保留最近 20 轮完整内容，更早的轮次做摘要或丢弃

```json
    "token_limit": 1000000,
```
- **含义**：Token 总量上限，达到此值时触发上下文压缩
- **源码影响**：每次消息处理后统计当前上下文的 Token 总数，超过 `token_limit` 触发压缩策略

```json
    "token_compression_ratio": 0.3,
```
- **含义**：触发压缩时，将 Token 总量压缩到原来的 30%
- **示例**：当前 100 万 Token → 压缩到 30 万 Token
- **源码影响**：压缩策略的目标值，决定需要删除/摘要多少历史内容

```json
    "important_memory_review_hours": 3,
```
- **含义**：重要记忆的审阅间隔（小时）
- **源码影响**：后台任务每 N 小时检查一次重要记忆，判断是否需要更新/降级/删除

```json
    "daily_memory_review_time": "02:00"
```
- **含义**：每日记忆审核的触发时间（北京时间）
- **源码影响**：每日固定时间执行全量记忆审计，检查所有档位的到期情况和晋升条件

```json
  }
```

## 编程智能体需要实现的要点清单

### 1. 新增字段：`tools.max_per_round`

- **位置**：ToolRunner 循环中
- **行为**：达到 `max_per_round` 后暂停工具调用，向前端返回"等待用户确认继续"的信号
- **`null`** 时跳过检查

### 2. 重命名字段：`history.older_tool_log_max_chars` → `consecutive_tool_fail_limit`

- **语义变更**：从"旧工具日志截断字符数"变为"同一工具连续失败阈值"
- **需要**：确认源码中是否还有读取旧字段名的地方，一并更新

### 3. 重命名字段：`memory.extraction_enabled` → `history_read_enabled`

- **语义变更**：从"是否提取记忆候选"变为"是否允许读取历史对话"
- **需要**：关联的代码逻辑从"记忆提取"改为"历史对话查询工具的注册控制"

### 4. 重命名 agents 字段（去除 n1-n7 序号前缀）

| 旧名 | 新名 |
|------|------|
| `n1_recent_rounds_before_tool_compression` | `conserved_rounds` |
| `n2_max_rounds` | `max_rounds` |
| `n3_rounds_after_compression` | `rounds_after_compression` |
| `n4_token_limit` | `token_limit` |
| `n5_token_compression_ratio` | `token_compression_ratio` |
| `n6_important_memory_review_hours` | `important_memory_review_hours` |
| `n7_daily_memory_review_time` | `daily_memory_review_time` |

### 5. 后台调度器扩展：`runtime_host.enable_background_scheduler`

- 当前源码可能只关联 cron。需要扩展为**统一后台调度器**，同时管理：
  - cron 定时任务（现有）
  - 临时记忆处理（到期检查、晋升、删除）
  - 上下文整理
  - 记忆审阅
  - 其他周期性维护任务

### 6. `memory.tiers.permanent` 从配置中移除

- 永久记忆层级不再在配置中声明
- 代码需要内部处理 `half_year.next → permanent` 的晋升逻辑，不依赖配置中的 `permanent` 条目

### 7. `memory.tiers.half_year.next` 值为 `null`

- 代码在读取 `next` 为 `null` 时，应理解为"晋升到永久记忆"，而不是"无晋升目标"

### 8. 移除的配置项对应源码清理

| 移除项 | 源码中需要检查/清理 |
|--------|-------------------|
| `provider` 所有字段 | 确认全局 provider 不再作为兜底，只从 user_config 读取 |
| `knowledge` 所有字段 | 全局知识库检索参数完全移除，相关默认值逻辑删除 |
| `skills` / `expand` / `perception` 白名单 | 全局白名单限制逻辑移除 |
| `agent_models` | 子智能体模型配置移除，统一继承主模型 |
| `web.host/port/log_level` | 确认从 `.env` 读取 `WEB_HOST`/`WEB_PORT` |
| `prompt.include_*` 四个开关 | 人格/手册/记忆注入开关移除，默认全部启用 |
| `cron.auto_start` | 移除，默认启动 |
| `runtime_host.shutdown_timeout` | 移除 |
| `message.dedupe_max_entries` | 移除（上下文管理已有去重） |
| `message.bindings` / `transports` | 移除，确认从 `message_config.json` 读取 |
| `agents.n8_task_plan_max_steps` | 移除（与 `task_plan.max_steps` 冗余） |
