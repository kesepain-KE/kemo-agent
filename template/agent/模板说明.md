# 子代理模板说明

将本目录复制到 `agents/<name>/` 或 `users/<name>/agents/<name>/` 后，按以下规则修改各文件即可创建子代理。

## agent.json — 基本信息

| 字段 | 说明 | 必须修改 |
|------|------|----------|
| `name` | 子代理唯一标识，如 `memory_manage`。决定目录名和调用名 | ✅ |
| `version` | 语义版本号 | 可选 |
| `description` | 子代理职责描述，注入系统提示词 | ✅ |
| `trigger` | 始终指向 `trigger.md` | 不改 |

## agent-config.json — 运行配置

| 字段 | 说明 | 必须修改 |
|------|------|----------|
| `internal_mode` | `true`=仅内部调用；`false`=可被外界调用 | 按需 |
| `allowed_callers` | 允许的调用方列表，如 `["main_agent", "engine"]` | ✅ |
| `tools.plugins.allow` | 允许使用的插件列表，如 `["memory_manage"]` | ✅ |
| `tools.shared_skills.allow` | 允许使用的技能列表 | 按需 |
| `tools.max_iterations` | 单次调用最大工具调用次数，默认 20 | 可选 |
| `global_knowledge` | 是否注入全局知识库索引 | 按需 |
| `shared_knowledge` | 是否注入共享知识库索引 | 按需 |
| `inherit_main_history` | 是否继承主智能体对话历史 | 按需 |

## AGENT.md — 运行手册

注入子代理系统提示词的核心文件。需按实际职责完整改写"核心职责""输入来源""执行流程""输出格式"四部分。

## trigger.md — 注册与调用

分两部分：
- **注册信息**：名称、触发条件、职责、模型（cheap/default/reasoning）、工具列表
- **操作信息**：调用方式、调用场景、输入输出格式、注意事项

`main_agent` 读到注册信息决定何时调用；读到操作信息知道如何调用。

## executor.py — 执行入口

`execute(context, input_data)` 是框架调用的唯一入口。模板已包含 trigger 校验骨架，只需：
1. 修改 `VALID_TRIGGERS` 为实际触发值
2. 在 `context.run_model(input_data)` 前后插入预处理/后处理逻辑
3. 如需调用子代理，使用 `context.runner`
