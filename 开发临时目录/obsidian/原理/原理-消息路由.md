# 原理：智能体消息路由

对应源码：

- `E:\code\kemo-agent\message\router.py`
- `E:\code\kemo-agent\message\identity.py`
- `E:\code\kemo-agent\message\transport.py`
- `E:\code\kemo-agent\message\plugin.py`
- `E:\code\kemo-agent\message\state.py`
- `E:\code\kemo-agent\run\runtime_host.py`

## 当前状态

消息路由支持两条路径：

### 路径一：传统 Transport

```
Transport 收到平台消息
→ MessageEnvelope
→ IdentityResolver 映射内部用户
→ ProcessedMessageStore.claim（单键幂等）
→ MessageRouter → iter_request_events
→ OutboundMessage.reply → Transport.send
```

### 路径二：文件夹插件

```
message/out/<platform>/input.py 收到平台消息
→ 写入 message.md / files/
→ FileMessageTransport 领取并解析队列
→ MessageEnvelope
→ message.json.bound_user 绑定内部用户（不经 IdentityResolver）
→ ProcessedMessageStore.claim_many（多键幂等）
→ MessageRouter.request_payload()（附件→Kemo Content Blocks）
→ iter_request_events
→ OutboundMessage → output.py.send
→ FileMessageTransport.finalize()（写日志、清理附件、释放领取文件）
```

## 关键设计

### 身份绑定

- 传统 Transport：`config/message_config.json` 的 `bindings` 数组，逐条匹配外部身份
- 文件夹插件：`message.json.bound_user` 整体绑定到内部用户，跳过 IdentityResolver

### 消息合并

- 群聊：同一 `external_chat_id` 的多条消息合并为一个 MessageEnvelope
- 私聊：逐条处理
- 幂等：合批时 `claim_many` 批量领取所有原始消息 ID

### 附件路由

- 图片/音频/PDF → `inline_base64` Kemo Content Blocks
- 文本 → 直接读取拼入 prompt
- 视频/未知 → 仅注入文件说明

### finalize 钩子

RouteResult 进入终态后，RuntimeHost 调用 Transport 的 `finalize()`（如存在）。FileMessageTransport 用此钩子完成：
- 写按日 Markdown 日志
- 删除已处理附件
- 释放领取文件
