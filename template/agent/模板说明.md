# 子代理模板说明

本目录只展示子代理可发现的最小包合同，不是固定工程结构。可复制到 `agents/<name>/` 或 `users/<user>/agents/<name>/`，也可以在创建器建立用户代理后继续完善。

## 框架合同

- `agent.json`：名称、版本、描述和 `trigger.md` 路径。
- `agent-config.json`：公开范围、调用方、插件/共享技能白名单、循环上限、知识和历史权限。
- `AGENT.md`：子代理 Prompt 指令。
- `trigger.md`：必须包含“注册信息”和“操作信息”，用于发现与按需调用说明。
- `schema.json`：可选，声明输入输出 JSON Schema。
- `executor.py`：可选；不存在时使用内置 LLM 执行器，存在时由框架调用 `execute(context, input_data)`。

## 模块目录内部自由

子代理目录可以包含任意文件、任意层级 Python 包、资源、配置、测试或完整工程。复杂实现应让根 `executor.py` 保持为协议适配器，再导入内部工程；简单代理可以完全不提供自定义执行器。框架不会因为模板未列出额外文件而拒绝它们，也不会自动加载未被入口导入或合同引用的内容。

自定义执行器会被主进程直接导入，没有代码沙箱，只能使用可信代码。不得在导入阶段产生副作用；运行中必须遵循已授予工具权限、写入边界、取消信号和整体超时。

## 修改原则

按真实职责重写模板占位内容，不需要保留示例章节或 `VALID_TRIGGERS` 结构。只有最终清单、Prompt、触发说明、可选 Schema 和执行入口合同必须正确。创建器只建立数据型最小包；完整实现可在创建后使用正常文件或代码工具迁入代理目录。

## 统一验收

创建完成后，从仓库根目录运行：

```powershell
python -m tests.template_tests.agent --target users/<user>/agents/<name>
```

验收只锁定上述公开合同，不会因内部新增文件或嵌套工程而失败。稳定标准见
`tests/template_tests/agent/STANDARD.md`。
