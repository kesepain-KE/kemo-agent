# 存储与持久化功能说明

本文集中说明历史、记忆、运行状态、结构化日志和高频写盘的当前持久化规则。各章节保持独立职责，代码和数据库实现是事实来源。

## SQLite 初始化、迁移与恢复安全

CardStream、tasks、logs、memory 共用 `run/infra/sqlite_migrations.py` 的事务与备份基础设施。

| 数据库 | 版本权威 | 当前 schema |
|---|---|---|
| `users/<user>/cards.sqlite3` | `PRAGMA user_version` | 5 |
| `users/<user>/task_plan/task_plans.sqlite3` | `task_plan_meta.schema_version` | 1 |
| `runtime/logs.sqlite3` | `PRAGMA user_version` | 3 |
| `users/<user>/improve/memory.sqlite3` | `memory_meta.schema_version` | 4 |

初始化持有 `BEGIN IMMEDIATE` 后复查版本；未来、负数、非法版本明确拒绝。已存在且需要迁移的
数据库先用独立只读连接执行 SQLite backup，含已提交 WAL；备份失败阻止任何 schema 修改。
备份名为 `<数据库文件名>.bak.v<原版本>.<UTC时间戳>-<唯一标识>`，未完成文件保留 `.partial`。
DDL 与版本戳同事务提交，失败整体回滚。当前 CardStream schema 不完整时拒绝猜测修复。
迁移与更新备份不自动清理，恢复须核对代码版本和数据库版本。

CardStream 使用独立 schema，完全不读取、迁移、覆写或删除用户已有 history/window 文件。
读取无历史用户的列表和状态，不为其建立空数据库。在线备份使用 SQLite backup API，离线复制
应先完整停止写入并保留 WAL/SHM。

### 手工恢复单库

源码回滚不会自动回滚用户数据库。恢复前先停止 Web、CLI、Cron 等全部写入进程，
保留当前库及其 `-wal/-shm` 作为现场；依据 `manifest.json` 或错误提示选定备份，
核实安装根和用户，再恢复。不要让旧进程继续持有被恢复的数据库连接。
下面是需由操作者替换路径、审查后执行的单库示例，不是自动恢复入口：

```powershell
$backup = 'E:\选定的备份目录\users\alice\cards.sqlite3'
$target = 'D:\实际安装根\users\alice\cards.sqlite3'
python -c "import sqlite3,sys; from pathlib import Path; from contextlib import closing; b=Path(sys.argv[1]).resolve(); t=Path(sys.argv[2]).resolve(); assert b!=t and b.is_file() and t.is_file(); s=sqlite3.connect(b.as_uri()+'?mode=ro',uri=True); d=sqlite3.connect(t); s.backup(d); d.close(); s.close()" "$backup" "$target"
```

恢复全部库时逐项核对同一备份集，不拼接不同更新批次。恢复后先验证库的完整性与适配代码
版本；不要只降级代码后直接运行更高版本库。

## 业务智能体任务账本

`users/<user>/runtime/agent_tasks.sqlite3` 独立保存业务父子任务归属、真实执行终态、
待处理结果／处理确认以及最近 160 条公开事件。它不替代会话历史、系统维护队列或任务计划库。
入队前登记与完成封口的事务屏障、调度器快照顺序、进程存活核验／interrupted、
脱敏及有界查询合同见 `agent-task-coordination.md`。

## CardStream 历史与执行存储

每用户的 `users/<user>/cards.sqlite3` 是当前历史事实来源。启用 WAL、外键、
`synchronous=NORMAL`。旧 `history/history.sqlite3` 与 JSON window 文件保持原样，当前引擎
不读取它们，也不通过兼容层双写。

| 表 | 职责 |
|---|---|
| `context_cards` | 同行保存不可变 RAW、可变 VIEW、Token、版本及摘要吸收关系 |
| `card_sessions` | source/session 身份、代际、生命周期、last_seq、view_epoch、有效 Token 与维护游标 |
| `card_integrations` | 整合状态、请求在途、已确认序号、继续推理要求及终态元数据 |
| `card_tool_executions` | execution_id、原始调用快照、真实执行存活状态与结果关联 |
| `card_bindings` | Web/App/CLI/外部消息的活跃会话指向 |
| `card_leases` | 按会话/页面或设备隔离的在线序号、释放状态和到期时间 |
| `card_meter_observations` | 请求快照关联的估算/实际 usage 校准，不存正文或凭据 |
| `message_processed_messages` | 外部消息领取、终态及跨重启幂等 |

### RAW 与 VIEW 一致性

RAW 事件仅允许追加，数据库触发器拒绝更新和删除。用户正文与引导、助手 interim/final、
工具调用和结果都属于历史卡片。工具调用与结果用不同 seq 写入，通过 tool_call_id 与
execution_id 关联；结果重复携带完整 original_call，可独立理解。

压缩只操作 VIEW。新摘要寄存在最旧前缀的首张 RAW 所在行，失活其余吸收卡片；所有修改、
摘要唯一性、view_revision/view_epoch 与有效 Token 更新同事务提交。先生成并校验候选再提交，
任何错误整体保留旧视图。内存和数据库重叠时按 card_id 选最新 view_revision，仅计量一次。
请求屏障使用事务快照，冻结历史、动态状态、Schema 和计量后才发起 Provider 请求。

进入编辑或取消编辑只操作网页草稿，保留原对话，不调用历史撤回；确认发送后才执行撤回。
编辑重发只检查最新未撤回整合自身的压缩状态。压缩后追加、尚未被摘要吸收的整合可以撤回：
仅失活该轮 VIEW 并扣除对应有效 Token，保留已有摘要和全部 RAW。
目标轮的任一卡片已作为摘要宿主或被摘要吸收时，拒绝单独撤回，避免摘要继续携带被撤回内容；
即使该轮仍有未压缩的后半段，也遵守此边界。判断与撤回保持同一写事务，原有空闲状态、
整合计数和原始输入匹配校验继续生效，不因会话里存在其他轮次的摘要而一律拒绝。

### 查询、检索与界面投影

Web 历史、历史搜索和维护分析读取 RAW。网页按 integration_id 关联正文、工具轨迹和用量，
更早历史按 seq 游标分页，不从压缩后的 VIEW 拼造原文。`history_search` 的 search/dates/list/read
继续提供只读检索，归档身份基于当前 CardStream 会话，不对应旧物理 window。
其中 search 的匹配与相邻上下文、read 的正文分页只读取用户正文、引导正文与智能体正文
（RAW `user_text` / `agent_text` 的 `text`）。工具调用、参数、回执、思考和其他载荷不进入
检索正文；工具 RAW 继续完整保留。相邻前后 N 条、read 的消息总数和后续页判断均按正文计数，
跳过工具卡片，保留正文原始 seq 与既有片段/单页预算。

Web 每页仅对本页所涉及整合附带 `integrations.initial_card`，从相同 user/source/session 的
RAW 中读取最早 initial 用户卡，正文与附件复用用户消息安全投影。此锚点不追加进本页
`cards/messages`，不改变 limit 或 seq 游标；前端按 card_id 去重插入显示，确保长任务分页
不会隐藏原始提问，同时仍可按原游标完整加载处理过程。缺少真实 initial 时不虚构输入。

会话列表、日期和收藏过滤使用会话元数据；置顶/收藏按 source + session_id 隔离，
不会改写历史卡片或模型上下文。具体网页合同见 `frontend-conventions.md`。

### 生命周期、租约与删除

会话关闭、重开、在线租约、闲置扫描及活动指针都在 CardStream 数据库中维护。
正常整合完成要求没有存活工具、待确认事件、在途主请求或继续推理要求。超时/取消回执
不能伪造真实工具退出，迟到结果继续关联原 execution_id；未知副作用不自动重放。

网页“全部删除”请求 `DELETE /api/users/{user}/sessions?source=all&client_id=...`，
覆盖当前用户全来源、全部分页的会话与预留身份。服务先核验 ActiveRun，数据库再在同一
写事务中核验整合/工具存活和其他页面租约；任一繁忙会话使整批失败，事务异常全部回滚。
成功只将会话标记为 deleted、解除绑定/租约，RAW 原文永久保留，返回实际
`deleted_sessions` 与 `raw_preserved=true`。旧身份不能由迟到写入或重新预留复活。

单来源删除和自动生命周期回收同样不物理删除 RAW；不会清理其他用户、记忆、附件、
任务定义或旧历史文件。运行中备份不得只复制 cards.sqlite3 主文件而遗漏 WAL。

## 记忆 SQLite 存储

四档记忆以每用户独立的 `users/<user>/improve/memory.sqlite3` 为唯一权威存储。旧式 Markdown 碎片、三层 `data.json`、`storage.json`、`.memory_operations.json` 和 `important_view.json` 不再参与读取，也不会自动导入。`memory_temporary_important.md` 仍是位于用户根目录的可重建热视图，不是权威数据库或第五个生命周期层。

### 为什么独立建库

记忆与历史采用两个数据库：`improve/memory.sqlite3` 和 `cards.sqlite3`。二者的写入频率、保留周期和维护任务不同，分库可避免记忆加权与聊天归档争用同一写锁，也便于单独备份、诊断和重建。

数据库启用 WAL、`synchronous=NORMAL`、外键、5 秒 busy timeout 和显式写事务。连接、Schema 与业务规则统一归入 `run/memory/` 领域，生产代码只通过该领域入口的条目级接口读取或修改记忆，不再提供模拟旧 `data.json` 的 `load_index`、`write_index`、层级目录或正文文件路径接口，外部代码不得直接拼 SQL 修改生命周期状态。

### 表结构

| 表 | 用途 | 关键约束 |
|---|---|---|
| `memory_meta` | schema 与派生视图元数据 | `key` 主键 |
| `memory_fragments` | 四档正文和生命周期 | `filename_key` 全局唯一；tier 枚举；权重非负；永久层无 `expires_at` |
| `memory_weight_events` | 用户历史/人工更新的日锁与加权记录；creation 只占日锁、不加分 | `(fragment_id, evidence_date)` 主键，数据库强制每日最多一次 |
| `memory_operations` | 批量提取幂等结果 | `operation_id` 主键，重复批次只重放结果 |
| `memory_important_sources` | 临时重要热视图引用 | 每个临时源最多一条，并保存内容摘要用于失效判断 |
| `memory_work_items` | 提取分页、超限候选、归档和技能转化的共用持久待办 | 稳定 work_key、进度、状态、尝试次数和错误类型；重启后继续 |
| `memory_skill_sources` / `memory_generated_skills` | 自动技能来源身份、文件名、内容摘要及 active/stale 状态 | 来源删除仍保留引用以核对失效；正常晋升传递身份 |

记忆 schema v4 自动兼容迁移 v1/v2/v3。v2 新增 `memory_weight_events.source`，已有事件标为
`historical_migration`，不得伪称旧事件来自助手。新证据区分 `user`、`assistant`、`manual`。

v3 新增 `memory_fragments.domain`（fact/relation/state，缺省 fact）；旧行保留全部正文、
权重和生命周期并标为 fact。新增列和版本戳沿用既有 schema_migration 同事务校验，
不另建域索引；失败不留下半迁移。只部署新源码不等于已迁移正在使用的数据库。
公开 fact 条目保留原字段集合，relation/state 增加 domain，省略域的旧搜索结果视为 fact。
`memory.profile` 默认 `companion`，开放个人关系与近期情境；用户明确选择 `work` 时仅保留 fact，
规则及字段见 `configuration-reference.md` 的 memory 节和 `run/memory/lifecycle.md`。

`filename` 保留 `.md` 后缀只是稳定的逻辑身份和 UI 展示合同，不表示磁盘上存在对应 Markdown。跨层同名由数据库唯一约束拒绝，晋升直接更新同一行的 tier，不复制正文文件。

### 生命周期与事务

- 新的非明确候选进入 `seven_days`；用户明确要求长期记住的 fact/relation 可直接进入 `permanent`，state 始终留在 seven_days。
- fact/relation 更新正文后，生命周期到期时间不滑动；companion 中 state 正文更新默认刷新 tier_entered_at/expires_at，created_at 不变。重复命中不续期。用户历史证据按 RAW 事件时间对应的上海自然日写入 `memory_weight_events`，每个证据日最多加一（初建首日仅登记不加分）。
- 到期且达到阈值时，在一个事务内更新 tier、重置权重和加权事件、写入新的固定到期时间；未达阈值则先成功归档 Markdown，再条件事务移出活跃库。
- 语义融合会在同一事务内更新目标正文和生命周期、删除来源；任何一步失败都会回滚。
- 永久层不累计权重且无到期时间，普通非明确候选不能覆盖永久正文。
- companion 的 relation 晋升阈值来自 domain_rules，默认 1；state 不参与晋升，到期归档。
  域在候选写入、直接编辑、到期扫描和归档检查中一致生效，跨域改写或融合明确拒绝，拆分保留域。

Prompt 注入、Web 浏览、`memory_manage` 搜索和用户主动查看均为只读操作，不写加权事件。会话关闭或 CardStream 压缩成功后，运行时按 RAW seq 登记记忆待办；`background` 与兼容值 `on_commit` 还允许 Maintenance 认领 pending RAW。`on_commit` 当前不表示请求线程同步提取。用户主动修改正文（Web / memory_manage edit）或手动审阅更新是明确的人工维护入口，按执行日使用同一日锁；并非只读检索产生加权。

记忆输入只含用户正文、运行中引导和助手最终正文，排除工具、推理、重试/临时残片和撤回整合。
正文按 DeepSeek token 预算组织同一整合，不按 100 张 RAW 卡片截断；RAW 覆盖游标仍连续，
工具-only 区间无需模型调用。超大正文分片保留证据 ID 和偏移，后续助手页带有界用户背景，
context_only 不作新增证据。后台和手动入口共用 `memory.extraction_input_tokens`（默认 12000）。

### 记忆主题与分类

记忆首先要回答「以后理解这个人时，哪些信息需要一起想起」，再决定保存边界。
默认以连贯主题为单位持续累积，不按每句话、属性标签或可独立加权的字段拆条。
检索、更新和失效是帮助组织主题的参考，不是任一条件触发强制拆分的公式。

| 类型 | 适用 | 组织方式 |
|---|---|---|
| **A 类：个人画像与主题脉络** | 用户相对稳定的背景、表达、价值取向、偏好，以及能共同解释这些选择的经历 | 允许跨相邻属性组织成可读主题画像，随证据逐步补充；1000 字是存储硬上限，不是拆成属性小条的依据 |
| **B 类：具体约定与事件** | 需要单独查找或修订的明确决定、参数、约定、事件结论 | 只在确需单独取用时另存，最长 150 字；可以保留理解该事件所需的背景 |
| **state：近期情境** | 正在变化的生活状态、计划、情绪和关注点 | 同一持续情境合成一个时间性快照并更新原条目，限 seven_days、最长 150 字 |
| **relation：相处语境** | 用户明确表达的称呼、互动方式、共同梗与相处偏好 | 合并成能让后续互动保持连续的关系记忆，不为每个表达单独建档 |

同一边界也适用于用户通过 `memory_manage add/edit` 的手动写入：不显式声明类型时正文不得超过 B 类 150 字硬上限；超过 150 字必须声明 `memory_type=A`，且仍不得超过 1000 字。显式声明 `memory_type=B` 时超过 150 字直接拒绝。`important` 热画像由运行时维护，`memory_manage` 对该层只开放读取和搜索，不能直接新增、编辑或删除。

同一用户画像中的身份、表达、偏好和其明确给出的原因可以共同构成 A 类；同一项目的目标、
决定和当前进展也可以作为一个连续主题。不同用户、互不相关的生活事件、独立有效期或相互矛盾的事实才分别保存。
标题描述用户能理解的主题，不因“汇总”字样自动拒绝；避免把无关内容塞入一个空泛总览。

#### 晋升时超限拆分

记忆晋升需判断现有主题是否可与目标层同主题记忆融合。**只有融合后超过存储硬上限**
（A 类 1000 字 / B 类 150 字）时，才判断其中是否包含语义独立的内容并拆分：

- A 类按确实不同的画像/项目主题拆，不按属性维度拆；B 类只在混入不同主体或独立事件时拆分。
- 子碎片**就地留在目标档位**，不跨层移动；需要换层时由用户主动调整。
- 继承源碎片的 `expires_at` 与 `tier_entered_at`，**不重算时效**——拆分是同一份记忆的切分，不是新记忆。
- 权重按新档位规则从 0 起算（与直接晋升一致）；拆分本身**不产生加权事件**。
- `split_into` 与 `merged_with` 同时出现时优先执行拆分并记录告警。子碎片文件名继续受全局 `filename_key` 唯一约束；已有同名不会被覆盖，而是按 `-2`、`-3` 后缀生成可用名称。
- **主题连续性**：拆分后如果后续证据表明仍属同一主题，可重新融合；融合仍须通过硬上限校验。
- 只返回决策，多条落盘由 cron 在同一事务内完成。
- 该拆分挂在**晋升链路**（action=`memory_promotion`）上，不并入热画像任务 `daily_consolidate`。
- 每项晋升决策必须显式返回 `memory_type: "A" | "B"`。`split_into` 子项默认继承顶层类型，类型不同时可单独声明。模型决策不是唯一防线：SQLite 落盘前会再次检查，B 类通常应控制在 100 字且绝不超过 150 字，A 类绝不超过 1000 字；正文超过 150 字但没有显式声明 A 类、融合后超限或任一拆分子片超限时，本次晋升拒绝、整项不落盘，来源碎片保留等待下次巡检。

**计数口径**：提取按有意义的主题计批次，不按每句话建条；权重是“不同日期出现次数”，不是消息提及次数。
`extraction_max_candidates_per_batch` 是实际处理批次上限，不是丢弃线：满页或 `has_more=true`
继续请求尚未返回的候选主题，候选全部进入持久待办，分批完成后才推进历史游标。
晋升时可融合同一画像或持续情境的互补内容，不融合不同主体、域或有效期的记录。

文件名提示词建议 ≤ 20 字符，运行时字段上限 `FILENAME_MAX_CHARS` 为 50；两者刻意不对称，为 LLM 输出不稳定留余量，不得强行对齐。

### 搜索命中与每日加权

`self_improve` 先把每个候选提炼为 2～4 个核心关键词，再通过 `memory_manage search_many tier=all`
批量搜索：不超过 20 个候选时一次查询，超过 20 个时按最多 20 个一批分组。搜索优先规范化完整短语；模糊查询使用英文词、中文关键词和 bigram 计算覆盖率，
多片段查询至少命中两个有效片段且覆盖率不低于 50%，单个较长中文片段要求至少两个 bigram
且覆盖率不低于 60%。单个公共词不能直接证明两个碎片语义相同。

搜索结果返回 `match_score`、`match_coverage`、`matched_by`、`matched_terms` 和 `exact_match`。
子代理必须结合完整正文确认语义一致，并返回检索命中的 `memory_ref` 与 `filename`。
`self_improve` 的 `search_many` 强制 `include_content=true`；仍只授权只读搜索和必要的技能创建，
无须增开权重写入工具。宿主在 SQLite 事务中负责实际修改：

| 候选 action | 宿主行为 |
|---|---|
| `create` | 新建事实，同名冲突拒绝，不能覆盖旧碎片 |
| `reinforce` | 旧事实再次被证明，只加权、不接受正文替换 |
| `revise` | 旧事实被修正，写入完整新正文，并按证据登记权重 |
| `forget` | 后台提取须显式遗忘与用户原话证据；已有目标同样绑定检索引用 |
| 兼容 `upsert` | 新目标转 create；旧目标绑定真实搜索回执后按正文是否变化转 reinforce / revise |

每个旧目标都必须在本次成功的 `memory_manage search_many` 完整正文回执中出现；执行器依据
回执注入内容 SHA-256（忽略模型自行给出的哈希），落盘前同时检查 tier、filename 与内容摘要。
缺少回执、引用不一致、正文或层级已变化的候选拒绝，不盲改。用户主动 `manual_review` 的旧目标
同样遵守检索绑定，但不强制套用历史轮次证据格式。引用校验只能证明目标和快照一致，
**不能保证模型的语义判断永远正确**；公共关键词或高匹配分数仍不等于同一事实。

`search_many` 在一次调用中只加载一次目标记忆层，再在内存中处理最多 20 个查询，不会随候选
数量重复访问四层数据库。该路径面向数百至数千碎片；单项搜索同样使用相同评分规则和全局排序。

### 原证据日期、幂等与可观测性

- 每个后台候选提供 `durable=true`、`evidence` 及 `evidence_rounds`。create/revise/forget 仅接受用户原话；
  reinforce 可用助手确定性正文，但必须绑定真实搜索结果，并提供同一整合中明确确认该事实的 `user_evidence`；
  关联依据宿主 RAW 的 `integration_id`，不能将其他整合的用户原话当作背书。
  用户背书至少 8 字、非问题、包含明确确认措辞且与原事实至少三个词元交集；泛泛“继续/都对”不算。
  引文须位于单条安全正文内；工具结果、代码块、引用块、未确认猜测、敏感凭据不作证据。
  候选中的 `round` / `evidence_rounds` 在 CardStream 入口映射为 RAW `seq`；同名候选在持久化时合并已经验证的证据序号。
- 每张 RAW 卡片的 UTC `created_at` 随归档和 seq 恢复读取。宿主将事件时间转换为 **Asia/Shanghai 自然日**，模型不决定日期；处理发生在哪一天不影响证据日期。
- 事件时间缺失、无时区、非法或位于未来时，可保存有效正文，但不伪造历史加权，返回 `missing_evidence_date`；不得用会话创建时间回填。
- 首次证据创建碎片时 weight=0，登记 `reason=creation` 占据其日期的日锁；该事件不是 +1。
  新片批量获得四个不同日期的可信证据时，首次为 0、后三日各 +1，最终为 3。
  同一天跨批次再次出现不重复加分；不能把事件总行数直接当作权重。
- 当前档位首次 creation 日期是可接纳历史证据的下界；没有该登记的旧片使用进入档位日期。
  更早的乱序证据保守跳过并返回 `outside_tier_evidence_window`，不重置生命期或倒推创建时间。
  入库和晋升的固定到期时间仍基于实际入库/进入档位时间，未改成回溯历史时间。
- 普通晋升会清空原档位事件并重置权重；早于新档位进入日的证据不能再次加分。
  拆分晋升维持既有的生命周期继承契约，子片证据下界使用继承的 tier_entered_at，不另造晋升时间。
  `last_weight_date` 为本档位最新的已加权证据日期，乱序补提取不能让它倒退；
  真正去重依据是 `(fragment_id, evidence_date)`，不是单个 last_weight_date 字段。
- on_commit、补提取和后台恢复使用稳定批次 `operation_id`，只哈希用户证据、RAW seq 与事件时间，
  不因助手/工具序列化差异改变身份。操作结果与碎片修改同事务提交。
  同一批次返回 `replayed=true` 时只是旧回执，不代表本次又加了权重；不同批次边界仍由日锁兜底。
- 结果区分 `created`、`updated`、`content_updated`、`weighted`（发生实际 +1 的文件）、
  `daily_locked`、`weight_events`（逐证据日期的 +1）、`weight_skipped` 和 `rejection_reasons`；
  `candidate_filter` 报告执行器过滤原因，缺少日期不是静默当作今天加权。
- Web 详情由后端返回 `weighted_today`（今日证据实际 +1）与 `weight_locked_today`（包括 creation
  的今日已登记），并附 `weight_day` / `weight_timezone`。前端不再用 UTC 日期猜上海日锁，
  不再把历史加权一概描述为“因编辑增加”。运行状态维护栏按实际处理时间包含纯加权更新，
  不要求正文修改；`weight_increments` 排除 creation。日锁事件随档位晋升/删除清除，
  该列表是当前碎片状态视图，不是永久审计日志。

`memory_manage list(tier=all)` 与跨层搜索统一绑定 `seven_days`、`one_month`、`half_year`、`permanent` 四个碎片层，不包含独立热画像 `important`。跨层列表按上述层序及各层原排序合并，条目返回实际 `tier` 和 `memory_ref`，条数与字符预算、`offset/next_offset/has_more` 对合并后的列表统一生效。

自动注入由全局 `memory.prompt_injection` 控制，默认开启；关闭时不读取永久、热画像及三层临时记忆作为 Prompt 正文，只保留可通过工具检索的提示。该设置不删除记忆，也不关闭提取、整理或按需查询。记忆搜索默认保留关键词评分，可用 `match_mode=substring/word/exact` 或 `regex=true` 复用历史搜索的文本匹配；显式 `match_mode=fulltext` 使用 SQLite FTS5 / simple 中文分词索引和 BM25，不改变旧匹配模式。

### simple 全文索引

历史 schema v5 新增 `card_text_content` 正文视图与 `card_text_fts` 外部内容索引；只索引
`user_text`、`agent_text` 的 RAW text。引导属于用户正文，工具载荷、元数据和思考不进入索引。
RAW 追加时触发器同步索引；压缩与编辑撤回只改变 VIEW，不改历史原文和原文索引。
查询继续关联会话状态，逻辑删除后不返回该会话，但不物理删除其 RAW。

记忆 schema v4 新增 `memory_text_fts` 外部内容索引，覆盖四个碎片层的逻辑文件名和正文，
不包括独立 `important` 热画像文件。新增、改名、正文编辑和删除的触发器与原写入同事务；
层级迁移、权重和生命周期由权威碎片表保持，搜索不加权。
迁移先按现有机制备份，补建索引与版本戳同事务，已有记录会一次性回填；失败回滚。

两个工具显式传 `match_mode=fulltext` 后使用 `jieba_query` 与 BM25，默认关闭拼音扩展，
相关性查询建议 2～4 个核心词。历史支持既有过滤、offset 和字符预算；记忆批量查询使用一个
读取快照，标题/正文可分别匹配。全文 rank 不作为记忆融合的关键词覆盖率证据。
扩展与词典固定为 simple v0.7.1，随源码/发布包离线分发；每个相关连接显式加载后关闭扩展
加载开关。缺依赖或平台不兼容明确失败，不静默换分词器。平台要求与复现入口见
`run/infra/sqlite_simple/README.md`、`deploy/README.md` 和两个插件说明。

### 临时重要热视图

数据流固定为：

```text
用户对话历史 → 临时三层表行 → memory_temporary_important.md
```

后台整理临时三层时禁止把 `memory_temporary_important.md` 作为输入证据。热视图发布时，`memory_important_sources` 记录来源行和内容摘要；该关系只负责热视图失效判断，不过滤普通临时记忆的 Prompt 注入。来源碎片始终在原层按数量上限正常注入，热视图只作为更高优先级的强化概括。来源内容被修改、删除、转为永久层或到期时，旧热视图视为失效，普通临时层继续按自己的规则处理，等待后台更新。临时层间正常晋升且内容未变、期限有效不单独导致失效。主动查看仍可读取旧文件，查看本身不加权。

### 临时重要记忆的生命周期与页面状态

`MemoryStore.important_view_status()` 以一致的只读 SQLite 快照检查来源数量、内容摘要、所在层级和有效期；
`important_view_is_current()`、来源读取和 Web 读写接口使用同一判定。到期判断不必等待清理任务先删除来源。
校验不会删除正文、加权或刷新来源关系，损坏的来源数量记录按失效处理。

`GET/PUT /api/users/{user}/memory/important` 返回 `lifecycle`：
`status`（`valid`/`invalid`/`untracked`/`empty`）、`is_current`、`reason_codes`、简短 `reason` 和 `prompt_eligible`。
失效原因包括“来源内容已更新”“来源记忆已删除或清理”“来源已转为长期记忆”“来源记忆已到期”“来源记录异常”；
多个原因可合并，不回显源正文、文件名或 SQL。已删除来源没有历史原因记录时，不猜测是人工删除还是到期清理。

旧版或手写文件没有来源记录时显示“未校验”，保留原有兼容注入行为，不伪称已验证有效；空正文显示“暂无内容”。
`prompt_eligible` 表示全局记忆注入开关、当前有效性与注入预算允许后续构建使用，不代表当前 Run 已实际注入；关闭开关或预算不等于记忆失效。
人格/记忆静态 Prompt 在 Run 开始时构建，页面发现失效不会追改正在执行的 Run 快照。

网页临时重要记忆分栏使用单个只读详情，直接显示正文预览、路径、大小、上海时区更新时间以及后端生命周期状态和简短原因；失效时显示暂不注入，旧内容保留。该分栏不提供编辑、保存或删除控件，既有 HTTP 人工维护接口保持原有行为。
记忆页前台每 15 秒重读一次（后台标签不主动轮询），也可手动重新读取；状态请求失败显示“状态未知”，不沿用缓存的有效结论。
刷新不会覆盖未保存编辑。人工保存热画像只改正文，不重置来源摘要或自动恢复有效；正常后台更新并重新记录来源后，页面重新校验恢复状态。

热视图巡检不能一次性返回整个大型层级。`memory_temporary_important` 使用 `memory_manage list(limit=500, offset, compact=true, include_content=true, page_char_limit=80000)` 按“条目数 + 序列化字符数”双重边界分页读取三层临时记忆和永久记忆，正文随列表批量返回，不再对全部碎片逐条 `get`。沿 `next_offset` 读取到 `has_more=false` 且累计数量等于 `total` 后才能发布新热视图；否则必须保持旧视图，不得基于局部数据执行永久协调或清理。

热视图文件正文尽量保持在 `important_memory_max_chars`（默认 20000）以内，该值只控制 Prompt
注入预算。`important_memory_output_max_chars` 是语义独立的输出防失控硬上限，当前默认同为
20000；超过输出上限时拒绝本次更新且保留旧视图。

### 模板、升级与旧格式

`template/user/improve/` 保留 `.gitkeep` 与 `expired_memory/.gitkeep`，不提交预生成二进制库。
新用户补齐 `improve/expired_memory/`；已有 SQLite v1/v2 由连接层迁移为 v3，不导入旧式 JSON/目录记忆。

### 到期归档、续处理和技能生命周期（2026-10）

- 到期但未达晋升阈值时先以普通 Markdown 写入 `users/<user>/improve/expired_memory/YYYY-MM/`，
  文件名含首次归档时间、原层级、原文件名和稳定工作摘要；正文前保留原身份、层级、权重、时间和摘要。
- 完整文件先 fsync 并以不覆盖方式发布，成功后才按行身份、revision、正文摘要条件移除活跃行。
  文件写失败绝不删库；文件成功而事务失败时按原待办路径复用，避免每次重试生成副本。不同内容撞名则加后缀。
- 归档也检查凭据；发现遗留敏感正文或文件名时阻止归档和移除，报告错误，不把密钥写进普通 md。
  没有自动清理期限；不提供专用恢复工具、不做归档网页入口，不自动扫描/注入，不连接 Kemo Graph。
- 提取输入每页正文最多 12000 字符，单消息 5000 字符、300 字重叠，续处理摘要另限 4000 字符。
  单次 executor 最多六页，达到预算保留源和已返回候选并暂停；饱和且无进展报错，不假报处理完成。
  `memory_work_items` 记录 extraction / candidate / archive / skill；源提取完且所有候选批次落盘后才推进历史游标。
  提取执行器使用完整的 `context.runner.root/user/config`，分页始终经过持久账本与租约；
  不因上下文缺字段退回无账本执行，候选仍须按当前用户记忆库绑定检索引用。
- 自动技能先查同名及文本语义近似；完全相同可复用，同名独立内容用稳定后缀，相近内容须 get 核对后明确 update，
  不把重复失败当成功。产物须有实质适用场景、至少两个步骤和失败处理；纯事实不得编造方法。
- `source_memories` 经宿主核对后保存稳定来源行、文件名与内容摘要；正常晋升/融合/拆分只传递内容摘要仍匹配的技能和待办来源，不重新激活此前因修正而失效的技能。
  来源修正/删除/到期移出触发 stale；Cron、Prompt 发现和网页列表读取均核对，stale 停止自动注入且网页可见。
  技能保留人工编辑/删除，不自动删除；旁车 JSON 只是创建时可携带快照，数据库为当前状态权威。
- 晋升与技能创建分离：工具连续失败被移出、超时或缺少真实产物时，晋升可继续，
  未完成技能留独立账本，由下一次 30 秒晋升维护扫描重试。不能只凭模型 `skill_created=true` 清掉待办。
- 阈值 3/10/60、固定 TTL、条数制注入及其现行配置保持不变；不批量提升/续期任何存量。

### 备份与维护

- 最稳妥的备份方式是停止写入后复制整个 `improve/`，或在运行中使用 SQLite backup API。
- WAL 模式运行时不能只复制 `memory.sqlite3` 而忽略尚未 checkpoint 的 WAL。
- 不提交 `memory.sqlite3`、`-wal` 或 `-shm` 到模板或 Git。
- 完整性检查使用 `MemoryStore.integrity_issues()`；不要通过手工编辑数据库修复生产数据。

## 运行状态 SQLite 存储

卡片历史、整合、工具事实、会话绑定/租约及外部消息幂等归 `cards.sqlite3`。
任务计划归 `task_plans.sqlite3`，结构化日志归 `runtime/logs.sqlite3`；业务父子任务
账本仍归 `runtime/agent_tasks.sqlite3`，各库不复制同一份权威数据。

CardStream 滚动摘要属于 `context_cards.VIEW`，不再有独立上下文摘要缓存表或 runtime window。
维护任务按 RAW seq 连续认领，记忆候选成功持久化后推进 memory_processed_seq；
失败不推进游标，过期/陈旧 claim 不能提交迟到结果。`history_summary` 生成的是会话列表标题/简介，
从 RAW 读取并更新会话元数据；它与上下文滚动摘要及记忆提取分别独立。

关闭逻辑空间、排队维护和更新标题使用单会话事务，不能为一次元数据修改加载整份历史。
普通运行、记忆提取、网页查看与压缩都必须尊重 source/session/用户及代际边界。

### 文件边界

- `message.md` 与 `.processing.md` 是插件和核心之间的持久消息队列。
- 附件目录只保存消息附件，不保存结构化状态。
- `template/task_plan/plan_template.json` 只说明任务输入 Schema，不复制到用户目录。
- Cron 定义、用户配置、模块清单与资源文件继续按各自合同存储。

运行时不扫描其他文件格式来迁移、回退读取或双写这些状态。更新器只初始化当前数据库 Schema。

在线备份必须使用 SQLite backup API；离线复制应先完整停止框架，并连同 WAL 相关文件一起处理。不要直接编辑数据库。

## 结构化运行日志存储

### 单一事实来源

运行日志统一存放在项目运行目录的 `runtime/logs.sqlite3`：

| 类型 | 表 | 内容 |
|------|----|------|
| Cron 执行记录 | `cron_execution_logs` | 用户、任务、时间、状态、耗时、结果摘要与错误 |
| 任务中枢已清理记录 | `task_hub_cleaned_records` | 用户、记录种类、稳定记录 ID、执行时间的联合唯一清理标记 |
| 外部消息路由记录 | `message_route_logs` | 入站、出站、附件元数据与失败状态 |
| 外部消息模块状态 | `message_route_state` | 健康、收发计数、延迟、输入线程状态与平台扩展字段 |

进程启动和重启等纯诊断输出仍可使用普通文本日志。Cron 任务定义仍是任务配置文件；附件仍在模块附件目录。运行日志数据库不是聊天历史库，也不保存附件二进制。

### 写入与查询规则

数据库使用 Python 标准库 `sqlite3`，启用 WAL、忙等待、事务和时间索引，允许 RuntimeHost、Cron、消息路由与 Web 并发访问。Cron 记录同时提供 `user + task_id + occurred_at` 联合索引，单任务历史必须在 SQL 过滤后再应用条数上限，不能先截取用户总记录再用 Python 筛选。网页只查询表，不扫描模块目录或 Cron 目录寻找日志文件。

任务中枢“清理已完成执行记录”仅写入按用户隔离的 `task_hub_cleaned_records` 标记，不修改
`cron_execution_logs`、计划步骤结果或诊断接口。任务中枢查询 Cron 日志时在 SQL 条数限制
之前排除标记，避免已清理的新记录遮住未清理的旧记录；计划步骤按相同身份与执行时间过滤。
清理预览读取全部符合条件的记录，不套用总览最近 100 条窗口。标记跨服务重建保留，
同一任务的新执行时间或新日志事件键不受旧标记影响；批量确认与并发核验见 `task-automation.md`。

保留期未变时，清理完成后每天至多执行一次；修改有效保留期后，下次日志写入即可重新清理，每表每批最多 1000 条，余量在后续写入继续处理。既有自动空间回收机制仍保留：若清理确实删除了记录，且数据库至少 64 MiB、空闲页达到 25%、距离上次压缩至少 7 天，日志存储会在同一进程锁保护下执行一次受控 `VACUUM`；压缩失败只影响空间回收，不影响 Cron 或消息写入。配置读取本身不触发清理或 VACUUM。

每个事件根据稳定业务字段生成幂等键，重复提交不会制造重复行。写入失败属于可观测性故障，不得重放已经执行的任务或已经发送的消息；路由状态事务失败则必须显式报告，不能伪装为状态已更新。

仓库实例配置 `cron.log_retention_days=30`；读取优先级为 `KEMO_LOG_RETENTION_DAYS` → 实例配置 → `DEFAULT_RETENTION_DAYS=90`，非法环境值回退实例配置，非法配置回退代码默认；`0` 不自动清理。显式构造 `LogStore(retention_days=...)` 仍作为调用方覆盖。已有实例在每次写入重新读取配置，只读实例 `config/global_config.yaml`，用户配置不参与。清理只删除事件表过期记录；定时任务历史会话由独立 `cron.history_retention_days=7` 控制，不删除任务定义、消息队列或附件。

### 运行状态页分类执行记录

`GET /api/users/{user}/runtime/logs` 独立提供近期日志，不重新聚合 Prompt、记忆、Token 和整页运行状态。参数为 `category=all|backend|threads|terminal|message`、`page`（从 1 开始）、`page_size`（默认 25，上限 100）、`refresh`（默认 false，true 强制绕过读取缓存）。返回 entries、counts、分页、生成时间、cache 和 source_errors；除 `terminal` 外，页码超过当前记录窗口时回到最后一页。

- **全部**：合并以下来源的有界近期视图，不是全量历史日志。各分类数量也仅代表此窗口。
- **后端日志**：当前用户和 `__system__` 的 Cron 持久化记录，以及当前进程观察到的工具调用（包括 shell）与 RuntimeHost 组件生命周期摘要；不是原始 Python/服务器文本日志。已知无变化成功仅以小时统计出现，变化成功与每次 partial/failed 立即记录，统计行另计这些运行。
- **后端线程**：当前后端进程最多 200 个线程的即时快照，仅含线程 ID、存活/守护状态和通用类别，不保存轮询快照，不展示自定义线程名、栈和局部变量，也不声称是历史执行轨迹。
- **终端日志**：`start_web.py` 启动 kemo-agent 时用户可见终端的标准输出与标准错误快照，不是 shell 工具日志。启动入口会在保留原终端显示的同时按行收集输出；ANSI 控制字符会移除，常见 API Key、Token、Cookie、密码、Authorization/Bearer 与 URL 密码形态会脱敏。未换行的单条输出在收集器内也只保留 1001 字符，最终展示为最多 1000 字符加省略号，避免异常长行让进程内 pending 缓冲无限增长。终端分类是单个只读、按时间正序的实时输出页：不分页，历史行在上、新输出在底部动态出现；前台每 2 秒只读取并渲染最近 300 行，达到窗口上限后自动丢弃浏览器侧最旧行，避免全量缓冲区卡顿。用户向上滚动时不强制拉回底部。日志仅在当前进程内存中保留，重启后以新启动终端重新开始；不写入 SQLite，也不能补录启动前或其他进程的终端内容。shell 工具调用仍归入“后端日志”摘要，完整命令及输出不进入此页面。
- **消息日志**：当前用户的消息平台、类型、成功状态和脱敏后的完整文本正文，运行诊断投影在分页前将同轮输入、输出合并为一条 `direction=exchange` 记录，`inputs` / `outputs` 数组分别保留正文、附件名、类型与状态；`counts` 和分页总数按合并卡片计。“全部”分类沿用同一投影。不暴露其他用户记录、聊天标识、附件路径和凭据。消息模块详情仍按 machine_id 与 bound_user 共同过滤，继续返回原始逐条收发记录，不改变持久化正文、保留期或 LLM 上下文限制。

消息日志数据库 schema v3 在原 `message_route_logs` 上增补 `exchange_id`，旧库首次读取时自动兼容升级，原记录保留且默认为空。文件消息插件将原入站 `message_id` 写入同轮收发与附件日志；服务端按 user、machine_id、platform、chat_type、chat_id 与 exchange_id 关联，避免并发同秒消息配错。旧记录仅按上述路由身份与完全相同的时间关联；同桶存在多条非附件输入或输出时视为歧义，保留独立单边卡片，不依赖相邻顺序猜配。关联字段只在服务端使用，对外仅提供摘要哈希 ID；原始日志仍最多读取最近 200 条，窗口截断或单边记录使用空数组明确表示缺少一侧。

读取策略：SQLite 分别按索引选取最多 200 条合并 Cron 与 200 条消息投影，不解析大结果/错误 JSON。投影按规范化项目根目录和用户隔离，缓存 5 秒，最多 16 个 LRU 桶；并发缓存缺失合并查询，返回深拷贝。同进程 Cron/消息写入、消息删除在事务提交后失效缓存；其他进程写入最多经过 5 秒读取缓存窗口可见。源读取失败不缓存为空成功，页面显示简短的来源不可用提示。

新增诊断摘要只在进程内保留：全进程最多 2048 条、最长 1 小时，读取时清除过期记录，满容量淘汰最旧记录，重启丢失，不写入 SQLite。存量任务失败、消息记录、对话终态的立即持久化规则不变。本缓存不是可靠审计日志，也不削弱已有持久化保障。

除终端分类外，网页分类、翻页和刷新使用独立查询，前台每 10 秒刷新，后台页面不定时轮询；终端分类使用无分页的实时输出视图，前台每 2 秒刷新。切换用户不沿用旧用户展示数据。刷新日志强制绕过服务端 TTL，不触发整页聚合。

### 安全与维护

消息正文和外部平台标识属于敏感运行数据。`runtime/` 必须保持 Git 忽略，部署时应限制数据库文件的本地访问权限，不得把 Token、Cookie 或平台密钥写入日志。

在线备份应使用 SQLite backup API；离线复制必须先完整停止框架，并连同 WAL 相关文件一起处理。不要直接编辑数据库。

## Python 持久化写盘策略

### 多用户有界读取缓存

`run.infra.BoundedReadCache` 是可丢弃的读快照基础设施，不是数据库、任务队列或运行态存储。命名空间由缓存实例隔离，键包含规范化路径或服务实例内的用户/来源/会话；Windows 使用系统路径大小写规则，Linux 不折叠大小写。调用者必须先执行用户存在性、权限、路径包含及链接校验，不能把缓存命中视为授权。

| 接入点 | 总条目 / 估算容量 | TTL 与失效 |
|---|---|---|
| 配置 JSON 文本、人格/手册/技能/插件提示词、拓展/感知元数据与数据、子代理包源文件 | 512 / 16 MiB；同用户最多 64 条、4 MiB；单文件超过 512 KiB 不缓存 | 每次校验 mtime_ns、ctime_ns、大小、inode、device、mode；最多 5 秒；Web 原子写入及公共原子替换成功后显式失效 |
| Cron 持久化任务列表 | 128 / 8 MiB；每个任务目录一个桶、最多 2 MiB | 每次扫描任务文件成员和元数据签名，最多 30 秒；创建/修改/删除/迁移失效；只缓存磁盘定义，每次叠加实时运行态 |
| 执行日志投影 | 16 / 8 MiB；每个根目录+用户一个桶、最多 2 MiB | 5 秒；提交后失效，手动刷新失效 |
| 文件空间摘要 | 256 / 2 MiB；同父目录最多 8 条、512 KiB | 10 秒；Web 文件操作显式失效，外部修改由 TTL 兜底 |
| 首页概览 | 每个 Web 服务实例 32 / 8 MiB；每用户最多 4 条、2 MiB | 0.5 秒，用户/来源/会话独立键 |

同一键并发缺失只运行一个加载器；不同键的磁盘/数据库读取不持有全局缓存锁。等待任务结束后重新检查缓存，异常不缓存为空结果。每个缓存最多跟踪 128 个进行中的加载，超过预算直接读源、不增加跟踪状态。TTL/LRU 同时限制条目和 Python 对象估算容量，并优先淘汰超出当前用户配额的数据。此容量是缓存驻留快照估算，不是进程总 RSS 上限，也不包含请求正在构建的临时结果。

读快照深拷贝隔离；失效会标记正在读取的任务，禁止旧结果回填。已经开始的请求仍可能收到其读取时的快照，后续读取重新加载。失效标记随任务结束释放，没有无限增长的目录 generation 表。`stats()` 只返回命中、缺失、等待、淘汰、绕过、驻留条目/估算字节及正在加载数，不暴露路径、用户名、正文或密钥，也不新增统计落盘。

源文件缓存保留每次文件元数据检查，减少的是重复打开/读取，不消除所有 stat 或 JSON/YAML 解析。读取中变化会重试，持续变化回退直接读取；缺失、权限/编码错误不负缓存。`kemo.yaml` 不接入缓存。外部写入通常在下次元数据检查可见；外部工具刻意保持所有元数据不变时由 5 秒 TTL 兜底。JSON/YAML 每次重新解析，配置校验、权限裁决、目录成员发现、注册代码执行和完整 Prompt 构建不缓存，避免共享可变注册器或冻结用户/会话的动态记忆与权限。

本次不把未持久化的 Cron 状态、执行锁、活跃 Run、删除栅栏、消息幂等状态改为 LRU 缓存，也不推迟新的业务写入。模型能力/网络目录等其他专用缓存暂保留原策略；跨进程依赖文件签名/短 TTL 或数据库事务，没有分布式缓存一致性承诺。系统统计默认使用 3600 秒窗口，仅明确无数据变化的成功省略逐次日志；partial/failed 每次立即持久化，终态与用户操作仍按原业务规则落盘。

框架采用“运行态内存优先、语义变化写入、终态事务提交”的持久化策略。它减少高频 Python 任务对 JSON、Markdown 与 SQLite 的重复覆盖，但不延迟错误、取消、对话终态和用户主动操作。

### 高频系统任务

- 感知刷新、拓展刷新和记忆晋升检查仍按原调度频率执行。
- `latest_run_at`、`next_run_at` 与运行状态先保存在进程内；默认每 300 秒、发生错误或 RuntimeHost 正常停止时写回任务 JSON。
- 系统任务仅在成功且明确 `data_changed=false` 时静默；没有这个证据的 `skipped` 也保守写入。变化成功与每次失败/部分失败立即写入。
- 默认每 3600 秒按用户与任务写统计行，保留全部运行次数、状态计数、成功率、平均/最大耗时、窗口起止时间与最后一次有界结果摘要，不保存 Prompt 或大正文；到期或正常停机冲刷，异常退出可能丢失未冲刷统计。模块无变化证据边界见 `task-automation.md`。

### 感知与拓展采集

- 采集进程仍按设定频率运行，System Prompt 读取的仍是最新已采集结果。
- 数据 Markdown、JSON 和二进制图表只有在语义内容改变时才原子替换。
- 健康状态发生变化时立即写清单；健康状态稳定时最多每 300 秒更新一次检查点。
- 新建感知/拓展模板不再把当前秒级时间写进注入正文，避免“数据没变、文件必变”。

### 对话与记忆

- 用户、助手与工具 RAW 事件立即追加；写盘不会改变 VIEW 的有效 Token。
- VIEW 摘要替换、吸收关系与 Token 更新是同一事务；失败保持原历史有效。
- 终态记录只收口整合并保存指标，不把完整历史重新复制到另一套存储。
- 记忆维护按 RAW seq 认领与提交，不读取压缩 VIEW 作为唯一证据。
- 标题、收藏、租约和维护状态更新不改写历史 RAW。

### 不进入内存延迟的边界

以下内容仍立即持久化：错误与部分失败日志、对话成功/取消/失败终态、用户主动创建或修改任务、文件和媒体产物、外部消息幂等状态、记忆碎片正文，以及需要跨重启继续的任务声明。

## CardStream 原子写与并发冲突

卡片身份、事件键与会话 seq 唯一约束阻止重复写入；VIEW 更新以快照版本与会话代际校验。
摘要替换检查旧前缀版本，在事务中只修改选定 VIEW，保持同时到达的新尾部。
会话生命周期、绑定、租约与工具登记均以数据库状态为准，不接受旧进程内副本覆盖新状态。
失败必须向调用者报告，不能静默丢弃写入再返回成功。

撤回、清空或删除都是视图/会话生命周期操作，保留 RAW。数据库触发器和运行时状态共同
阻止迟到写入复活已删除身份。维护 claim 过期回收不是工具或任务重放授权。
