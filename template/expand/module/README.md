# `module/` —— 模块内部实现区（含小组件栏）

> 框架只读取本目录声明的 `panel.json`、对应值文件和状态文件；除此之外的内部实现、资源和工程文件
> 不会被自动注册、注入或执行。上一层 `expand.json` 的字段集保持不变，不要把面板字段写进清单。

## 这个目录里有什么

| 文件 | 谁写 | 谁读 | 作用 |
|---|---|---|---|
| `panel.json` | 模块作者手写 | **框架（只读 JSON 渲染控件）** | 小组件栏的**声明**：放几个容器、每个容器显示什么、能改什么 |
| `panel.values.json` | 框架（用户点保存时写） | 模块自己 | 用户在面板上改出来的**值**（明文 JSON，允许含密钥） |
| `status.json` | 模块自己（采集时写） | **框架（只读渲染）** | 状态容器的**数据源**，只给用户看 |
| 其他任何文件 | 模块自己 | 模块自己 | 实现、资源、完整工程……随你放 |

## 小组件栏怎么工作

```text
       用户点一下                             模块自己的代码
  ┌──────────────────┐                  ┌───────────────────┐
  │  config 容器     │ ──写──────────▶  │ panel.values.json │
  │  （改地址/密钥） │                  └─────────┬─────────┘
  └──────────────────┘                            │ 模块读它做真事
                                                  ▼
  ┌──────────────────┐                  ┌───────────────────┐
  │  status 容器     │ ◀──读──────────  │   status.json     │
  │  （看状态）      │                  └───────────────────┘
  └──────────────────┘                            ▲
                                                  │ 采集时写
  ┌──────────────────┐                  ┌───────────────────┐
  │  action 容器     │ ──expand_call──▶ │ start_expand.py   │
  │  （按钮/发送）   │                  │   execute(...)    │
  └──────────────────┘                  └───────────────────┘
```

三条关键性质：

1. **状态与配置都不进 Prompt。** 进 Prompt 的永远只有模块根目录的 `input_data.md`。
2. **面板不需要模块提供后端。** 框架只读写 JSON 文件，不执行模块代码、不要求模块起服务。
3. **数据来源自由。** 状态文件里写什么、数据从哪来（网络、本地、框架内）由模块自己决定。

## `panel.json` 字段速查

顶层：

| 键 | 说明 |
|---|---|
| `schema_version` | 固定 `1` |
| `title` | 面板标题（可省略） |
| `containers` | 容器数组，每个元素是一块独立的小卡片 |

三类容器：

| `kind` | 必填键 | 可选键 | 说明 |
|---|---|---|---|
| `status` | `source`（模块内文件路径） | `fields` | 只读展示 |
| `config` | `values`（模块内文件路径） | `fields`、`presets` | 读写配置 |
| `action` | `controls` | — | 按钮 / 输入发送 |

`fields[]` 每项：`key`（对应文件里的键）、`label`（显示名）、`type`、以及按类型可选的
`default` / `options` / `min` / `max` / `placeholder` / `masked` / `required`。

`controls[]` 每项：

- `{ "type": "button", "label": "…", "command": "<已有命令>" }` —— 零参数按钮
- `{ "type": "send", "label": "…", "command": "<已有命令>", "inputs": [ … ] }` —— 带输入的"发送"

## 控件类型

| 类型 | 用途 | 落盘形态 |
|---|---|---|
| `string` | 单行文本（地址、密钥） | 字符串；`masked: true` 只影响显示 |
| `number` | 数值，可配 `min` / `max` | 数字 |
| `boolean` | 开关 | `true` / `false` |
| `enum` | 下拉选择，配 `options` | 选中的 `value` |
| `text` | 多行文本（备注、长指令） | 字符串 |
| `badge` / `markdown` / `keyvalue` | 仅用于 `status` 容器的展示 | — |

## 硬边界

- **不要**把 `panel.json` 写进 `expand.json` —— 清单拒绝未知字段，写进去整个模块会判 invalid。
- **不要**把密钥写进 `input_data.md` —— 那份文件会送到模型提供方。密钥写在 `panel.values.json` 里是允许的。
- 面板**不做**任意 HTML/JS：只能使用上表中的原语，由框架渲染。
- 路径必须留在模块目录内，不能用 `..` 或符号链接指向外部。

## 当前框架行为

- Web 拓展详情已经提供第三个“用户配置”Tab，并在每次请求时重新读取 `panel.json`、值文件和状态文件；
  修改后无需重启 Web，重新进入 Tab 或刷新页面即可热加载。
- `expand_creater action=create` 会把本目录四个文件原子复制到新模块，并把面板标题替换成真实模块名。
- 默认面板只声明已经由模板 `start_expand.py` 实现的 `refresh` 动作，避免生成可见但不可用的按钮。
- 创建时若提供自定义 `start_expand`，创建器会移除默认 action 容器；请在真实命令实现完成后再声明按钮。
- 默认 `data_update.py` 会读取 `panel.values.json`、刷新 Prompt 摘要，并把脱敏执行状态写入
  `module/status.json`。面板值不会仅因存在而自动进入 Prompt。
- `validate` 会在面板存在时使用框架真实解析器复验；没有面板的旧拓展仍保持兼容。
