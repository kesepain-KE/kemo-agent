# 用户模板说明

将本目录复制为 `users/<name>/` 后，按以下规则修改即可创建新用户。

## user_config.json — 用户配置

| 字段 | 说明 | 必须修改 |
|------|------|----------|
| `provider.type` | 固定 `"kemo"` | 不改 |
| `provider.base_url` | Kemo 网关地址 | ✅ |
| `provider.api_key` | API 密钥（优先于 `api_key_env`） | 按需 |
| `provider.model` | 默认聊天模型名 | ✅ |
| `provider.stream` | 是否启用流式输出 | 可选 |
| `provider.input_modalities` | 主模型确认支持的输入模态；Chat 只允许 text/image，Kemo 可增加 audio/video/file | 按需 |
| `multimodal_models.*` | 各多模态能力对应的专用模型名，含独立的 `video_understanding` | 按需 |
| `multimodal_routing.vision` | 图片使用主模型还是专用视觉模型；默认自动 | 按需 |
| `task_plan.auto_accept` | 是否自动批准任务计划 | 按需 |
| `skills.shared_whitelist` | 允许使用的共享技能列表 | 按需 |
| `expand.shared_whitelist` | 允许使用的共享拓展列表 | 按需 |
| `expand.global_whitelist` | 允许使用的全局拓展列表 | 按需 |
| `perception.global_whitelist` | 允许使用的全局感知列表 | 按需 |
| `knowledge.use_shared` | 是否使用共享知识库 | 按需 |
| `knowledge.use_global` | 是否使用全局知识库 | 按需 |
| `kemo_graph.*` | 知识图谱切换开关（需 kemo-graph 模块接入） | 按需 |
| `plugins.whitelist` | 允许使用的插件白名单 | 按需 |

## user_soul.md — 用户人格

注入系统提示词的人格定义。格式为 Markdown，包含工作方式、沟通风格、执行习惯。

## 子目录骨架

需要保留的空目录使用 `.gitkeep` 跟踪。`improve/` 在模板中只保留目录标记，不预置 SQLite 二进制、Markdown 记忆碎片或旧式 `data.json`；真实用户创建完成后会初始化 `improve/memory.sqlite3`，四档记忆都存放在该数据库的表中。

`history/` 与 `task_plan/` 在模板中必须保持为空，只保留目录标记；不要预置数据库二进制文件或运行数据。创建用户的后处理会按当前 schema 初始化 `history/history.sqlite3` 与 `task_plan/task_plans.sqlite3`。

## memory_temporary_important.md

由 `memory_temporary_important` 子代理自动维护，不需要手动修改。

## 统一验收

```powershell
python -m tests.template_tests.user --target users/<name>
```

验收会检查配置合并、人格 Prompt、SQLite 记忆库、知识目录和多用户隔离，但不会回显密钥，
也不会请求真实 Provider。`task_cron` 与 `task_plan` 只检查初始化目录，不在本批测试其
业务逻辑。稳定标准见 `tests/template_tests/user/STANDARD.md`。
