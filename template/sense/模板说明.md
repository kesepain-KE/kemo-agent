# 感知模块模板说明

感知只提供只读数据采集。将本目录复制为 `global_sense/<name>/`；模块必须是 `global_sense/` 的直接子目录，不存在用户层或共享层感知。

## 自动运行机制

RuntimeHost 按 `task_cron_system.sense_update_rate` 扫描合法模块，并在独立 Python 子进程中调用 `data_update.py` 的零参数 `update()`；没有 `update()` 时才回退到零参数 `main()`。

- 子进程使用隔离模式并受 `task_cron_system.module_update_timeout` 限制。
- Windows 后台采集由框架以隐藏窗口方式启动；Linux 使用普通无交互子进程。
- 模块不要自行启动终端、守护进程、无限循环或常驻线程，也不要设置 `CREATE_NEW_CONSOLE`。
- 用户在终端手动执行 `python data_update.py` 属于前台调试，不受后台隐藏策略影响。

## 文件合同

### `sense.json`

| 字段 | 说明 |
|------|------|
| `name` | 模块唯一标识，建议与目录名一致 |
| `data_md` | 数据输出文件名，通常为 `sense.md` |
| `recent_update` | 最近一次成功采集时间，格式为 `YYYY-MM-DD HH:MM:SS` |
| `health` | `正常` 或 `异常`；首次成功前建议为 `异常` |
| `start_update` | 零参数同步采集入口，通常为 `data_update.py` |

### `data_update.py`

只修改 `collect()` 和 Markdown 展示内容。`update()` 必须是同步、零参数、可在超时内结束的函数。成功可以返回 `None` 或 `{ "ok": true }`；失败应抛出异常、返回 `False`、`{ "ok": false }` 或失败状态。

输出应原子写入，认证信息只从环境变量读取。框架会再次校准 `sense.json` 健康状态，因此模块不得伪造成功时间。

### `sense.md`

该文件可能进入所有启用用户的 System Prompt。只保存必要、低敏感且有界的数据，不写密钥、Cookie、完整环境变量或无界日志。

### `_last_run.json`

可选的最近运行记录，不参与模块发现。模板会保存 `ok`、时间、错误和输出大小，便于排查采集失败。

感知模块不需要模块级 `register.py`；根级发现和 Prompt 注入由框架统一完成。
