## 一、完整配置 + 逐项解释

### provider — LLM 提供商配置

```json
  "provider": {
    "type": "kemo",
```
- **含义**：Provider 类型，`"kemo"` 或 `"openai"`
- **源码影响**：根据 type 决定走哪个适配器分支

```json
    "base_url": "http://127.0.0.1:8741/v1",
```
- **含义**：API 端点地址
- **自动补全**：代码应自动补全 `/v1` 后缀（如果用户没写）

```json
    "api_key": "YOUR_KEMO_API_KEY",
```
- **含义**：明文 API Key，**优先级最高**
- **源码影响**：读取 provider 时，先检查 `api_key` 是否非空；非空则直接使用，空则回退到 `api_key_env`

```json
    "api_key_env": "KEMO_API_KEY",
```
- **含义**：环境变量名，作为**兜底密钥来源**
- **源码影响**：仅当 `api_key` 为空时，才读取此环境变量
- **不填时的默认值**：`"KEMO_API_KEY"`

```json
    "model": "deepseek-deepseek-v4-pro",
```
- **含义**：默认聊天模型名

```json
    "stream": true
```
- **含义**：是否流式输出
- **默认值**：`true`

```json
  },
```

### multimodal_models — 多模态专用模型

```json
  "multimodal_models": {
    "vision": "",
    "image_generation": "",
    "image_edit": "",
    "audio_transcription": "",
    "speech_generation": "",
    "speech_to_speech": "",
    "video_generation": ""
  },
```
- **含义**：各多模态能力的专用模型 ID。`""` = 使用 Provider 的默认模型
- **源码影响**：当某个能力被调用时，如果对应字段非空则使用该模型，空则使用聊天模型或 Provider 能力默认模型

### task_plan — 任务计划

```json
  "task_plan": {
    "auto_accept": false
  },
```
- **含义**：是否自动执行任务计划。`false` = 需用户在 Web UI 点击批准

### skills — 用户 Skill 白名单

```json
  "skills": {
    "shared_whitelist": []
  },
```
- **含义**：共享技能白名单。`[]` = 全部允许，有内容则只允许列出的项
- **注意**：`user_whitelist` 已移除

### expand — 拓展模块白名单

```json
  "expand": {
    "shared_whitelist": [],
    "global_whitelist": []
  },
```
- **含义**：拓展白名单。`[]` = 不限制

### perception — 感知模块白名单

```json
  "perception": {
    "global_whitelist": []
  },
```
- **含义**：全局感知白名单。`[]` = 不限制

### knowledge — 知识库

```json
  "knowledge": {
    "use_shared": true,
    "use_global": true
  },
```
- **含义**：
  - `use_shared`：是否使用共享（全局）知识库
  - `use_global`：是否使用**全局知识库**
- **注意**：`enabled` 字段已移除。启用状态由源码默认处理（默认启用）

### kemo_graph — 知识图谱替换器

```json
  "kemo_graph": {
    "enabled": false
  },
```
- **作用**：当 `enabled = true` 时，作为**上层替换器**，替代知识库索引和记忆碎片的直接注入
- **详细行为**：见下文第三节

### plugins — 插件白名单

```json
  "plugins": {
    "whitelist": []
  }
```
- **含义**：插件白名单。`[]` = 不限制所有插件
- **路径**：`E:\code\kemo-agent\plugins` 目录下的插件
- **源码影响**：注册/加载插件时，检查白名单；非空时只加载白名单内的插件

```json
}
```

## 三、核心逻辑变更（需重点实现）

### 1. API Key 优先级链

```
provider.api_key（明文，非空）
    ↓ 为空时回退
provider.api_key_env（环境变量名，读取系统环境变量）
    ↓ 为空时回退
```yaml
    报错：无可用 API Key
```

**源码位置**：Provider 初始化/认证模块

---

### 2. `kemo_graph.enabled` 的替换器行为

当 `enabled = true` 时：

```
┌─────────────────────────────────────────────┐
│               Prompt 注入                      │
├─────────────────────────────────────────────┤
│  原本单独注入：                                │
│    • 知识库索引（knowledge_index）             │
│    • 记忆碎片（permanent/important/temporary） │
├─────────────────────────────────────────────┤
│  kemo_graph.enabled = true 时：               │
│    ✗ 不注入知识库索引                          │
│    ✗ 不注入记忆碎片                            │
│    ✓ 统一注入 kemo_graph 的                     │
│      图谱化 + 向量化检索后的过滤结果             │
└─────────────────────────────────────────────┘
```

**条件判断**：
- `kemo_graph.enabled = true` **+** 知识库 `use_shared/use_global` 任一启用 → 用图谱结果替换知识库索引
- `kemo_graph.enabled = true` **+** 记忆层级启用 → 用图谱结果替换记忆碎片

**源码位置**：PromptBuilder 注入管线，在注入知识库索引和记忆碎片的步骤前增加判断

---

### 3. `plugins.whitelist` 插件过滤

**逻辑**：

```python
def get_enabled_plugins(whitelist: list[str]) -> list[Plugin]:
    if not whitelist:
        # 空列表 = 不限制，加载所有插件
        return all_plugins
    else:
        # 非空列表 = 只加载白名单内的插件
        return [p for p in all_plugins if p.name in whitelist]
```

**源码位置**：`plugins/__init__.py` 或插件注册/发现模块

---

### 4. `knowledge.enabled` 移除后的默认行为

移除 `enabled` 字段后，知识库的启用状态应为：

```
默认 = 启用
仅当用户显式设置 enabled = false 时才关闭
```

由于 `user_config.json` 中不再有 `enabled` 字段，而全局配置中也已删除 `knowledge` 块，代码应默认知识库为启用状态。
