# 拓展模块标准化重构方案

## 一、问题

当前 `global_expand` / `shared_expand` / `users/<user>/expand` 三层的拓展模块没有统一的结构规范，`register.py` 里通过 `add_expand(scope, module, inject_file)` 硬编码注入文件路径，只支持单一文件注入，没有元数据描述，也没有"采集"和"操控"的能力分层。

具体问题：

1. **单文件注入**：每个模块只能注册一个 inject 文件，无法区分"数据采集"和"操控能力"两个不同维度
2. **无元数据**：模块叫什么、能做什么、数据是否健康——这些信息没有结构化的描述
3. **注册即注入**：注册了就一定注入，无法通过配置精细控制"只采集不操控"或"只操控不采集"
4. **无操控手册机制**：AI 要操控外部设备时，没有分层参考手册（注入层提示能力、操作层详细指导），要么全量注入挤占 prompt，要么完全不注入 AI 不知道怎么用
5. **三层差异未标准化**：`global_expand`、`shared_expand`、`users/<user>/expand` 各有各的注册方式，缺乏统一的数据契约

---

## 二、方案

每个拓展模块采用**硬编码标准化结构**，与感知模块（`global_sense`）风格统一。

### 目录结构

```
<scope>_expand/<module>/
├── expand.json               ← 必选。元数据描述
├── input_data.md             ← open_input=true 时注入，数据采集结果
├── expand_control.md         ← open_control=true 时启用，操控手册
├── data_update.py            ← 数据采集入口，运行它刷新 input_data.md
├── start_expand.py           ← 操控入口，运行它执行外部操控
└── 其他任意文件.py            ← 与 AI 无关，系统不扫描
```

### 适用范围（三层）

| 层级 | 目录 | 注册模块 | 说明 |
|------|------|----------|------|
| global | `global_expand/` | `global_expand/register.py` | 全局通用拓展，所有用户共享 |
| shared | `shared_expand/` | `shared_expand/register.py` | 共享层拓展，知识库共享用户可用 |
| user | `users/<user>/expand/` | 自动发现（`attach_user_prompt_sources`） | **用户私有拓展，每个用户不同** |

**核心差异在 user 层**——每个用户自己的 `expand/` 目录里放的是自己定制的拓展模块。同一个系统不同用户看到的 `[expand_data]` 段内容因此不同。

### `expand.json` 字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 拓展模块显示名称 |
| `explain` | string | 是 | 简短描述，可选注入 prompt 帮助 AI 理解模块用途 |
| `open_input` | bool | 是 | 是否开启数据采集。true 时系统注入 `input_data.md` |
| `input_data` | string | 是 | 输入数据文件路径，一般为 `"input_data.md"` |
| `input_health` | string | 是 | 数据采集健康状态，仅允许 `"正常"` 或 `"异常"` |
| `start_update` | string | 是 | 更新数据的入口文件名，一般为 `"data_update.py"` |
| `open_control` | bool | 是 | 是否开启拓展操控。true 时系统注入 `expand_control.md` 的注入层 |
| `start_expand` | string | 是 | 操控入口文件名，一般为 `"start_expand.py"` |
| `start_control` | string | 是 | 操控手册文件名，一般为 `"expand_control.md"` |

### 硬性规则

1. **`expand.json` 必须存在**，不是可选
2. **`open_input` 和 `open_control` 是唯一权威**。不靠文件存在性推断——即使 `input_data.md` 文件存在，`open_input: false` 就不注入；用户可能保留文件但临时关闭能力
3. **`input_health: "异常"` 时**，该模块的数据不注入（数据不可靠），但操控能力不受影响
4. 字段校验规则：
   - `name` / `explain` → 非空字符串
   - `open_input` / `open_control` → 布尔值
   - `input_data` / `start_update` / `start_expand` / `start_control` → 模块目录内的文件名（不得跳出目录）
   - `input_health` → 仅 `"正常"` 或 `"异常"`
5. 违反任何规则 → 该模块标记为 **异常**，不注入数据也不暴露操控

### `expand_control.md` 分层约定

使用 markdown 二级标题分隔：

```markdown
## 注入层

简短文本，描述该拓展的存在和基本操作能力。这部分自动注入到 AI prompt。

## 操作层

详细操控手册、指令格式、参数说明、示例。AI 决定操控此拓展时主动读取。
```

- **注入层**：由系统自动提取并注入到 `[expand_data]` 段
- **操作层**：不注入，文件路径返回在诊断元数据中，AI 按需主动 `read_file`

### 改动 1：`run/prompt_sources.py` — 新增 `ExpandMeta` 和 `_read_expand_meta()`

```python
_EXPAND_JSON_FIELDS = {
    "name", "explain",
    "open_input", "input_data", "input_health", "start_update",
    "open_control", "start_expand", "start_control",
}
_EXPAND_HEALTH = {"正常", "异常"}


@dataclass(frozen=True, slots=True)
class ExpandMeta:
    name: str
    explain: str
    open_input: bool
    input_data: str
    input_health: str
    start_update: str
    open_control: bool
    start_expand: str
    start_control: str
    module_dir: Path
    valid: bool
    error: str = ""


def _invalid_expand_meta(module_dir: Path, error: str, *, name: str = "") -> ExpandMeta:
    return ExpandMeta(
        name=name or module_dir.name,
        explain="",
        open_input=False,
        input_data="",
        input_health="异常",
        start_update="",
        open_control=False,
        start_expand="",
        start_control="",
        module_dir=module_dir,
        valid=False,
        error=error,
    )


def _read_expand_meta(module_dir: Path) -> ExpandMeta:
    """Read one standardized expand module without failing the whole registry."""

    json_path = module_dir / "expand.json"
    if not json_path.is_file():
        return _invalid_expand_meta(module_dir, "expand.json 缺失")
    try:
        raw = json.loads(json_path.read_text("utf-8-sig"))
    except (OSError, UnicodeError, json.JSONDecodeError):
        return _invalid_expand_meta(module_dir, "expand.json 不可读或 JSON 无效")
    if not isinstance(raw, dict):
        return _invalid_expand_meta(module_dir, "expand.json 根节点必须是对象")

    # 检查未知字段
    unknown = sorted(set(raw) - _EXPAND_JSON_FIELDS)
    if unknown:
        return _invalid_expand_meta(
            module_dir, "expand.json 包含未知字段：" + ", ".join(unknown)
        )
    display_name = str(raw.get("name") or module_dir.name).strip()
    explain = str(raw.get("explain") or "").strip()

    # 布尔字段
    for field in ("open_input", "open_control"):
        val = raw.get(field)
        if not isinstance(val, bool):
            return _invalid_expand_meta(
                module_dir, f"{field} 必须是布尔值", name=display_name
            )

    # 字符串字段
    str_fields = {
        "input_data": raw.get("input_data", ""),
        "input_health": raw.get("input_health", ""),
        "start_update": raw.get("start_update", ""),
        "start_expand": raw.get("start_expand", ""),
        "start_control": raw.get("start_control", ""),
    }
    invalid_str = [
        f for f, v in str_fields.items()
        if not isinstance(v, str) or not v.strip()
    ]
    if invalid_str:
        return _invalid_expand_meta(
            module_dir,
            "字符串字段不能为空：" + ", ".join(sorted(invalid_str)),
            name=display_name,
        )

    open_input = raw["open_input"]
    open_control = raw["open_control"]
    input_data = str(raw["input_data"]).strip()
    input_health = str(raw["input_health"]).strip()
    start_update = str(raw["start_update"]).strip()
    start_expand = str(raw["start_expand"]).strip()
    start_control = str(raw["start_control"]).strip()

    # input_health 值域
    if input_health not in _EXPAND_HEALTH:
        return _invalid_expand_meta(
            module_dir, "input_health 必须是“正常”或“异常”", name=display_name
        )

    # 所有文件名必须在模块目录内，且为单文件名
    for field_name, file_name in [
        ("input_data", input_data),
        ("start_update", start_update),
        ("start_expand", start_expand),
        ("start_control", start_control),
    ]:
        if Path(file_name).name != file_name:
            return _invalid_expand_meta(
                module_dir, f"{field_name} 必须是文件名而非路径", name=display_name
            )
        resolved = (module_dir / file_name).resolve()
        try:
            resolved.relative_to(module_dir.resolve())
        except ValueError:
            return _invalid_expand_meta(
                module_dir, f"{field_name} 不得跳出模块目录", name=display_name
            )

    return ExpandMeta(
        name=display_name,
        explain=explain,
        open_input=open_input,
        input_data=input_data,
        input_health=input_health,
        start_update=start_update,
        open_control=open_control,
        start_expand=start_expand,
        start_control=start_control,
        module_dir=module_dir,
        valid=True,
    )
```

### 改动 2：`run/prompt_sources.py` — 修改注册模型

当前 `add_expand(scope, module, inject_file)` 接收的是单个文件路径。
改为接收模块目录，让 `select_expand()` 内部读取 `expand.json` 做决策。

**方案一（推荐）**：新增 `add_expand_module()` 方法，接收模块目录。

```python
def add_expand_module(self, scope: str, module_name: str, module_dir: Path) -> None:
    """注册一个拓展模块目录，select_expand 时自动读取 expand.json。"""
    base = {
        "global": self.root / "global_expand",
        "shared": self.root / "shared_expand",
        "user": self.root / "users" / self.user / "expand",
    }.get(scope)
    if base is None:
        raise PromptRegistrationError(f"expand scope 无效：{scope}")

    resolved = module_dir.resolve()
    try:
        resolved.relative_to(base.resolve())
    except ValueError:
        raise PromptRegistrationError(
            f"expand module 不得跳出来源根目录：{module_dir}"
        ) from None

    entry = (scope, module_name, resolved)
    if entry in self._expand_entries:
        raise PromptRegistrationError(
            f"expand 模块重复注册：{scope}:{module_name}"
        )
    self._expand_entries.append(entry)
```

### 改动 4：`run/prompt_sources.py` — 重写 `select_expand()`

核心逻辑变更为：

```python
def select_expand(self, *, max_chars, mode="full", allow=None):
    if mode != "full":
        raise PromptSourceError(...)
    if max_chars == 0:
        return ExpandSelection(...)

    # 1. 遍历所有已注册的模块
    # 2. 对每个模块读 expand.json → _read_expand_meta()
    # 3. 检查 allow 白名单
    # 4. 根据 open_input / open_control 决定注入内容

    pieces = []
    injected_files = []
    offsets = []
    used = 0
    health_status = {}  # 诊断用

    for scope, module_name, module_dir in self._expand_entries:
        meta = _read_expand_meta(module_dir)
        health_status[f"{scope}:{module_name}"] = {
            "name": meta.name,
            "valid": meta.valid,
            "input_health": meta.input_health,
            "open_input": meta.open_input,
            "open_control": meta.open_control,
            "error": meta.error,
        }

        if not self._allowed(module_name, ...):
            continue
        if not meta.valid:
            continue

        module_pieces = []

        # 数据注入
        if meta.open_input and meta.input_health == "正常":
            data_path = module_dir / meta.input_data
            if data_path.is_file():
                content = read_required_text(data_path)
                if content:
                    module_pieces.append(f"## 数据采集\n{content}")

        # 操控注入
        if meta.open_control:
            control_path = module_dir / meta.start_control
            if control_path.is_file():
                control_text = read_required_text(control_path)
                # 提取 ## 注入层 之后到下一个 ## 之前的内容
                injection_text = _extract_injection_layer(control_text)
                if injection_text:
                    module_pieces.append(f"## 操控能力\n{injection_text}")
                # 操作层路径记入 injected_files（供 AI 后续按需读取）
                injected_files.append(relative_path(control_path, self.root))

        if not module_pieces:
            continue

        full_piece = f"[{scope}:{module_name}]\n" + "\n\n".join(module_pieces)
        offsets.append(used + (2 if pieces else 0))
        pieces.append(full_piece)
        used += len(full_piece) + (2 if len(pieces) > 1 else 0)

    # 截断、构建 ExpandSelection
    ...
```

辅助函数 `_extract_injection_layer()`：

```python
_INJECTION_HEADING = re.compile(r"^##\s+注入层\s*$", re.MULTILINE)
_OPERATION_HEADING = re.compile(r"^##\s+操作层\s*$", re.MULTILINE)


def _extract_injection_layer(text: str) -> str:
    """从 expand_control.md 中提取注入层内容。"""
    inj_match = _INJECTION_HEADING.search(text)
    if not inj_match:
        return ""
    start = inj_match.end()
    op_match = _OPERATION_HEADING.search(text, start)
    end = op_match.start() if op_match else len(text)
    return text[start:end].strip()
```

## 四、应达到的效果

### 重构前

```python
# register.py 里硬编码
registry.add_expand("global", "light", "light/inject.md")
# 只注入一个文件，不知道模块有什么能力
```

### 重构后

```
global_expand/light/
├── expand.json              ← 描述模块所有能力
├── input_data.md            ← open_input=true → 自动注入
├── expand_control.md        ← open_control=true → 注入层进 prompt
├── data_update.py           ← AI 按需调用刷新数据
└── start_expand.py          ← AI 按需调用操控硬件
```

AI 看到的 `[expand_data]` 段：

```
[expand_data]
[global:light]
## 数据采集
# 智能灯光状态
> 最后更新: 2026-07-19 15:00:00
客厅灯组: 开启, 80%, 4000K
卧室灯组: 关闭

## 操控能力
智能灯光扩展可用。支持指令：开关灯、调亮度、调色温。
使用方法见操作层。
```

当 AI 决定操控时，主动读 `expand_control.md` 的操作层获取详细指令格式，然后调用 `start_expand.py`。

### 三层差异的实际效果

| 层 | 模块 | 用户 A 看到 | 用户 B 看到 |
|----|------|-------------|-------------|
| global | 系统监控 | ✅ | ✅ |
| shared | 共享日历 | ✅（有权限） | ❌（无权限） |
| user | 用户 A 的智能灯 | ✅ | ❌ |
| user | 用户 B 的打印机 | ❌ | ✅ |

**不同用户的 `[expand_data]` 段天然不同**，因为 `users/<user>/expand/` 是用户隔离的。

### 异常模块处理

```
global_expand/broken/
├── expand.json    ← 缺少 input_health 字段

→ _read_expand_meta() 返回 valid=False
→ select_expand() 跳过此模块
→ 诊断信息显示：
    "global:broken": { "valid": false, "error": "...", "input_health": "异常" }
```

## 五、兼容与迁移

- 现有 `register.py` 中的 `add_expand("scope", "module", "inject.md")` 调用需迁移为 `add_expand_module("scope", "module", module_dir)`
- 旧模块没有 `expand.json` → `_read_expand_meta()` 返回 `valid=False` → 不注入不报错、诊断标记异常
- 用户层旧 `inject.md` 查找退化为自然失效（改为找 `expand.json`），需通知用户更新

## 六、测试要点

| 场景 | 预期 |
|------|------|
| 标准模块，open_input+open_control 都开 | input_data.md + 注入层 均注入 |
| open_input=false，open_control=true | 仅注入操控层，不注入数据 |
| open_input=true，input_health=异常 | 不注入数据，操控层不受影响 |
| open_control=true，expand_control.md 缺失 | 操控注入为空，不报错 |
| 无 expand.json | valid=false，跳过，诊断显示异常 |
| expand.json 缺少必填字段 | valid=false，跳过 |
| expand.json 布尔值为字符串而非 true/false | valid=false |
| 白名单过滤 | 按模块目录名过滤 |
| 三层（global/shared/user）各有模块 | 按 global→shared→user 顺序注入，scope 空间隔离 |
| 用户 A 和用户 B 的 user expand 不同 | 各自只注入自己目录下的模块 |
