# 感知模块标准化重构方案

## 一、问题

当前 `global_sense/` 下的感知模块没有统一的结构规范，`select_perception()` 的实现是暴力扫描每个子目录下所有 `.md` 文件全量注入：

```python
# 当前行为 — run/prompt_sources.py
for module in modules:
    for path in iter_files(module, suffixes={".md"}):
        content = read_required_text(path)
        piece = f"[{path.relative_to(base)}]\n{content}"  # 全部注入
```

带来的问题：
1. 一个模块目录下如果有多个 `.md` 文件，全部被扫进 prompt，不可控
2. 没有元数据描述（模块叫什么、数据是否新鲜、是否健康）
3. 注入文件的选择逻辑不透明，只能通过目录名 + 文件后缀暗箱匹配
4. 模块的更新脚本、辅助脚本与注入文件混在一起，无法区分"哪些是 AI 要读的、哪些是采集用的"

---

## 二、方案

每个感知模块采用**硬编码标准化结构**，一个模块目录内只识别以下约定：

```
global_sense/<module>/
├── sense.json          ← 必选。元数据描述
├── sense.md            ← 必选（由 data_md 指定文件名）。唯一被注入的 markdown
├── data_update.py      ← 可选。数据更新入口
└── 其他任意文件.py      ← 与 AI 无关，系统不扫描
```

### `sense.json` 字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 感知模块的名称 |
| `data_md` | string | 是 | 指定注入的 markdown 文件名（如 `"sense.md"`） |
| `recent_update` | string | 是 | 最近数据更新时间，格式 `YYYY-MM-DD HH:mm:ss` |
| `health` | string | 是 | 健康状态，仅允许 `"正常"` 或 `"异常"` |
| `start_update` | string | 是 | 更新数据需要启动的模块文件名（如 `"data_update.py"`） |

### 硬性规则

1. **`sense.json` 必须存在**，不是可选
2. **`sense.json` 必须包含 `data_md` 字段**，指向模块目录下的一个 markdown 文件
3. **只注入 `data_md` 指向的那个文件**，不递归扫描其他 `.md`
4. 没有 `sense.json` 或缺少 `data_md` → 该模块判定为 **异常模块**（health = 异常），系统应感知到并上报
5. `health` / `recent_update` **不进 prompt 注入**——这些是元数据，走诊断面板或外部监控，不由 AI 读取
6. 模块目录下的其他文件（采集脚本、辅助工具）不与 AI 交互，系统不扫描不注入

## 三、需要改动的源代码

### 文件：`run/prompt_sources.py`

#### 改动 1：新增辅助函数 `_read_sense_json()`

```python
import json

_SENSE_JSON_FIELDS = {"name", "data_md", "recent_update", "health", "start_update"}


@dataclass(frozen=True, slots=True)
class SenseMeta:
    name: str
    data_md: str
    recent_update: str
    health: str                     # "正常" | "异常"
    start_update: str
    data_md_path: Path
    valid: bool                     # False = sense.json 缺失或损坏


def _read_sense_meta(module_dir: Path) -> SenseMeta:
    """读取一个感知模块的 sense.json，返回结构化的元数据。

    无 sense.json / 缺 data_md / JSON 损坏 → valid=False
    """
    json_path = module_dir / "sense.json"
    if not json_path.is_file():
        return SenseMeta(
            name=module_dir.name, data_md="", recent_update="",
            health="异常", start_update="",
            data_md_path=module_dir / "sense.md",
            valid=False,
        )
    try:
        raw = json.loads(json_path.read_text("utf-8"))
        data_md = (raw.get("data_md") or "").strip()
        if not data_md:
            return SenseMeta(
                name=raw.get("name", module_dir.name), data_md="",
                recent_update=raw.get("recent_update", ""),
                health="异常",
                start_update=raw.get("start_update", ""),
                data_md_path=module_dir / "sense.md",
                valid=False,
            )
        md_path = (module_dir / data_md).resolve()
        # 防止路径逃逸
        md_path.relative_to(module_dir.resolve())
        return SenseMeta(
            name=raw.get("name", module_dir.name),
            data_md=data_md,
            recent_update=raw.get("recent_update", ""),
            health=raw.get("health", "异常"),
            start_update=raw.get("start_update", ""),
            data_md_path=md_path,
            valid=True,
        )
    except (json.JSONDecodeError, OSError, ValueError):
        return SenseMeta(
            name=module_dir.name, data_md="", recent_update="",
            health="异常", start_update="",
            data_md_path=module_dir / "sense.md",
            valid=False,
        )
```

#### 改动 2：修改 `perception_inventory()` — 返回元数据

当前：只统计文件数。
改为：遍历模块时调用 `_read_sense_meta()`，返回 `name`、`health`、`recent_update`、`data_md`、`valid`。

```python
def perception_inventory(self, *, allow_modules=None):
    inventory = []
    for base in self._perception_roots:
        if not base.is_dir():
            continue
        modules = sorted([p for p in base.iterdir() if p.is_dir() and not p.name.startswith(".") and p.name != "__pycache__"], key=lambda p: natural_path_key(p.name))
        for module in modules:
            meta = _read_sense_meta(module)
            selected = self._allowed(module.name, allow_modules)
            active = selected and meta.valid
            data_items = [meta.data_md] if meta.valid else []
            inventory.append({
                "name": module.name,
                "display_name": meta.name,
                "data_md": meta.data_md,
                "files": 1 if meta.valid else 0,
                "recent_update": meta.recent_update,
                "health": meta.health,
                "valid": meta.valid,
                "data_items": data_items,
                "selected": selected,
                "active": active,
                "status": (
                    "active" if active else
                    "invalid" if not meta.valid else
                    "filtered"
                ),
            })
    return tuple(inventory)
```

                continue

            if not meta.valid:
                # 异常模块不进注入，但计入 discovered
                continue
            selected_modules.append(module.name)

            paths.append(path)

## 四、应达到的效果

### 重构前

```
global_sense/weather/
├── weather.md
├── forecast.md              ← 也被注入（不想要的）
├── cache.py                 ← 也被扫描
└── __pycache__/

→ 注入内容：
[global_sense/weather/weather.md]
晴天，27°C
[global_sense/weather/forecast.md]  ← 多余
明天有雨
```

### 重构后

```
global_sense/weather/
├── sense.json               ← 描述：name="天气感知", data_md="sense.md"
├── sense.md                 ← 唯一被注入的文件
├── data_update.py           ← 更新入口
└── cache.py                 ← 无关文件，不扫描

→ 注入内容：
[weather]
当前天气：晴天，27°C
明日预报：有雨
```

### 异常检测效果

```
global_sense/broken_module/
├── helper.py                ← 没有 sense.json
├── data.txt
└── old.md

→ perception_inventory() 返回：
{
    "name": "broken_module",
    "valid": False,
    "health": "异常",
    "status": "invalid",
    ...
}

→ select_perception() 跳过此模块，不注入
```

### AI 感知到的变化

AI 收到的 prompt 段 `[perception]` 中：
- 只有每个模块 **明确指定的 `sense.md`** 内容
- 不再有多余文件乱入
- 内容干净、可控、可预期

### 维护者视角

新人新增感知模块只需：
1. 在 `global_sense/` 下建一个目录
2. 创建 `sense.json` 填写元数据
3. 创建 `sense.md` 写入数据
4. 写 `data_update.py` 负责定时刷新数据
5. 无需注册、无需改代码、无需关心注入逻辑

## 五、兼容与降级

- 没有 `sense.json` 的旧模块 → `valid=False`，**不注入、不报错崩溃，但标记为异常**
- 想兼容旧行为？在 `sense.json` 中填写 `data_md` 指向旧文件即可
- 注册层（`global_sense/register.py`）**不需要任何改动**，仍然是 `registry.add_perception(...)`

## 六、测试要点

| 场景 | 预期 |
|------|------|
| 标准模块（sense.json + sense.md） | 正常注入 sense.md 内容 |
| 无 sense.json | valid=False，不注入，诊断显示异常 |
| sense.json 缺 data_md 字段 | valid=False，不注入 |
| data_md 指向不存在的文件 | 跳过该文件，其他模块正常 |
| data_md 含路径跳跃（../） | 路径逃逸检测，valid=False |
| 白名单过滤 | 按模块目录名过滤，异常模块不计入选中的统计 |
| 多个感知根目录（多注册） | 各自遍历子模块，各自独立判断 |
