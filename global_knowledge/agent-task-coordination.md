# 主任务与后台子智能体协作

## 身份与执行边界

本次用户请求是一个逻辑主任务，不是整个会话，也不等同一次 Provider 请求。
`iter_request_events` 为请求分配 `main-task-*`，自动重试沿用这个根身份；Web 编排器为一次
逻辑请求绑定同一个根身份，长任务自动续跑保留它。每次执行尝试另分配 `attempt_id`。
调用身份包括用户、来源、会话、根任务、Run、工具调用及子任务；归属从框架工具 context
传递，不加入模型可填写的参数。旧尝试的迟到提交会被拒绝。

主模型通过 `subagent_dispatch(action=call)` 派出的业务任务，不论 `wait=true/false`，
都登记为必要依赖。`wait=false` 只让主模型继续做其他工作，不解除主任务责任。
调度器在入队前事务登记依赖，入队失败会登记失败结果。系统记忆维护、独立 Cron、
Shell 服务不会因此自动归属业务主任务。外部代理继续只支持同步等待合同；
同步等待期限到达、实际执行尚未退出时，同样保留必要依赖。

## 并行调度与共享 API 请求池

普通本地子任务由 `AgentScheduler` 有界并行执行，不再被一个工作线程强制串行。
每用户可运行任务数采用当前 Provider 总闸的 `max_requests`，来源仍是
`provider_runtime.max_concurrent_requests`（默认 10），不增加独立的子代理并发配置。
任务超过调度额度时留在原有有界队列（`agent_runtime.queue_maxsize` 默认 50）。
排队中的串行维护任务不会挡住其后可以运行的普通任务。

主模型、所有用户的子代理和已有维护请求继续共用 `provider_request_slot` 的进程级
API 请求池，也就是网页状态面板的 Provider 请求计数。例如池上限为 10 时，
主模型占 1 个请求槽，子代理及其他来源最多共同占剩余 9 个；不是主模型 10 个再加子代理 10 个。
子任务在执行工具、等待或收尾时不占 API 槽；不能在子任务外层再占一次 API 槽。
调度中的任务数不是正在请求模型的数量，不应把两者在状态面板混加。
保存的新上限用于后续调度；API 池已有请求/等待者时仍遵循既有空闲重配合同，
不替换活动信号量、不打断在途请求。

`background_serial` 维护代理保留原有用户级串行写入约束（含结果持久化），不会因普通任务并行
而并发改写同一份记忆。超时/取消但执行器未退出的任务继续计入调度额度；
取消请求本身不释放该额度，真实退出或可信完成回调后才释放。
并行不放宽用户、来源、会话、权限和禁止子代理递归委派的边界。

普通公开本地非串行 LLM 业务子代理（如 `general_worker`）的 call/resume 省略 `wait`
默认后台提交，主模型可以继续工作，结果由框架自动交付；也可显式使用 `wait=false`。
工具 Schema 不再全局注入 `wait=true`；list 的 `default_wait` 披露有效缺省策略。
`wait=true` 仍是显式同步等待合同，单个主工具循环会先等待这个调用，再执行后面的工具；
不会为了并行静默改变参数、抢跑依赖工具或越过 `task_plan` 的批准边界。
互相依赖的任务显式同步或先收集依赖；特殊同步规划、串行维护、外部及自定义非 LLM
执行器保持默认同步，禁止后台的规划/外部入口显式 `wait=false` 仍拒绝。
这不是整个工具批次并行化：普通 file/shell 等副作用工具仍按原顺序执行。

工具调用卡片在尚未取得 task_id 且任务 ledger 无匹配登记时显示“等待提交”，不是“正在分派”
或“排队中”。登记后才按权威 queued/running/终态展示；查询失败分别显示提交/执行状态不可用，
不伪造正在运行。发现查询按用户和会话共享，已匹配任务后停止该卡片的列表发现轮询；
实际执行未退出的停止任务仍继续刷新详情。

### 对话空间公平与多窗口余量

空间身份为安装根、用户、来源和 `session_id`，不包含浏览器 client_id、窗口数、主任务 ID
或子代理名称。同一空间开多个窗口、发起多个主任务，仍合并计数；不同来源或用户不混为同一空间。

调度器仍是用户级队列，执行上限仍跟随现有 API 池，不新增另一套并发上限。派发时优先选择
当前存活子任务占用较少的空间；占用相同按空间轮转，同空间内按可运行任务的入队顺序。
只有一个空间有工作时可以借满空闲执行额度。另一个空间加入后优先获得新释放的额度，
不会强杀原空间正在执行的任务，也不会让阻塞的串行维护任务挡住普通业务任务。
超时停止中、取消但执行尚未退出的任务照旧计入实际占用。

有界等待区另有入队保护，不与执行额度混算：

- 总容量仍为 `agent_runtime.queue_maxsize = Q`，单个有明确身份的空间最多等待
  `ceil(Q/2)` 项；默认 `Q=50` 时单空间最多 25 项，不包含已经运行的任务。
- 对已有待执行任务的空间，在总等待数达到 `Q-min(5,floor(Q/5))` 后拒绝继续积压，
  剩余位置供当前没有待执行项的其他空间首次入队。默认保留 5 个这样的新空间保护位置；
  两个老空间不能各排满 25 项把第三个空间挡在队列外。
- 所有保护仍受总容量约束；达到总上限明确拒绝，不丢弃/替换已接受任务，不伪报 queued。
  同步 call、后台 call、可信 callable 与 resume 都走同一队列；resume 入队失败保留原超时结果。
- 显式配置 `Q=0` 保留既有无界语义，无硬等待区保护；`Q<5` 时无法额外留出上述新空间位置。
  旧式未绑定空间的可信维护调用仍受总容量与既有串行规则约束，不伪造会话身份。

实际 Provider 请求池也采用“当前空间占用较少者优先、相同占用轮转”，同空间请求 FIFO；
有其他等待空间时，新来的同空间请求不能绕过它们抢到刚释放的位置。主模型、子代理、
能力查询/媒体请求和线程工具通过可信执行边界继承空间身份；未知身份维护请求进入兜底组。
身份只存在进程内，不写入模型可填参数或对外请求正文。主对话生成器每次推进及关闭分别
绑定/恢复身份，避免同线程交替读取两个会话时串号；子代理、工具在线程执行入口重新绑定。

这是**进程内、非抢占、有限容量**的公平性，不是为无限数量空间永久预留独享槽位，
也不提供“到点必启动”的承诺。全部在途请求都未结束时，新空间仍须等待真实释放；
不同服务进程或隔离子进程不共用内存池。网页聊天入口的每用户 3 个运行/5 个等待
是独立入口闸门，没有因此变成每窗口各一份。任务展示/结果交付仍使用原持久提交序号，
不会为公平派发改写历史编号或按实际完成时间重排卡片。

## 稳定提交顺序与结果顺序

每个主任务下的子任务在登记事务中分配单调 `submission_order`（1、2、3……），并持久化。
编号分配与父任务封口使用同一写事务，重试沿用根任务并继续编号；不依赖时间戳精度或随机 ID。
网页任务树按持久登记顺序从前到后展示，卡片和详情带 `#编号`；进度更新、反序完成或同一时刻
返回不会把任务在列表中重新洗牌。主任务列表按登记时间倒序，而不是按子任务进度跳动。
旧记录利用 SQLite 持久插入顺序稳定回退，不破坏旧数据库或编造旧任务时间。

后台结果通知每批最多四项，选取当前已完成且未确认的结果，再按相同提交顺序回填，
每项附 `submission_order` 和 `task_id`，同一时间完成也能确定先后。
**稳定顺序不等于等待最早任务**：若 #2 已完成、#1 仍运行，#2 可以先交付，不因排序造成队头阻塞；
稍后交付 #1 时仍带原编号。跨批次按可用性推进，同批次按提交序号排序。
完成屏障、Provider 完整响应后的确认、重试去重和失败/取消结果交付规则保持不变。

## 完成屏障与结果续接

`run/agents/task_ledger.py` 提供状态账本与单写执行器协调器：

- 主任务显示 `running / waiting_children / merging / cancelling` 等阶段；
  `completed / failed / cancelled / interrupted` 是主任务终态。
- 子任务真实执行状态来自调度器，而不是模型自述或执行器发出的“completed”进度事件。
  `timed_out_running`、取消但 `process_terminated=false` 仍视作存活。
- 主模型没有返回工具调用时，框架先检查必要依赖和未处理结果。依赖仍运行就保留当前主执行器，
  释放 Provider 槽并按条件变量等待；不会通过模型反复调用 status 空耗 Token。
- 子任务退出后先保存结果，再通知等待执行器；主模型正在工作时在下一请求安全点消费。
  多个结果由同一个主执行器合并，每批最多四个有界结果。
- 后台工具的 queued 回执已有配对 tool result；后续结果使用明确标注“框架通知／外部数据”的
  消息，不伪造第二份同 ID tool result。通知不是新的用户指令。
- 通知送入请求后，仅在完整 Provider 响应被接受时确认处理。网络失败不能提前确认；
  新尝试重新交付未处理结果，不重放已完成的执行副作用。
- 同步工具结果也在后续完整 Provider 响应被接受后确认；等待期间不重复发送通知，
  失败后新尝试仍可重新交付结果，不重新执行子任务。
- 最终完成与新子任务注册在同一个 SQLite 写事务边界裁决，必要任务全部真实退出、
  结果全部处理后才允许封口。
- 等待时用户引导仍走已有 GuidanceMailbox；新引导可唤醒同一个执行器，不创建第二个主写循环。
  普通跟进消息仍由已有会话队列安排。

正常流程为“分派 → 主模型继续工作 → 等待子任务／汇总结果 → 最终交付”。
失败、超时和取消结果也必须交付主模型；主模型可在原有工具和预算限制内重试、接手，
或明确说明部分失败。主模型的 Provider、上下文、工具调用等保护不放宽；无法正常续接的
终止路径会取消所属剩余子任务并等待真实退出，而不是把它们遗留为无人负责的后台执行。
因此达到硬限制不承诺自动完成所有子任务。

## 停止、持久化与进程恢复

用户停止优先：设置主取消事件后，只取消本根任务的存活子任务。保持 `cancelling`，
直到执行器真实退出；不误停其他会话、系统维护或独立 Shell 服务。迟到结果不能
重新启动已取消主模型。非协作线程不能被宣称已强杀，取消收尾可能需要等待。

状态写入每用户 `users/<user>/runtime/agent_tasks.sqlite3`（WAL、5 秒 busy timeout）。
根任务、子任务、处理确认及最近 160 条公开事件保存在同一领域表，列表使用来源／会话／父任务
索引及有界分页，不遍历用户历史正文。调度器状态转换和对应持久快照串行，避免慢 queued 写入
覆盖 completed、把已结束任务“复活”。
同进程对同一账本的路径安全检查、SQLite 连接及关闭使用数据库级短锁，避免 Windows 下并发
连接关闭时 WAL/SHM 侧文件消失与路径检查竞态；不同用户不共用此锁。硬链接、符号链接及
reparse point 的拒绝规则不放宽，跨进程写事务仍由 SQLite 协调。
常规列表及等待轮询不重写未变化记录；仅进程恢复导致状态变化时复核并持久化。

浏览器刷新后可重新打开总览及详情，不依赖旧 SSE 浮卡。读取旧进程记录时用 PID 与进程创建
时间核验原执行进程；原进程已退出则标记 `interrupted`，不重放有副作用操作。不承诺线程、
外部连接或任意执行器跨进程重启自动恢复。

## 超时停止与原任务续跑

### 分段工具预算（1.5.2 同版本完善，2026-10-27）

`call/resume` 支持 `max_tool_calls`：正整数指定本段额度，0 显式不限工具次数；
省略时初次采用全局与代理默认的较小值，续跑沿用上一段有效额度。
只有公开 builtin:llm 非串行业务代理可以覆盖；授权交集、重复调用/连续失败保护、
用户取消和共享 API 请求池不改变。`timeout` 仍为正数秒，续跑省略沿用上一段时长，
从实际执行开始计时；不限工具次数不代表无限运行。

工具额度停止使用 `tool_limit` / `stop_reason=tool_budget_exhausted`，不伪装为超时或
普通执行错误。已执行调用配对保存，未执行调用明确 not_executed。一次有界收尾只
允许提交结论，不再执行业务工具；收尾失败仍保留最新安全点与已确认用量。
只有实际已退出、有有效安全点的预算停止可续跑，任意 failed/cancelled 不获得恢复权。
旧版 failed 且异常类型明确为 AgentToolLimitError 的记录可显式申请恢复；
仅匹配定义/轮次/身份的有效快照才接受，不按错误文案猜测，不恢复其他失败。
缺少旧预算字段时从已配对且非 not_executed 的工具结果计算历史累计次数。
正常完成恰好用完额度不强制改成停止；模型再要求超额工具时才进入额度停止。

本段 tool_calls_used 与累计 total_tool_calls 分开：80 次停止后新段再给 80，
不是清空累计，也不是立即再次超额。框架内部 Provider 重试保留本段计数；
普通工具调用尝试逐个计数，结构化提交不消耗业务工具额度。
失败/取消也尽量交付已得结论和已确认用量；provider_request_count 为已返回的模型
响应次数，provider_attempt_count 另记实际发起的尝试，无法取得的 token 不猜测。

`list` 披露默认工具额度、默认时长、续跑/预算覆盖能力、当前有效插件和知识权限。
子代理在开始和约 80% 时收到预算提醒；主代理在安全点收到每段一次的短预警，
仅完整模型响应接受后确认，失败可重交，不注入工具轨迹。status 提供有界预算、
用量和最后阶段/工具名。`guide` 可引导同根的排队/运行中业务子代理，于下一请求安全点
交付，不扩权、不实时强中断或创建第二个执行器。

同根多个任务同类预算停止时，结果通知附有界聚合建议。`split` 由主代理显式给出
1..8 个完整剩余任务输入，为实际已退出的预算停止/失败任务建立 origin_task_id 关联；
不自动生成任务、不让子代理继续委派、不从头重复原任务。批次可能部分入队，回执
明确已接受 ID 与数量，不回滚已经启动的任务，只补交未接受输入。

子代理停止回执列出至多 8 个关联后台 Shell 摘要与总数，不返回完整日志。
主代理接管已退出 owner 的结果收集，可显式 status/cancel；不会无条件强杀测试，
也不把仍在运行的作业写假终态。原任务跨主任务续跑后，required Shell 即使保留旧 root
记录，仍按可信 owner 的新归属纳入完成屏障；续跑必须先核对旧 job_id，不重复启动。

### 结论交付与执行状态

主智能体默认只收到 task_id、真实执行状态、run_count、resumable、代理业务结论、
必要证据/产物/未完成事项及有界数值用量。同步 call、后台通知、status 和 resume
均不返回工具卡片、tool_calls、事件、原始 metadata 或私有对话。
后台通知继续每批最多四项，保留原提交序号；旧格式结果也经过结论投影。
公开工具事件仍保存在现有任务账本并由认证网页详情展示，不进入默认主模型上下文。

运行预算到期，可恢复的本地 LLM 业务代理在既有宽限内尝试一次简短收尾；
不再调业务工具，仅保留结构化提交入口（若启用）。收尾按原代理 Schema 输出，不把
general_worker 字段强加给上下文/记忆等专项代理。收尾限制输出、不整任务自动重试，
请求仍占现有共享 API 池；在途模型/工具只能协作停止，收尾不保证能及时执行。
没有结论时返回“尚未形成可交付结论”，不把工具轨迹当作分析结论。

执行状态与成果完整性分开：timed_out 显示“超时停止”，可附已有结论；
timed_out_running 显示“超时停止中”，不能称为已退出，也不能继续下一轮。
收尾得出的残缺成果不进入正常结果提交器，不冒充 completed_after_timeout。
可恢复的业务任务一旦进入超时停止流程，迟到结论只补充该轮成果，不把“超时停止”
改写成完整成功；尚未进入超时流程的正常完成不受影响。
不支持续跑的维护/自定义执行器保留原有宽限完成/迟到完成对账合同。
用户取消优先，不为了收尾新增请求，不自动续跑。

对于超时/取消后仍在运行的线程工具，子执行器等待工具真实退出、记录实际结果并配对，
再结束本轮；等待不占 Provider 槽。直到这一步完成，执行槽、会话责任和完成屏障不释放。
不能安全杀掉的 Python 线程没有“到点必停”的保证。

### 私有快照与安全点

`run/agents/continuation.py` 维护版本化 JSON 快照，保存在
`users/<user>/runtime/agent_checkpoints/<task_id>.json`。每份最多 32 MiB，
原子写入并拒绝链接/越界，不使用 pickle；快照不进入 API、事件、日志或模型工具返回。
不复制系统提示词与凭据，必要协议上下文私有保存，凭据字段/文本脱敏，
恢复时根据当前配置重建提示词、工具注册与授权。公开推理不作为恢复材料保存。
快照失败/超限明确禁止恢复，不能使用忽略新副作用的旧快照。

安全点位于请求前、响应接受后和每次工具结束后。一批工具只完成一部分时，
保留已配对结果，给尚未执行的调用补明确的 not_executed 错误结果，而不是补跑；
恢复请求没有悬空调用。未知副作用要先对账，不能因续跑默认重执行。
上轮收尾控制消息从恢复上下文移除，添加显式续跑指导。
快照只保证这些安全点的恢复，不是任意操作系统进程或外部连接的镜像。

### 显式恢复合同

主智能体使用 `subagent_dispatch(action="resume", task_id=..., guidance=..., timeout=..., wait=...)`。
task_id、代理名、原输入、创建时间不变，原主任务内的提交序号保留，run_count 增加；
新一轮从实际开始执行时重新计时，排队不消耗运行预算；子任务工具额度可显式覆盖，
不改变主模型/Provider 保护或扩大授权。
累计数值用量/耗时、工具次数与有界 round_history 保留，最多 32 轮，不自动无限续跑。

恢复只接受当前 user/source/session 的 timed_out/tool_limit、实际已退出、有有效快照的公开
builtin:llm 非串行业务代理；自定义 executor、外部代理及维护代理明确不支持。
损坏、超限、定义指纹变化、旧轮次快照或权限不足时 fail closed。
仅真实超时停止的安全点可在重启后显式恢复；运行中进程中断仍按 interrupted 处理，
不以旧安全点推定未落盘副作用不存在。

在同一写事务内检查主任务/attempt 归属、认领新轮次、复位结果确认并登记必要依赖；
并发 resume 只有一个成功，入队/事务失败保留原超时结果。事件/快照按轮次防止旧执行覆盖。
原主任务仍活跃时不能由另一主任务抢走；原主任务已结束，同会话后续请求可以显式接管，
历史轮次保留原根任务身份；接入新主任务时分配该父任务内的新提交序号，避免编号冲突。
取消、完成、仍存活或不可恢复任务不被悄悄改成重新派发。
父任务封口与恢复注册使用同一账本写事务裁决，恢复后重新等待该必要子任务。

网页只展示超时状态、执行轮次、已有结论与“主智能体可继续”的提示，
沿用原 Markdown 结果容器和工具详情，不增加绕过主智能体归属的网页恢复按钮。
历史轮次详情不随任务列表整包传输。

## 公开信息与 UI

聊天保留简洁分派卡：代理名、任务摘要、真实状态和“查看执行”；queued 工具成功不显示为
子任务完成。旧工具卡右侧进度浮卡不再渲染。

右侧工作面板“智能体任务”展示当前会话近期主任务树及主任务阶段；
点击子任务打开独立详情标签，包含公开执行阶段、工具名、真实耗时／成功失败摘要、
最终结果及可靠的数值用量。标准化文件产物只有通过当前用户文件区域校验且存在时提供预览，
沿用已有文件标签去重，不开放任意路径。
顶栏“相关文件”浮层也列出当前 Web 会话的后台子任务摘要，点击复用同一详情标签；
仅浮层打开时刷新并按需加载后续分页，不跨用户/会话查找任务，关闭入口不影响执行。
其内部滚动、文件和 Shell 分区合同见 `frontend-conventions.md` 的“当前对话文件历史”。

时间线采用“左侧时间、右侧行为卡片”的紧凑排列。工具开始和返回事件用可信
`tool_call_id` 合并为一张卡片，绝不按同名工具猜测合并；展开查看脱敏后的调用参数与返回结果，
包括命令、文件路径、普通查询参数和公开输出。开始阶段可先查看参数，结束后原卡片原位更新，
轮询不重置展开状态。没有详情的旧事件明确提示未保存，不从工具名编造参数或补跑命令。
代码/JSON 按纯文本显示，超长内容内部滚动；窄屏仍保持时间在左、行为在右。
工具卡与主聊天保持一致的单行参数摘要、耗时、展开箭头和状态图标；摘要有界，
完整详情仍可展开。`model_request` 只从可见时间线隐藏，不删除后台事件或影响执行。

最终回复复用安全 `DocumentMarkdown`，支持正文、标题、列表、表格与代码；
结构化回复按摘要、执行结果、验证、遗留事项及其他返回字段分段。
字符串数组中的 Markdown 表格行会连续拼接渲染，原始结构化结果保留为折叠入口，
不默认输出整块 JSON，也不自动执行回复中的 HTML 或交互动作。
渲染正文使用独立圆角边框容器，原始结构化数据折叠入口和用量面板置于容器外。
底部用量使用当前界面九种语言及对应数字格式，命中率显示为百分比；
input/prompt、output/completion、cached_input/cached_prompt 别名各只显示一次，
保留输入、输出、总量、缓存命中/未命中、命中率、推理用量、模型请求次数。

任务总览与详情只在可见时轮询（1.5 秒），不自动打开／抢占文件或终端。
同任务标签去重，关闭／收起仅关闭视图，不取消执行。刷新后需重新打开总览查看持久状态，
不把运行输出或任务正文存进 localStorage。

只读接口：

- `GET /api/users/{user}/workspace/agents?source=web&session_id=...&page=1&page_size=20`
- `GET /api/users/{user}/workspace/agents/{task_id}?source=web&session_id=...`

详情必须提供完整来源与会话；用户校验沿用 Web 认证合同，错误作用域返回不存在。
响应 private/no-store。列表只投影摘要，详情返回有界公开内容。
不提供原始推理、系统提示词、未脱敏工具参数、Provider metadata 或凭据。
公开结果会做敏感字段过滤、凭据形状脱敏及长度／深度／节点限额；信息不足时只展示已有
阶段，不伪造百分比、Shell 输出或不存在的执行细节。
工具详情走独立 `public_tool_data` 投影，在发送事件及写入任务账本之前脱敏；
敏感键、嵌套 JSON 字符串和已知凭据形状均过滤，保留普通 prompt、max_tokens 等非敏感参数。
每个参数/结果最多约 16000 文本字符、512 节点、8 层深度，集合最多 80 项，
截断明确标记；不读取或转发完整 Provider 请求、主历史、原始执行元数据。
列表不携带参数与结果详情，只有带完整用户/会话身份的认证详情接口提供。
