# Kemo Bridge 2.1.0

单进程 FastAPI 拓展，在同一个监听端口服务手机工作台（`/v1`）和外部智能体（`/peer/v1`）。接口、示例与错误码见 [接入契约](expand_control.md)。

## 首次启动

1. 在宿主 Web 启用全局拓展 `kemo_bridge`。进「通用配置」点初始化、启动；这里显示实际进程健康与运行状态。初始化不启动服务。「停止桥接」也清除自动恢复意愿；命令行 `stop` 只停止本次进程。
2. 打开内嵌「桥接控制台」，由宿主实例管理员审查并授予工作台权限。不再设置或输入单独的控制台访问密钥，桥接停止时也可管理本地绑定和凭据。
3. 「总览」显示实时状态、已启用的手机绑定用户、外部实例数、近 24 小时通信记录数和本机 UUID。「本机绑定」分别管理手机通道和对外开放的单一用户；在「对外凭据」以对方 UUID 注册外部实例，再复制本机为它签发的连接密钥。「日志」只显示近期消息回传、输出及文件传输，不显示正文或密钥。

本机 UUID 在首次初始化、打开控制台或启动桥接时生成并持久保存，不随进程重启变化。更换后需要外部实例更新对本机旧 UUID 的引用；本机签发给它们的密钥不变。手机密钥只在签发和轮换时显示；外部实例密钥可在授权工作台再次复制。列表只返回密钥尾号。轮换和吊销使旧密钥失效。通道和绑定用户不能在注册后修改，已吊销的对端 UUID 不能复用。

默认监听 `0.0.0.0:8742`；如需改监听地址或端口，在停止后编辑模块的本地 `config.json`。桥接端口不提供管理网页或管理 API；对端接口在内网也必须校验身份，内部接口仍使用独立共享密钥。

## 公开入口

由管理员决定网络接入手段。公网用 HTTPS；在「本机绑定」把对端访问地址（`bridge.public_url`）设为对端可达的 HTTPS 基址，只向外转发 `/v1/*` 和 `/peer/v1/*`，保留身份头、Range 和 WS 升级，避免缓冲 SSE。不要转发 `/internal/*`；若代理需要内部健康探测，应只在私有链路发送 `X-Kemo-Internal`，切勿记录该头。

peer 拥有绑定用户在对应通道授予的权限。对话仍经该用户正常框架配置运行；能力门约束的是直接桥接 API，不是对本地模型工具的操作系统沙箱。只给可信对端签发密钥，若需单独隔离数据请注册到专用本地用户。

本机主动拨号时，使用「对外凭据 → 导入出站凭据」，存入**对端签给本机**的身份和密钥，不是本机签给对端的那组。启用前先更新接收端的只读续查接口。命令、超时和续查方式见 [本机出站命令](expand_control.md#本机出站命令)。

## 数据与更新

- 私有文件：`config.json`、`users.json`、`_workspace_credentials.yaml`、旧版的 `_admin_key.sha256`、`_bridge_peers.sqlite3*`（含本机 UUID、可复制的外部实例密钥、grant 和审计）、`_bridge_runs.sqlite3*` 及进程/连接状态。旧工作台保存的对方签发凭据仍单独读取，旧控制台密钥不再参与认证。此类文件应靠本机文件权限保护，不应上传或分享。状态与列表接口不回显密钥。
- 安装根的 `runtime/kemo_bridge_outbound.sqlite3` 保存出站编号、会话归属、远端实例身份、prompt 摘要和提交回执，不保存密钥或正文。收到对端明确终态后，回执保留 **30 天**，之后在新提交时分批清理；未发送的预留和未经确认终态的记录不按时间清理，会话归属也仍保留。只有确定没发出才能同号重提；不能以删除账本或换新编号的方式补发状态未知的请求。
- 接收端 `peer_audit` 保留 **30 天**，daemon 分批回收旧记录并保留未终态 run 关联的审计。每个 peer 的 `auth_ok` 每分钟最多记一次；`message_sent` 只在该 run 首次交付正文时记录。
- 产物由底层用户目录保管，grant 长期有效直至吊销，文件缺失返回 410；上传有 80 MiB 上限，与 Web 相同。产物下载按 Web 对应文件类型上限。可选 `bridge.upload_extensions` 列出接受的扩展名，`null` 表示不限。桥接不延长模型媒体引用 TTL，也不自动清理用户文件。
- 桥接审计与授权均落在本模块 SQLite。停止桥接后备份私有文件；不要把运行文件纳入源码、归档或发布产物。
- `python ui/build.py` 可独立重建宿主工作台静态入口；仓库级 `npm --prefix web/frontend run build:module-uis` 生成同样的资源。框架 core 更新会同步内嵌工作台，保留已有的 SQLite、密钥、运行状态和激活意愿。
- 从 1.1.5 切换时先停止旧桥接，将旧拓展目录移出全局拓展扫描根后再初始化新模块。不要把旧工作台的授权、设备 Token 或启用状态复制给新模块。

桥接与框架的产物、上传和统计使用同一安装根下的 `users/`；若上游 Web 运行在另一台主机而目录未共享，这三类数据不会自动同步。
