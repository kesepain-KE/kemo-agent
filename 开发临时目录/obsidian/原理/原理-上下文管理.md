# 原理：智能体上下文管理

对应源码：

- `E:\code\kemo-agent\run\context.py`
- `E:\code\kemo-agent\run\context_summary.py`
- `E:\code\kemo-agent\run\history.py` — `_trim_to_max_rounds()`
- `E:\code\kemo-agent\run\engine.py` — `_copy_committed_round_to_archive()`、`commit_window()`

## 结论

上下文管理仍然遵循：

- **整轮不可拆分**
- **只选择完整回合**
- **旧回合可被摘要接力**
- **不修改源历史归档窗口**

新增**双层历史架构**：
- **归档层**（`history/<window>/`）：完整、无界、不可裁剪
- **temp 工作区**（`history/temp/<window>/`）：受 `agents.max_rounds` 限制的 Provider 上下文

## 双层历史核心

### 轮号体系

- 归档使用**绝对轮号**（从 1 开始递增）
- temp 使用**局部轮号**（裁剪后从 1 开始连续）
- `data.context.round_offset` 记录两者差值

### _trim_to_max_rounds

temp 工作区每次提交前裁剪：
1. 按 user 消息分组，只保留最后 `max_rounds` 组
2. think/tool/items 的 round 号重映射为局部连续编号
3. `data.context.round_offset += removed`
4. `data.context.workspace_rounds = 裁后轮数`

### _copy_committed_round_to_archive

新轮次提交时：
- temp 中的局部轮号 → 归档中的绝对轮号
- 归档 `data.json` 不保存 `context` 诊断（只 temp 保存）
- 归档 `data.json` 只保留 `_ARCHIVE_DATA_FIELDS` 中的字段

### 恢复策略

temp 工作区丢失或损坏时：
1. 从归档 deep copy
2. 移除旧 context 诊断
3. 只恢复最近 `max_rounds` 轮
4. 重新计算 round_offset

## v0.2.0 变更（2026-08-04）

### 压缩轮次计算

压缩时把当前待发送轮次计入 `rounds_after_compression`：正常提交后，Provider 临时工作区总计保留最近 N 轮，而不是额外再保留当前轮次。

### 增量摘要

后续压缩沿绝对轮号继承旧摘要，只把新移出的轮次交给 `context_manage` 增量整理。缓存 schema 升级时自动重建。

### 异步记忆提取

正常聊天的自动压缩不在请求主线程同步提取记忆，而是在完整提交后把摘要已覆盖轮次登记到持久化后台队列。手动压缩仍可显式选择同步或队列策略。

### 关键配置（v0.2.0）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `agents.max_rounds` | 80 | temp 工作区轮次上限 |
| `agents.rounds_after_compression` | 20 | 压缩后保留轮次 |
| `agents.token_limit` | 1000000 | Token 上限 |
| `agents.token_compression_ratio` | 0.3 | 输入预算比例 |
